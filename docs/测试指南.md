# 测试与质量检查

本文汇总在仓库根目录（或注明子目录）执行的**自动化测试与常用检查命令**，覆盖 Rust 后端、依赖审计与协议门禁。业务 UI / Playwright 见 Client 仓。更细的模块与协议说明见 [`开发文档.md`](开发文档.md)。**人工三端/壳真实回合冒烟清单**（发版或大改后勾选，默认不进 CI）见 [`design/client_turn_smoke_runbook.md`](design/client_turn_smoke_runbook.md)。**`crabmate bench` 测评子系统的功能规划与专用测试策略**见 [`基准测试规划.md`](基准测试规划.md)（与本文通用测试清单分离）。**任务集如何设计与运维**（覆盖、可复现、成本、CI 分层）见 [`评测任务集设计.md`](评测任务集设计.md)。HumanEval 外挂判分脚本的**本地冒烟**（不调用 LLM）：`python3 scripts/humaneval_score_benchmark_results.py --tasks fixtures/benchmark/humaneval_tiny_tasks.jsonl --results fixtures/benchmark/humaneval_tiny_results.jsonl --output /tmp/tiny_scores.jsonl`（会执行 fixture 中的补全代码，见 `基准测试规划.md` §5.3）。

## 前置条件

- **Rust**：1.85+（edition 2024），见 [`README.md`](../README.md)。
- **端到端（E2E）**：**Playwright** 与 **Victauri** 均在 Client 仓（`../crabmate-client`）；本仓保留 `crabmate e2e` / HTTP 真 LLM。
- **Web 静态资源**：E2E 与托管 UI 的 `serve` 需要 **`index.html`**；在 Client 仓 **`make frontend`**，再设 **`CM_WEB_STATIC_DIR=…/frontend/dist`**（或同级探测）。纯 API：`serve --no-web`。

## GitHub Actions（主 CI）

对 **`main`** 的 push / pull_request 会运行 [`.github/workflows/ci.yml`](../.github/workflows/ci.yml)：

- **`workspace`**（check · clippy · test）：**`cargo check`**、**`cargo clippy`**（**`-D warnings`**）、**`cargo test --workspace --all-features`**（本仓**无** Tauri/GTK desktop job；壳 CI 见 Client 仓）
- **`client-contract`**：契约 / SSE 金样 / OpenAPI 门禁（**`scripts/check-client-contract.sh`**）
- **`build-release`**（package）：**`make package`**（server-only **`tar.gz` + `.deb`**，不附带 frontend；需 **`cargo-deb`**）

圈复杂度、依赖审计、覆盖率等见其它 workflow（**`code-complexity.yml`**、**`dependency-security.yml`**、**`code-coverage.yml`**）。

### GitHub Release（仅 tag）

[`.github/workflows/release.yml`](../.github/workflows/release.yml) **不会**在 PR / `main` push 时运行。推送 tag **`vX.Y.Z`**（或 **`workflow_dispatch`** 指定已有 tag）时：执行 **`make package`**、创建或更新 GitHub Release 并上传产物。正文取自 **`CHANGELOG.md`** 中该 tag **核心版本 `X.Y.Z`** 的章节（因此 **`v0.1.0-rc.1`** 仍用 **`[0.1.0]`**，**`Cargo.toml`** 可保持 **`0.1.0`**）。对同一 tag 重跑会更新该 Release。

## 提交前检查（pre-commit）

与 [`.pre-commit-config.yaml`](../.pre-commit-config.yaml) 对齐，建议在提交前执行：

```bash
pre-commit run --all-files
```

其中包含（节选）：

- **`cargo fmt --all`**
- **`cargo clippy --all-targets --all-features -- -D warnings`**
- **`lizard-rust`**：Rust 圈复杂度（需 **`pip install lizard`**；**`scripts/lizard-rust.sh`** / **`scripts/lizard_rust_metrics.py`**：按模块统计 **CCN>10**（可配 **`high_ccn_threshold`**）的函数个数；各模块个数上限见 **`scripts/lizard_module_ccn_caps.toml`**，未登记模块回退 **`default_over_max`**（默认 **0**）；棘轮要求实测个数与 cap **恰好相等**，变少须调低 cap）。可选 **`--module crates/…|src/…`**、**`--list-modules`**、**`--list-above N`**（列出高于 N 的函数，不改变失败条件）、**`--write-caps`**（按当前实测超阈个数重写 caps）
- **`fn-param-ratchet`**：Rust 函数形参个数（**`scripts/fn-param-ratchet.sh`** / **`scripts/fn_param_rust_metrics.py`**；硬上限 **32** 与 `scripts/fn_param_*.txt` 基线写死在 Python 内）
- **`fn-nloc-ratchet`**：Rust 函数体 **`nloc`**（lizard）与 **`.rs` 源文件物理行数**（同一脚本 **`scripts/fn-nloc-ratchet.sh`** / **`scripts/fn_nloc_rust_metrics.py`**，基线路径与写回策略写死在 Python 内）；函数棘轮 **`scripts/fn_nloc_max_baseline.txt`**、**`scripts/fn_nloc_top10_sum_baseline.txt`**；文件棘轮 **`scripts/rust_file_max_lines_baseline.txt`**、**`scripts/rust_file_top10_lines_sum_baseline.txt`**；与 **`lizard-rust`** 同在 CI **`.github/workflows/code-complexity.yml`**
- **覆盖率**：**`.github/workflows/code-coverage.yml`** 默认仅 **Actions 手动触发**（`workflow_dispatch`）；本地仍可 `cargo llvm-cov` + **`scripts/check_coverage_ratchet.py`**
- **`./scripts/check-sse-protocol.sh`**（改动 SSE / `fixtures/sse_ag_ui_golden.jsonl` 时；本仓金样，不依赖 frontend）
- **`cargo test -p crabmate-agent golden_final_plan_gate`**（当改动 `crates/crabmate-agent/fixtures/final_plan_gate_golden.jsonl` 或 `per_coord/final_plan_gate*.rs` 时）
- **`cargo test golden_turn_route_decision`**（当改动 `fixtures/turn_route_decision_golden.jsonl` 或 `turn_route_decision` / `run_dispatch` 时）
- **`cargo test golden_outer_loop_phase`**（当改动 `fixtures/outer_loop_phase_golden.jsonl` 或 `outer_loop_driver` / `outer_loop_fsm` / `outer_loop_iteration_reduce` 时）
- **`cargo test -p crabmate-agent golden_workflow_to_plan_requirement`**（当改动 `fixtures/workflow_to_plan_requirement_golden.jsonl` 或 `prepare_workflow_execute` / `PlanRequirementSource` / Gate context 时）
- **`cargo test golden_workflow_reflection_regression`**（当改动 `fixtures/workflow_reflection_regression.jsonl` 或 `workflow_reflection_controller` 时）

未安装 pre-commit 时，可至少执行：

```bash
cargo fmt --all
cargo clippy --all-targets --all-features -- -D warnings
bash scripts/lizard-rust.sh
bash scripts/fn-param-ratchet.sh
bash scripts/fn-nloc-ratchet.sh
```

**说明**：`pre-commit run --all-files` **不会**跑 `commit-msg`；提交说明格式在 **`git commit`** 时由 conventional-pre-commit 校验（见 [`.cursor/rules/conventional-commits.mdc`](../.cursor/rules/conventional-commits.mdc)）。

## Rust：工作区单元测试与集成测试

在**仓库根**执行（默认覆盖 workspace 成员：`crabmate`、`crabmate-web`、`crabmate-sse-protocol`）：

```bash
cargo test
```

### 按包筛选

| 包 | 命令 | 说明 |
| --- | --- | --- |
| 主程序与后端库 | `cargo test -p crabmate` | 大部分 `src/` 与 `tests/` 测例在此包 |
| SSE 协议 crate | `cargo test -p crabmate-sse-protocol` | 协议版本与文档标记自检等 |
| Web 前端 crate | `cargo test -p crabmate-web` | 见下文「前端（Leptos）」 |

### 按名称过滤（示例）

```bash
./scripts/check-sse-protocol.sh
cargo test tool_result_envelope_golden
```

### SSE 协议一键回归脚本

仓库提供脚本：

```bash
./scripts/check-sse-protocol.sh
```

该脚本会串行执行：

- `cargo test -p crabmate sse::protocol::tests`
- `cargo test -p crabmate-sse-protocol control_classify`

如需代理拉取依赖，可先设置：

```bash
export http_proxy=http://localhost:8118
export https_proxy=http://localhost:8118
./scripts/check-sse-protocol.sh
```

改动 **AG-UI 控制面**分发时，须同步 **`fixtures/sse_ag_ui_golden.jsonl`** 并跑前端金样测试（见 [`SSE协议.md`](SSE协议.md)）。**合并/发版前**若改动跨 crate 或公共 API，建议全量 **`cargo test`**（与 [`.cursor/rules/rust-clippy-and-tests.mdc`](../.cursor/rules/rust-clippy-and-tests.mdc) 一致）。

### 可选：nightly 测试

部分环境会用 nightly 跑全量：

```bash
cargo +nightly test
```

## 前端（Leptos / Client `frontend`）

业务 UI 源码在 Client 仓。下列命令均在同级 `../crabmate-client` 执行。

### 宿主目标单元测试（默认）

```bash
cd ../crabmate-client/frontend && cargo test
```

覆盖 Markdown 净化、会话逻辑、`debounce_schedule` 等纯 Rust 逻辑（不启动浏览器）。

### WASM 目标测试（可选）

`wasm-bindgen-test` 用例需安装与 Client `frontend/Cargo.lock` 中 **`wasm-bindgen`** 版本一致的 **`wasm-bindgen-cli`**，并指定 test runner。示例：

```bash
cd ../crabmate-client/frontend
cargo install wasm-bindgen-cli --version 0.2.114 --locked
CARGO_TARGET_WASM32_UNKNOWN_UNKNOWN_RUNNER=wasm-bindgen-test-runner \
  cargo test --target wasm32-unknown-unknown -p crabmate-web
```

### 编译检查（无测例）

```bash
cd ../crabmate-client && cargo check -p crabmate-web --target wasm32-unknown-unknown
```

### 构建静态包（非测试，但 E2E / serve 依赖）

```bash
cd ../crabmate-client && make frontend
# 发布体积：make frontend-release
```

### 本地运行

**一键脚本（推荐，在 Client 仓根）**：

```bash
cd ../crabmate-client
# 可选：CM_DESKTOP_BACKEND_BIN=/path/to/crabmate
./scripts/victauri-e2e.sh victauri_scroll_send
./scripts/victauri-e2e.sh all
```

**手动两终端**（本机有图形桌面时；须先起本仓 `serve`）：

```bash
# 终端 A（本仓）
cargo run -- serve --host 127.0.0.1 --port 18080

# 终端 B（Client 仓）
cd ../crabmate-client/desktop-tauri/src-tauri
CM_E2E_FIXTURES=1 CM_DESKTOP_SERVE_URL=http://127.0.0.1:18080/ cargo tauri dev

# 终端 C（同上 src-tauri）
VICTAURI_E2E=1 CM_E2E_FIXTURES=1 cargo test --no-fail-fast
```

一键脚本会自行拉起 `serve`（默认端口 **18080**）再开桌面壳。

**真实 LLM**（需 `API_KEY`，在 Client 仓）：`REAL_LLM_E2E=1 ./scripts/victauri-e2e.sh real_llm`

### xvfb / headless 环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| **`VICTAURI_USE_XVFB`** | **`1`** | **`1`**：**`exec xvfb-run`** 重入、不弹窗；**`0`**：本机窗口；**`auto`**：无 **`DISPLAY`** 或 **`CI=true`** 时用 xvfb |
| **`VICTAURI_START_TIMEOUT`** | **`90`** | 等待 **`http://127.0.0.1:7373/health`** 的秒数 |
| **`VICTAURI_MAIN_WINDOW_WAIT`** | **`15`** | health 通过后额外等待主窗口加载 |
| **`VICTAURI_PORT`** | **`7373`** | Victauri MCP 端口 |

Debian/Ubuntu 安装：`sudo apt install xvfb`
