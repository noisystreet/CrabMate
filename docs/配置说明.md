# 配置说明

默认配置由仓库 **`config/default_config.toml`**、**`config/session.toml`**、**`config/context_inject.toml`**、**`config/tools.toml`**、**`config/sandbox.toml`**、**`config/planning.toml`**、**`config/memory.toml`** 七段嵌入（各段主体为 **`[agent]`** 扁平键；**`config/tools.toml`** 还可选 **`[tool_registry]`** 表，见下文「`tool_registry` 策略」；**`session`** 为会话相关嵌入片段（历史路径 `.crabmate/tui_session.json`；进程内 TUI/REPL 会话 UI 键已移除）；**`context_inject`** 为首轮 **`living_docs_*`**、**`agent_memory_file_*`**、**`project_profile_inject_*`**、**`project_dependency_brief_inject_*`**；**`tools`** 的 **`[agent]`** 含 **`run_command`** 白名单/超时/工作目录、**`tool_message_*`** / **`tool_result_envelope_v1`**、**`read_file_turn_cache_*`**、**`test_result_cache_*`**、**`session_workspace_changelist_*`**、**`codebase_semantic_*`**（**`codebase_semantic_search`** 与写后失效 **`codebase_semantic_invalidate_on_workspace_change`**）、天气/搜索/**`http_fetch_*`**、**`tool_call_explain_*`**、**`mcp_*`** 等；**`sandbox`** 为 **SyncDefault Docker 沙盒** **`sync_default_tool_sandbox_*`**；**`planning`** 为规划 / 反思 / 编排；**`memory`** 为 **`long_term_memory_*`**）。另嵌入 **`config/llm_vendors.toml`**（**不**并入 `[agent]`）：OpenAI 兼容厂商匹配、`models` 常用列表与出站能力（`fold_system_into_user`、`image_url_content_parts` 等）；改后须**重新编译**，不随 **`POST /config/reload`** 热更新。`load_config` 按 **主默认 → session → context_inject → tools → sandbox → planning → memory** 顺序合并，再被用户配置覆盖（无 **`--config`** 时优先 cwd 的 **`config.toml`** / **`.agent_demo.toml`**；否则 **`$XDG_CONFIG_HOME/crabmate/config.toml`**（可从 **`/etc/crabmate`** 首次种子；源码树内默认跳过，除非设 **`CM_CRABMATE_CONFIG_DIR`**）），最后由环境变量覆盖。

**未知键与越界数值**：用户 **`config.toml`** / **`agent_roles.toml`** 中 **`[agent]`**、**`[tool_registry]`**、**`[[agent_roles]]`** 等已声明表内若出现**未在 CrabMate 中定义的键**，TOML 解析会失败（serde **拒绝未知字段**），避免拼写错误被静默忽略。对 **`finalize` 中有上下限的数值项**（如 **`temperature`**、**`max_message_history`**、**`chat_queue_max_concurrent`** 等），若在 TOML 或 **`CM_*`** 中写出**超出允许范围**的值，启动（及热重载路径上的 **`load_config`**）会返回明确错误，而**不再**仅做静默截断（`clamp`）；详见源码 **`src/config/validate.rs`** 与 **`finalize`** 中的默认值说明。

## 配置热重载（无需重启 `serve` 主进程）

- **CLI（历史）**：同进程 **`repl` `/config reload`** 入口已移除（D2.1）。
- **Web**：**`POST /config/reload`**（JSON body 可为 `{}`；鉴权与 **`/chat`** 等受保护 API 一致——若启动时启用了 Web API 鉴权层则须在请求头携带 **`Authorization: Bearer <token>`** 或 **`X-API-Key: <token>`**）。成功时返回 **`{ "ok": true, "message": "…" }`**。
- **会更新的典型项**：**`api_base`**、**`model`**、**`llm_http_auth_mode`**、**`llm_reasoning_split`**、**`llm_bigmodel_thinking`**、**`llm_kimi_thinking_disabled`**、**`thinking_avoid_echo_system_prompt`**、**`thinking_avoid_echo_appendix` / `thinking_avoid_echo_appendix_file`**（附录正文解析结果）、**`temperature` / `llm_seed`**、各类**超时与重试**、**`run_command` 白名单**、**`http_fetch_allowed_prefixes`**、**`http_fetch_user_agent`**、**`workspace_allowed_roots`**、**`web_api_bearer_token`**、**`web_api_require_bearer`**（见下；与密钥非空的**启动校验**仍以重启后为准）、**`web_audit_log_write_tools`**、**`web_audit_trust_x_forwarded_for`**（写副作用工具审计与 `X-Forwarded-For` 首跳信任；见下「Web 写工具审计」）、**`mcp_*`**、**`[tool_registry]`**（HTTP 外圈超时、并行墙钟覆盖、并行拒绝/内联/写副作用名单）、**`system_prompt_file` 重读**、上下文与规划相关键等（实现见源码 **`apply_hot_reload_config_subset`**）。**`system`→`user` 折叠**随 **`api_base` / `model`** 热更后由下一轮请求按 MiniMax 识别自动生效（非 `AgentConfig` 字段）。
- **刻意不热更**：**`conversation_store_sqlite_path`**（会话库连接在启动时打开，改路径须重启 **`serve`**）。**`reqwest::Client`** 不重建，**`api_timeout_secs` 等**对**新连接**的生效可能受连接池保留的空闲连接影响。**`[[scheduled_agent_task]]` 的 cron 注册**仅在 **`serve` 启动**时完成；热重载可更新内存中的 `scheduled_agent_tasks` 列表（供将来扩展或人工对照），**已运行的调度器不随热重载重建**——改 `schedule`、增删任务须**重启 `serve`**。
- **`API_KEY`**：**`serve` / 运维子命令**启动时可读取密钥并保存在内存（可为空）。对话权威密钥为请求体 **`client_llm.api_key`**（官方 Client）；进程 **`API_KEY`** 仅为可选回退。服务端 **不再** 持有 / 回填 `client_llm` / `executor_llm` / `saved_model_*` 钥匙串槽；**`PUT /user-data/secrets/client-llm`** 已移除。同进程 **`repl` / `chat` / `tui` 及 `/api-key` 入口已移除**（D2.1）。**热重载不**重读环境。**`crabmate models` / `probe`** 在 **`bearer`** 下仍要求启动前环境变量 **`API_KEY`** 非空。
- **配置路径与桌面对齐（`serve` / 运维 CLI）**：无 **`--config`** 且 cwd 无本地 `config.toml` / `.agent_demo.toml` 时，采用 **`$XDG_CONFIG_HOME/crabmate/config.toml`**（可从 `/etc` 种子；源码树内也采用）；并合并 **`$XDG_DATA_HOME/crabmate/llm_overrides.json`**（api_base / model 等）与 **`prefs.json`** 的 **`cm_role`**。**不**自动恢复 **`prefs.last_workspace_root`**（须 **`--workspace`**）。密钥见上条。
- **Web API 鉴权层**：若启动 **`serve`** 时 **`web_api_bearer_token` 非空**，Axum 会在该进程生命周期内挂上鉴权中间件；请求须带 **`Authorization: Bearer <同一密钥>`** 或 **`X-API-Key: <同一密钥>`**（二选一，与 Dify / Open WebUI 等常见网关习惯对齐）。密钥来源优先级：**`CM_WEB_API_BEARER_TOKEN` / TOML `web_api_bearer_token`** → **系统钥匙串**（**`crabmate web-bearer set`** 或 Web **`/user-data`** 写入的 **`web_api_bearer`**）。**`web_api_require_bearer`**（嵌入默认 **`false`**）为 **`true`** 时，**未配置非空密钥则 `serve` 拒绝启动**（含仅监听 `127.0.0.1`）。为 **`false`** 时允许无密钥启动；密钥仍为空则中间件不校验，受保护 API 可对能访问监听地址的客户端匿名调用（仅限可信环境）。热重载**不会**拆除或新增中间件——**从「无 token」变为「有 token」**或反向时，须**重启 `serve`**。热重载仍会更改 handler 内读取的密钥字符串（含钥匙串回退），用于已挂层时的校验。**浏览器侧**：环境变量 / 钥匙串只配置服务端校验值；打开 Web **设置 →「Web API 共享密钥（访问本服务）」**（外观相关页顶部，与「模型」分区视觉区分）填入**相同**字符串并保存，前端写入本页内存与 **`localStorage`** 键 **`crabmate-api-bearer-token`**，之后 `fetch` 才会带上头。这与模型 **`API_KEY`** / 「模型 API 密钥」无关。仅设置服务端密钥而不在浏览器保存，会出现 **401**（「缺少或无效的 Web API 凭证」）；状态栏会提供 **「填写 Web Bearer」** 入口。保存成功后会自动重试 **`/status`**、清理鉴权类错误并再拉会话水合。XDG **`config.toml` / `llm_overrides.json` 不会**让浏览器自动带上 Web Bearer。若仍见 401，可再点状态栏「重试」。**个人 VPS + 反向代理 TLS** 的落地步骤见 **`docs/个人VPS部署指南.md`**。
- **测试时临时跳过 Web Bearer**：中间件只在服务端密钥**非空**时校验。本机调试推荐：`unset CM_WEB_API_BEARER_TOKEN`（并清空 TOML / XDG 中的 **`web_api_bearer_token`**，必要时 **`crabmate web-bearer clear`**），`cargo run -- serve --host 127.0.0.1`，浏览器开回环地址即可匿名调受保护 API。仍需 **`0.0.0.0`** 时：同样先清掉密钥，再设 **`CM_ALLOW_INSECURE_NO_AUTH_FOR_NON_LOOPBACK=true`**（或 TOML **`allow_insecure_no_auth_for_non_loopback = true`**）后启动——**仅可信局域网**；密钥仍非空时该开关**不能**消除 401。勿在公网或不可信网络长期关闭鉴权。
- **Web 写工具审计（结构化日志）**：**`web_audit_log_write_tools`**（默认 **`true`**）为 **`true`** 时，每次**成功执行**的**非只读**内置工具在 tracing 中输出一行 **`target=crabmate::audit_write_tool`** 的 **`info`** 日志（字段含 Unix 毫秒时间戳、`job_id`、记忆/会话作用域 id、来源 **`http`** 或 **`scheduled`**、`client_ip` / `peer_ip`、与配置密钥一致的 **`bearer_fp`**（共享密钥的 SHA-256 **前 12 位十六进制**，请求未携带或未匹配有效凭证时为 `-`）、工具名与脱敏 **`args_preview`**）。**不**记录 Bearer / `X-API-Key` 明文。CLI / `bench` 等非 Web 路径不产生此类审计行。**`web_audit_trust_x_forwarded_for`**（默认 **`false`**）为 **`true`** 时，`client_ip` 优先取 **`X-Forwarded-For` 首跳**（逗号分隔列表左侧）；仅在 CrabMate **置于可信反向代理之后**时开启，否则易被客户端伪造。
- **敏感字段内存表示**：**`web_api_bearer_token`** 与 **`web_search_api_key`** 在 [`AgentConfig`](开发文档.md) 内为 **secrecy `SecretString`**，**`Debug` / 结构化日志默认不打印明文**；源码中通过 **`ExposeSecret::expose_secret()`** 取用（`config` crate 再导出 **`ExposeSecret`**）。**`API_KEY`** 仍为仅环境变量，未并入 `AgentConfig`。

## 环境变量（`CM_*`）

以下为常用项；**完整键名与默认值以 `config/default_config.toml`、`config/session.toml`、`config/context_inject.toml`、`config/tools.toml`、`config/sandbox.toml`、`config/planning.toml`、`config/memory.toml` 为准**。**`API_KEY`** 仅环境变量，见下节「模型与 API」表格；热重载与密钥行为见上文「配置热重载」。

### 模型与 API

| 环境变量 | 说明 |
| --- | --- |
| `API_KEY` | 云厂商 Bearer；**`serve` 可在未设置时启动**。对话权威：请求体 **`client_llm.api_key`**。进程环境仅为可选回退；**`models` / `probe`** 在 bearer 下仍要求非空。服务端不再读写模型钥匙串槽。`llm_http_auth_mode=none` 时可不设。 |
| `CM_API_BASE` | 覆盖 `api_base`。 |
| `CM_MODEL` | 覆盖 `model`。 |
| `CM_LLM_HTTP_AUTH_MODE` | `bearer`（默认，需 **`API_KEY`**）或 `none`（不向 `chat/completions` / `models` 发 `Authorization`，本地 Ollama 等可不设 **`API_KEY`**）。 |
| `CM_LLM_REASONING_SPLIT` | 覆盖 `llm_reasoning_split`。未在 TOML/环境变量设置时：**MiniMax 网关**（`model` 或 `api_base` 可识别为 MiniMax）**默认为开**（`true`），其它网关默认为关；见下文「MiniMax」。 |
| `CM_LLM_BIGMODEL_THINKING` | 为真时在请求体中带智谱 **`thinking: { "type": "enabled" }`**（GLM-5 深度思考；见下文「智谱 GLM」）。 |
| `CM_LLM_KIMI_THINKING_DISABLED` | 为真时在请求体中带 **`thinking: { "type": "disabled" }`**（关闭 Moonshot **kimi-k2.5** 默认思考；见下文「Moonshot（Kimi）」）。 |
| `CM_SYSTEM_PROMPT` | 内联系统提示；会清除继承的 `system_prompt_file`（若再设 `CM_SYSTEM_PROMPT_FILE` 则以文件为准，见「系统提示词」）。 |
| `CM_SYSTEM_PROMPT_FILE` | 系统提示词文件路径。 |
| `CM_DEFAULT_CM_ROLE` | 未传 Web / API `agent_role` 时使用的**默认角色 id**（须已在角色表中定义；见下文「多角色」）。全局 CLI **`--agent-role` 已随同进程对话入口移除**。 |

### Web 服务

| 环境变量 | 说明 |
| --- | --- |
| `CM_HTTP_HOST` | 未传 `--host` 时作为绑定地址。 |
| `CM_WEB_API_BEARER_TOKEN` | 受保护 Web API 的共享密钥（服务端校验）。请求头须为 **`Authorization: Bearer …`** 或 **`X-API-Key: …`**（值相同）。未设置且 TOML 亦空时，**`serve`** 可回退系统钥匙串（**`crabmate web-bearer set`** / Web 侧栏同源）。浏览器须在 **设置 → Web API 共享密钥** 另行保存同一串（见上文「Web API 鉴权层」）；**不是**模型 `API_KEY`。 |
| `CM_WEB_API_REQUIRE_BEARER` | 未设置时继承嵌入默认（**`false`**）：允许无密钥启动 **`serve`**；设为 **`1`/`true`** 等价 **`[agent] web_api_require_bearer = true`**，启动前须已配置非空的 **`CM_WEB_API_BEARER_TOKEN`**（或 TOML **`web_api_bearer_token`**），否则拒绝启动。 |
| `CM_WEB_CORS_ALLOWED_ORIGINS` | 逗号分隔的 Origin 白名单（trim 每项，跳过空段）；对应 TOML **`web_cors_allowed_origins`**。**未设置**时默认放行官方壳 Origin：**`tauri://localhost`**（Linux WebKit `fetch`）与 **`http://tauri.localhost`**（Android http 资产），并挂 CORS 层（暴露 **`x-conversation-id` / `x-stream-job-id` / `x-request-id`**，`/uploads` CORP 为 **`cross-origin`**）。**显式空串**（或 TOML 空列表）关闭 CORS。非空时与上述默认壳 Origin **合并**（无 `*`）。改后须**重启 `serve`**。浏览器另开静态站时把其 Origin 写入本变量或 TOML 即可。 |
| （浏览器）API 基址 | **无** `CM_*`：Web **设置 →「API 基址」**，写入 **`localStorage`** 键 **`crabmate-api-base-url`**（空=同 Origin 相对路径；**键存在的空串**表示显式同 Origin，不会回落到构建期默认）。可选构建期默认 **`CRABMATE_API_BASE`**（仅在键缺失时生效）。跨 Origin 时须配合上表 CORS 与 Web Bearer。冒烟：**`docs/design/client_turn_smoke_runbook.md`** §9。 |
| `CM_WEB_AUDIT_LOG_WRITE_TOOLS` | 覆盖 **`web_audit_log_write_tools`**；默认 **`true`**：写副作用工具审计日志（**`target=crabmate::audit_write_tool`**）。 |
| `CM_WEB_AUDIT_TRUST_X_FORWARDED_FOR` | 覆盖 **`web_audit_trust_x_forwarded_for`**；默认 **`false`**：审计里的 **`client_ip`** 是否信任 **`X-Forwarded-For`** 首跳。 |
| `CM_ALLOW_INSECURE_NO_AUTH_FOR_NON_LOOPBACK` | 非回环（如 `0.0.0.0`）且**未**配置非空 `web_api_bearer_token` 时，是否允许启动（默认拒绝）。设为 `true` / `1` 可本地/局域网**临时**无鉴权调试（高风险）。**密钥仍非空时中间件照样校验**，须先 `unset CM_WEB_API_BEARER_TOKEN` 并清空 TOML 同名键。 |
| `CM_CRABMATE_USER_DATA_DIR` | 覆盖本机用户数据根（绝对路径）；默认 **`$XDG_DATA_HOME/crabmate`**（Linux 多为 **`~/.local/share/crabmate`**）。存放 Web 侧栏会话、壳层偏好、LLM **非机密**覆盖，以及仍使用文件存储的 Web API/MCP token；LLM API Key 改存系统钥匙串。见 **`docs/design/user_data_dir.md`**。 |
| `CM_GITHUB_OAUTH_SCOPES` | 可选。非空时作为 Device Flow 的 `scope`（空格分隔，如 OAuth App 的 `repo`）。**未设置或空**：请求**不带** `scope`（适合 GitHub App，权限在 App 设置里配）。Client ID / user token **不**再由服务端 env/钥匙串保存：仅在客户端按需配置，经 `POST /github/oauth/device/start` body 与请求头 / Cookie 交给服务端（见 **`docs/命令行与路由.md`**）。运维无 UI 时可直接设 **`GH_TOKEN` / `GITHUB_TOKEN`**。 |
| `CM_CRABMATE_CONFIG_DIR` | 覆盖本机用户**配置**根（绝对路径）；默认 **`$XDG_CONFIG_HOME/crabmate`**（多为 **`~/.config/crabmate`**）。无 **`--config`** 时发现顺序：**cwd** **`config.toml`** / **`.agent_demo.toml`**（可并存合并）→ 否则本目录下的 **`config.toml`**。若尚无用户 **`config.toml`** 且系统有 **`/etc/crabmate/config.toml`**（桌面 deb 模板），首次会**种子拷贝**运行时所需子集（**`config.toml`**、**`agent_roles.toml`**、**`prompts/`**、**`config/`**、可选 **`skills/`**；**不**拷贝嵌入分片如 **`tools.toml`**；**不覆盖**已有文件）。在 CrabMate **源码树内**默认**不**自动采用本机 XDG（避免开发机装过 deb 后污染嵌入默认）；设本变量则可强制走 XDG。运行时以用户副本为准（桌面仅在种子失败时只读回退 `/etc`）。 |
| `CM_CRABMATE_SKIP_CONFIG_SEED` | 为 **`1`** / **`true`** / **`yes`** / **`on`** 时跳过从 **`/etc/crabmate`** 的种子拷贝（测试/CI）。 |

**Web 工作区**：**`serve`** 启动后，在侧栏通过 **`POST /workspace`** 选择目录之前，服务端不把 **`run_command_working_dir`**（默认常为 `"."`）视为「已选工作区」：不注入依赖工作区根的首轮上下文，**`@路径`** 引用会返回 **`WORKSPACE_NOT_SET`**，**SyncDefault** 类内置工具亦不可用；对话任务入队时进程内工作目录仍会规范为 **`run_command_working_dir`**，**`GET /health`** 对该目录做可选依赖探测。显式将工作区设为与 **`run_command_working_dir`** 等价的目录后，行为与旧版「默认 cwd 即工作区」一致。

**Web 项目池（`web_workspace_pool` / `CM_WEB_WORKSPACE_POOL`）**：面向 VPS / 远程浏览器。将固定目录（如 **`/workspace`**）作为项目池；用户通过 **`GET/POST /workspace/projects`** 或 Web「项目 → 选择工作区」弹窗按**项目名**（字母数字及 `._-`）打开或新建子目录（如 `/workspace/my-app`），亦可「项目 → Clone 远程仓库…」经 **`POST /workspace/clone/stream`** 将远程仓克隆到池内并自动切换工作区（需服务端已安装 **`git`**；**`https://github.com/`** 私有仓可走请求头 / Cookie / **`GH_TOKEN`** 凭据，其它 host 或 SSH 仍依赖本机凭据；超时 20 分钟），无需在浏览器里输入服务器绝对路径。配置池根时**必须**同时设置非空 **`workspace_allowed_roots`**（或 **`CM_WORKSPACE_ALLOWED_ROOTS`**），且池根须落在白名单内；命中敏感系统前缀（如 `/etc`、`/usr`）会在启动时拒绝。建议配置 **Web Bearer 鉴权**。目录不存在时 finalize 会尝试 **`mkdir -p`** 创建池根。

**路径安全（与实现一致）**：`workspace_allowed_roots` 与每次请求对当前工作区根的重验可拒绝明显的 `..` 逃逸与**校验时刻**已指向根外的 symlink。在 **Unix** 上，**`read_file`**（`resolve_for_read_open`）与 **Web** 工作区列表、读/写/删文件等经 **`src/workspace/fs.rs`**：Linux 上使用 **`openat2` + `RESOLVE_IN_ROOT`** 在已打开的工作区根 fd 上解析相对路径并打开，将「策略校验后的路径字符串」与「实际 `open`」之间的竞态窗口收窄；工作区内 symlink 仍可跟随，但解析不得越过该根。**残余风险**：校验阶段仍依赖该时刻的 `canonicalize`；非 Linux、或未走 `workspace_fs` 的代码路径仍可能存在 TOCTOU；**`create_dir_all`** 等与按路径打开的组合亦未完全原子化。不可等同于内核沙箱；开放网络须配 **Web 鉴权**等。详见 **`src/workspace/path.rs`** 模块注释。

| 配置 / 机制 | 生效阶段 | 与 `plan_rewrite_max_attempts` 的关系 |

**DeepSeek 官方 `api_base` 与普通 Agent 请求（思考开关）**：当 **`api_base`** 含 **`deepseek`** 或模型 ID 以 **`deepseek-`** 开头、且未被 Kimi/MiniMax/智谱路由命中时（匹配表见 **`config/llm_vendors.toml`**），出站 **`chat/completions`** 可按 [思考模式](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode) 携带 **`thinking: {"type":"enabled"|"disabled"}`**，并在显式 **`enabled`** 时附带 **`reasoning_effort: "high"`**（与文档 OpenAI 兼容字段一致）。映射：**`llm_bigmodel_thinking = true`**（Web **`client_llm.llm_thinking_mode: on`**、**`CM_LLM_BIGMODEL_THINKING=1`**）→ **`enabled`** + **`reasoning_effort`**；**`llm_kimi_thinking_disabled = true`**（Web **`llm_thinking_mode: off`** 会置位）→ **`disabled`**（不传 **`reasoning_effort`**）；二者均未触发则**省略**两字段，由网关默认（文档：默认思考 **enabled**）。无工具结构化 JSON 路径（若存在）仍会清除 **`thinking` / `reasoning_split` / `reasoning_effort`**。常用 **`models`** 列表与是否允许 **`image_url`** 内容块（如 **`deepseek-v4-flash-vision-exp`**）亦见该目录文件。聊天附图在会话中只存 **`/uploads/<文件名>`**（文件落在会话库旁的 **`chat_uploads/`**，默认与 **`conversations.db`** 同级，**不**随 `POST /workspace` 切换；`GET /uploads/{filename}` 与其它 API 同鉴权）；工作区 **`@图.png` / `file:///图.png`** 不按源码展开。出站时：文本模型去掉图片块以免 400；视觉模型把 `/uploads/` 与工作区栅格图打成 **`data:`** URL（[图像理解](https://api-docs.deepseek.com/zh-cn/guides/vision)）。请把 **`model`** 设为 **`deepseek-v4-flash-vision-exp`** 才能看图。

### 命令白名单、MCP、会话存储

**TOML 专用（无 `CM_*`）**：`[agent]` 键 **`allow_external_path_with_approval`**（嵌入默认 **`true`**，见 **`config/tools.toml`**）：为真时，`run_command` / `terminal_session` 的 argv 若含工作区外绝对路径或**路径穿越形** `..`/`../`（及 `cd … &&` 前缀中的同类路径），可经 **人工审批** 后执行；为假则仍无条件拒绝。**git 修订范围**（如 `main..HEAD`）不算穿越。**不**审计 `bash`/`sh -c` 脚本字符串内部路径；**Docker** 同步沙盒模式下仍拒绝。CLI **`--yes`** 会一并自动批准此类外部路径审批（极危险）。白名单含 **`bash`/`sh`** 时，需要 glob/`$VAR`/`~` 的 `run_command` 会把 **完整脚本** 交给 `bash -c`（审批卡片也展示该脚本）；独立 argv 中的 **`&&` / `|` / `;`** 在 **Web** 上即使 bash 已在白名单也会**再审**该脚本（避免 `ls && rm` 绕过单命令白名单）。`cd dir && git status` 会先剥 `cd` 前缀，不因此误走脚本审批。从白名单去掉 bash/sh 则回到纯 `execve`（无展开，除非 Web 审批后临时加入 `bash`）。

#### 动态工具（工作区 `plugins/*.json`）

- 无需额外开关：每轮 `run_agent_turn` 会扫描当前工作区 `plugins` 目录下的 `*.json`，动态注册工具。
- 工具名必须以 **`dyn__`** 开头，避免与内置/MCP 工具冲突。
- 运行时字段最小示例：
  ```json
  {
    "name": "dyn__echo_args",
    "description": "将入参 JSON 透传给脚本",
    "parameters": {
      "type": "object",
      "properties": {
        "text": { "type": "string" }
      },
      "required": ["text"]
    },
    "command": "python3",
    "args": ["scripts/echo_args.py"],
    "pass_args_json": true
  }
  ```
- 安全约束与内置命令工具一致：`command` 必须命中 **`allowed_commands`** 白名单；执行目录固定当前工作区；动态工具默认按“未知副作用”处理，不参与只读并行批。

### 联网搜索与 `http_fetch`

| 环境变量 | 说明 |
| --- | --- |
| `CM_WEB_SEARCH_PROVIDER` | 搜索供应商：默认 **`worbrow`**（本机浏览器，别名 `browser`）；可选 **`brave`** / **`tavily`**（需 API Key）。 |
| `CM_WEB_SEARCH_API_KEY` | 搜索 API 密钥（仅 `brave` / `tavily`）。 |
| `CM_WEB_SEARCH_TIMEOUT_SECS` | **内层**搜索超时（秒）；默认 **60**（适配 worbrow）。 |
| `CM_WEB_SEARCH_MAX_RESULTS` | 最大结果数。 |
| `CM_HTTP_FETCH_ALLOWED_PREFIXES` | `http_fetch` / `http_request` URL 前缀（CSV）。条目 **`*`** 表示任意 **http/https**（嵌入默认 **`["*"]`**）。**显式空**（TOML `[]` 或环境变量设为空串）覆盖嵌入默认，全部走审批（Web）或同步路径失败。具体前缀须可解析为 URL，按同源 + 路径前缀边界匹配。 |
| `CM_HTTP_FETCH_TIMEOUT_SECS` | 抓取超时（秒）。 |
| `CM_HTTP_FETCH_MAX_RESPONSE_BYTES` | 响应体截断上限。 |
| `CM_HTTP_FETCH_USER_AGENT` | `http_fetch` / `http_request` 请求 `User-Agent`（默认 **`crabmate/<版本>`**）。 |

**`worbrow`**：链接 [worbrow](https://crates.io/crates/worbrow) **≥0.2.0** 库，优先使用本机 **Firefox**，否则 **Chrome/Edge/Chromium**；引擎链默认 **`bing,duckduckgo`**（验证码/低质低产时降级）；结果含解包装后的落地 URL、`domain`，以及质量信号（`result_kind` / `is_ad` / `published_at` 等）。库另提供正文抓取 **`fetch`/`fetch_page`**（CrabMate 仍用自有 **`http_fetch`**）。无浏览器时请改用 `brave`/`tavily` 或安装浏览器。Docker SyncDefault 沙盒内通常**没有**宿主浏览器，请改 API 供应商或勿在沙盒内依赖联网搜索。

**`web_search` 外圈超时**：异步路径在 **`spawn_blocking`** 外另有墙钟，默认 = **`web_search_timeout_secs` + 宽限**（worbrow **+15s**，brave/tavily **+2s**），以便内层先超时并收尾浏览器/连接，避免外圈先放弃等待后残留进程。可用 **`[tool_registry].parallel_wall_timeout_secs.web_search_spawn_timeout`** 覆盖并行批/外圈墙钟。

**`http_fetch` / `http_request` 外圈超时**：除 **`http_fetch_timeout_secs`**（`reqwest` 读超时）外，异步路径在 **`spawn_blocking`** 外包一层 **`tokio::time::timeout`**；默认与 **`command_timeout_secs`**、**`http_fetch_timeout_secs`** 取较大者。可在 TOML **`[tool_registry]`** 中设 **`http_fetch_wall_timeout_secs`** / **`http_request_wall_timeout_secs`** 单独收紧或放宽（见 **`config/tools.toml` 文件末尾注释**）。

**`http_fetch` / `http_request` URL 闸门**：嵌入默认 **`http_fetch_allowed_prefixes = ["*"]`**，任意 **http/https** 不再弹前缀审批。**风险**：模型可请求环回、内网与云元数据地址（SSRF）；**`http_request` 还可对同一范围发 POST/PUT/PATCH/DELETE**。多租户或监听非本机时请改为具体前缀，或 **TOML `http_fetch_allowed_prefixes = []` / `CM_HTTP_FETCH_ALLOWED_PREFIXES=`（空串）** 覆盖嵌入默认以恢复「未匹配须审批」。省略该键不会清空列表。scheme 仍仅 **http/https**。

**`http_fetch` / `http_request` 请求行为（向 curl 对齐）**：自动发送 **`Accept: */*`** 与 **`Accept-Encoding`**（gzip/brotli/deflate，响应体自动解压，减少未压缩原文撞截断上限）；**`User-Agent`** 默认 **`crabmate/<版本>`**，可用 TOML **`[agent]` / `[tool_registry]` 的 `http_fetch_user_agent`** 或环境变量 **`CM_HTTP_FETCH_USER_AGENT`** 覆盖（例如设为浏览器 UA 或 curl UA 以应对反爬站点）。
**环境代理**：遵循 **`ALL_PROXY` / `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`**（HTTP(S) 代理正常）；注意 **reqwest 0.13 不支持 SOCKS**——若代理为 `socks5://` 等（常见于 Clash/v2ray），`http_fetch` 会失败并提示，可用 **`unset ALL_PROXY HTTPS_PROXY HTTP_PROXY`** 或改用同端口 **`http://`** 代理（如 Clash 混合端口）后重试。

| **`parallel_sync_denied_tools`** | 禁止与其它只读工具同批并行的工具名（精确匹配）；省略用内建构建锁类规则。 |
| **`parallel_sync_denied_prefixes`** | 同上，按工具名前缀拒绝并行批。 |
| **`sync_default_inline_tools`** | 在当前 async 任务上**内联**执行的 SyncDefault 工具（跳过 **`spawn_blocking`**）；省略则仅内建轻量工具。 |
| **`write_effect_tools`** | 视为非只读（写副作用）的工具名；影响 **`is_readonly_tool`**、解释卡、代码语义索引失效等；省略用内建写工具表。 |

**后台任务（`run_command` 的 `async:true`）**：以上 **`[tool_registry]`** 表另含后台任务 6 键（默认见 **`config/tools.toml`** 注释；仅 TOML，无 `CM_*`）：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| **`background_jobs_enabled`** | `false` | 总开关；`false` 时 `run_command` 传 **`async:true`** 返回 `invalid_args` |
| **`background_job_max_concurrent`** | `4` | 同时运行上限；超出进入 `queued`（FIFO） |
| **`background_job_max_queued`** | `32` | 排队上限；`0` = 满并发即拒绝创建 |
| **`background_job_ttl_secs`** | `86400` | 自**创建**起算的保留时长（秒），到期轮询返回 `410 JOB_EXPIRED` |
| **`background_job_result_grace_secs`** | `300` | 终态后再保留的宽限（秒）；`0` = 完成即到期 |
| **`background_job_max_entries`** | `128` | 注册表条目上限；**仅淘汰终态**条目 |

轮询/取消端点（**`GET /tools/jobs/{id}`**、**`POST /tools/jobs/{id}/cancel`**）与 `run_command` 的 `async` 参数语义见 **`docs/命令行契约.md`** 与 **`docs/工具说明.md`**；读取时机为**创建 job 时**，已运行 job 不受后续热重载影响。

**按工作区与用户提问的动态选材**：启用 **`skills_enabled`** 并配合 **`skills_top_k`**（及 **`CM_SKILLS_TOP_K`**）时，Web（及 Client **`crabmate-tui`**）可在每轮按当前用户输入从**已合并的三层 skills**选取片段并入首条 **`system`**（见 **`docs/design/system_prompt_assembly.md`**（**L5**））。三层目录：**工作区** **`skills_dir`**（默认 **`.crabmate/skills`**）、**用户级** **`skills_user_dir`**（默认 **`$XDG_CONFIG_HOME/crabmate/skills`**）、**系统级** **`skills_system_dir`**（默认 **`/etc/crabmate/skills`**）；同 callable id 优先级为 **工作区 > 用户 > 系统**（跨层覆盖；同层同 id 仍可能歧义）。与「源码树是否自动加载 XDG `config.toml`」**无关**：skills 约定路径始终可用（目录不存在则跳过）。测试/CI 可用 **`CM_SKILLS_DISABLE_HOST_LAYERS=1`** 关掉主机层。首次从 **`/etc/crabmate`** 种子用户配置时，若存在 **`skills/`** 会一并拷到 XDG（不覆盖）；系统层仍会继续扫描 **`/etc`**，故仅删用户副本不足以禁用包内 skill。skills 支持平铺 **`*.md`** 与 Cursor 同形的 **`<id>/SKILL.md`**。另支持 Cursor 同形的 **显式调用**：用户消息为 **`/<skill-id> [可选任务说明]`** 时，按 frontmatter **`name`**（或平铺文件 stem / 子目录名）解析唯一 skill，**强制**注入其正文（跳过 Top-K），并将去掉前缀后的文字作为真正 `user`（若无任务正文则用默认句「请按该技能执行。」）。内建命令（`/help`、`/skills`、`/clear`…）仍优先，不会被当成 skill id。未知 `/id` 返回明确错误（Web：`SKILL_INVOKE_FAILED`）。**Web** 输入框输入 **`/`** 时浮层展示 **内建命令**（当前：`/skills`、`/skills list`）与 skill **id + description**（`GET /skills`；description 来自 frontmatter **`description:`**，缺省则用正文首行；响应含 **`skills_dir` / `skills_user_dir` / `skills_system_dir`**）。IME 组字过程中不拦截方向键/Enter、也不触发发送。**`/skills list`** 会列出可 `/id` 调用的标识。

## 本地 Ollama（OpenAI 兼容）

Ollama 提供 **`http://127.0.0.1:11434/v1`** 下的 OpenAI 兼容 API。建议配置：

```toml
[agent]
api_base = "http://127.0.0.1:11434/v1"
model = "llama3.2"   # 以 ollama list 为准
llm_http_auth_mode = "none"
```

然后可不设环境变量 **`API_KEY`** 即启动 `serve`。若使用默认 **`llm_http_auth_mode=bearer`**（云端网关）而未 export **`API_KEY`**，进程仍可启动；对话密钥优先走请求体 **`client_llm.api_key`**（官方 Client），进程 **`API_KEY`** 仅为可选回退；服务端模型钥匙串槽已退役。皆无时对话会报缺密钥（Web 为 **`LLM_API_KEY_REQUIRED`** 等）。同进程 **`repl` / `chat` / `tui` 入口已移除**。**工具调用（function calling）**依赖模型与 Ollama 版本；若不稳定可先 **`--no-tools`** 验证对话。`crabmate config`（自检）**不要求** **`API_KEY`**。

## MiniMax（OpenAI 兼容）

MiniMax 提供 **`https://api.minimaxi.com/v1`**（与官方文档一致；亦可能见 **`https://api.minimax.io/v1`** 等别名，以控制台为准）下的 OpenAI 兼容 **`POST …/chat/completions`**。官方文档示例含 **`role: "system"`**（见 [OpenAI API 兼容](https://platform.minimaxi.com/docs/api-reference/text-openai-api)），但**线上接口仍常返回** HTTP 400 **`invalid message role: system`**。CrabMate 在识别为 **MiniMax**（**`model`** 形如 **`MiniMax-…`** / **`abab…`**，或 **`api_base`** 主机名含 **`minimax`**）时**自动**将系统提示**并入**相关 **`user`**，无需 TOML 配置。其它网关保留独立 **`system`** 条。

**本仓库已实测的 `model` 示例**（与 CrabMate OpenAI 兼容调用链联调）：**`MiniMax-M2.7`**、**`MiniMax-M2.7-highspeed`**、**`MiniMax-M2.5`**。更多模型名与能力以 MiniMax 控制台及官方 API 文档为准。

建议配置：

```toml
[agent]
api_base = "https://api.minimaxi.com/v1"
model = "MiniMax-M2.7"   # 或 M2.7-highspeed / M2.5 等；以控制台为准
llm_http_auth_mode = "bearer"
# llm_reasoning_split：可省略；未写时 MiniMax 网关默认为 true（思维链分离）
# llm_reasoning_split = false   # 若不需要 reasoning_split，可显式关闭
```

环境变量 **`API_KEY`** 填平台发放的密钥（与 DeepSeek 等一致，走 **`Authorization: Bearer`**）。**`llm_reasoning_split`** 为 **`true`**（含未写配置时 MiniMax 的默认值）时，请求体会包含 **`reasoning_split: true`**（与文档中 `extra_body={"reasoning_split": True}` 一致）；供应商若在流式 **`delta`** 中返回 **`reasoning_details`**（常见为带 **`text`** 的 JSON 数组），CrabMate 会将其**增量合并**进内部的 **`reasoning_content`** 流与终态消息，终端/Web 仍按现有「思考 / 正文」路径展示。非 MiniMax 网关未写该键时默认为 **`false`**；MiniMax 下不需要分离思维链时请显式 **`llm_reasoning_split = false`** 或 **`CM_LLM_REASONING_SPLIT=0`**。

### 思维链中减少复述系统提示

默认 **`thinking_avoid_echo_system_prompt = true`**（**`[agent]`** 键，嵌入默认见 **`config/default_config.toml`**，与 **`system_prompt_file`** 同节）：附录正文默认来自 **`thinking_avoid_echo_appendix_file`**（仓库内 **`config/prompts/thinking_avoid_echo_appendix.md`**，可**直接改该 Markdown** 无需重编）；亦可 **`thinking_avoid_echo_appendix`** 内联多行字符串。**优先级**：配置了非空 **`thinking_avoid_echo_appendix_file`** 时**读盘优先**于内联；均未配置时用编译嵌入的默认正文。经 **`tool_stats::augment_system_prompt`** 拼到新会话首条 **`system`** 末尾。仅为**软性约束**。关闭开关：**`thinking_avoid_echo_system_prompt = false`** 或 **`CM_THINKING_AVOID_ECHO_SYSTEM_PROMPT=0`**。仍复述时可再收紧自有 **`system_prompt`** 或换模型。

## 智谱 GLM（OpenAI 兼容）

智谱在 **`https://open.bigmodel.cn/api/paas/v4`** 下提供 OpenAI 兼容 **`POST …/chat/completions`**。请将 **`api_base`** 设为 **`https://open.bigmodel.cn/api/paas/v4`**（**不要**再拼 `/chat/completions`，程序会追加），**`model`** 如 **`glm-5`**；环境变量 **`API_KEY`** 填控制台密钥（**`llm_http_auth_mode = bearer`**），请求头 **`Authorization: Bearer …`** 与官方 cURL 一致。

### 与最小 cURL 对齐（默认流式、无深度思考）

下列官方风格的请求只需 **`model`**、**`messages`**、**`stream: true`**（无 **`thinking`**）即可工作：

```bash
curl --location 'https://open.bigmodel.cn/api/paas/v4/chat/completions' \
  --header 'Authorization: Bearer YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{
    "model": "glm-5",
    "messages": [{ "role": "user", "content": "写一首关于春天的诗" }],
    "stream": true
}'
```

在 CrabMate 中：**默认 `llm_bigmodel_thinking = false`** 时出站 JSON **不**含 **`thinking`**，与上例同形（另会带 OpenAI 兼容常用字段 **`max_tokens`**、**`temperature`** 等，来自 **`[agent]`** 配置；智谱兼容端一般接受）。Web / 默认 CLI 对话为 **SSE 流式**，对应 **`stream: true`**；若使用 **`--no-stream`** / **`no_stream`**，则对应 **`stream: false`**。

### 可选：GLM-5 深度思考（`thinking`）

文档中的 **深度思考** 为 **`thinking: { "type": "enabled" }`**（见 [GLM-5 调用示例](https://docs.bigmodel.cn/cn/guide/models/text/glm-5)）。需要时设 **`llm_bigmodel_thinking = true`**（或 **`CM_LLM_BIGMODEL_THINKING=1`**）。流式下思维链可走 **`delta.reasoning_content`**，与现有解析路径一致。

### 配置示例

**最小对接（与上节 cURL 一致，不含 `thinking`）：**

```toml
[agent]
api_base = "https://open.bigmodel.cn/api/paas/v4"
model = "glm-5"
llm_http_auth_mode = "bearer"
# llm_bigmodel_thinking 默认 false，可不写
```

**启用文档中的深度思考时：**

```toml
[agent]
api_base = "https://open.bigmodel.cn/api/paas/v4"
model = "glm-5"
llm_http_auth_mode = "bearer"
llm_bigmodel_thinking = true
# max_tokens、temperature 等按控制台与用量自行调整
```

## Moonshot（Kimi，OpenAI 兼容）

Moonshot 在 **`https://api.moonshot.cn`** 提供与 OpenAI SDK 兼容的 HTTP API；单轮对话示例见 [Kimi Chat API / 单轮对话](https://platform.moonshot.cn/docs/api/chat#%E5%8D%95%E8%BD%AE%E5%AF%B9%E8%AF%9D)。

- **请求地址**：**`POST https://api.moonshot.cn/v1/chat/completions`**（与文档一致）。
- **CrabMate**：将 **`api_base`** 设为 **`https://api.moonshot.cn/v1`**（程序会再追加 **`chat/completions`**）。**`model`** 填文档中的模型 ID（如 **`kimi-k2.5`**、**`kimi-k2-thinking`**、**`moonshot-v1-8k`** 等，以 [List Models](https://platform.moonshot.cn/docs/api/chat#list-models) 与控制台为准）。环境变量 **`API_KEY`** 填平台密钥（**`llm_http_auth_mode = bearer`**）。

**`max_tokens` 与 `max_completion_tokens`**：Kimi 文档将 **`max_tokens`** 标为可选且**已废弃**，推荐使用 **`max_completion_tokens`** 表示**完成段**上限。CrabMate 当前仍序列化 OpenAI 常见字段 **`max_tokens`**（来自 **`[agent] max_tokens`**），多数兼容网关会接受；若遇 **`invalid_request_error`** 与长度相关，请核对文档中的 **`max_completion_tokens`** 语义并适当调低 **`max_tokens`** 或关注后续版本是否增加该字段。

**`thinking`（仅 kimi-k2.5）**：文档说明可选 **`thinking`**，取值 **`{"type": "enabled"}`** 或 **`{"type": "disabled"}`**，**服务端默认接近 enabled**。不写入请求体时由 Kimi 默认行为决定。若需**显式关闭** k2.5 思考模式，在 CrabMate 中设 **`llm_kimi_thinking_disabled = true`**（或 **`CM_LLM_KIMI_THINKING_DISABLED=1`**）；实现上**仅当**当前 **`model`** 为 **`kimi-k2.5` / `kimi-k2.5-…`** 时才会在 JSON 中带 **`thinking: { "type": "disabled" }`**，避免误发给其它网关。若同时开启 **`llm_bigmodel_thinking`** 且 **`model`** 为 k2.5 系列，**以 Kimi `disabled` 优先**（先写 Kimi 关闭）。

**多轮与工具调用**：在 **kimi-k2.5** 且**未**关闭思考（默认）时，接口会校验历史里带 **`tool_calls`** 的 assistant 消息必须带 **`reasoning_content`**，否则会报类似 **`thinking is enabled but reasoning_content is missing in assistant tool call message`**。CrabMate 对此类消息在出站时**保留**会话中的 **`reasoning_content`**（若上游当时未返回则补空串），其它 assistant 条仍按惯例剥离思维链以省 token。关闭思考后按 Kimi 行为一般不再强制该字段。

**`temperature` / `top_p`**：文档对各系列默认值不同，且部分模型**不可修改**。CrabMate 按 **`model`** ID 自动钳制出站 **`temperature`**（含 Web 单条覆盖、上下文摘要轮等），避免 **`invalid temperature`**：**`kimi-k2.5` / `kimi-k2.5-…`** 与 **`kimi-k2-thinking` / `kimi-k2-thinking-…`** → **`1.0`**；其它 **`kimi-k2` / `kimi-k2-…`**（如 **`kimi-k2-0905-preview`**）→ **`0.6`**。**`moonshot-v1-*`** 等其它 Kimi 模型仍使用配置中的 **`temperature`**；若遇类似报错请查阅当前模型说明。

配置示例：

```toml
[agent]
api_base = "https://api.moonshot.cn/v1"
model = "kimi-k2.5"
llm_http_auth_mode = "bearer"
# llm_kimi_thinking_disabled = true   # 可选：关闭 k2.5 默认思考
```

## 火山引擎方舟（OpenAI 兼容，含 Coding Plan）

## 终答规划（`final_plan_requirement`）

控制模型以**非 tool_calls** 结束一轮时，是否必须嵌入可解析的 `agent_reply_plan` JSON（详见 **`docs/开发文档.md`**）。

- **`workflow_reflection`**（默认）：仅在工作流反思后要求规划。
- **`never`**：关闭该校验。
- **`always`**（实验性）：每次终答都校验，**调用次数与费用明显更高**；适合强合规或调试。

若存在 `workflow_validate_only` 结果，服务端还会按 `spec.layer_count` 约束规划步骤条数。若规划步骤填写了可选字段 `workflow_node_id`，其值须属于该次（或最近一次）`workflow_execute` 工具结果中 `nodes[].id`。

**严格节点覆盖（`final_plan_require_strict_workflow_node_coverage`，默认 `false`，环境变量 `CM_FINAL_PLAN_REQUIRE_STRICT_WORKFLOW_NODE_COVERAGE`）**：为 `true` 时，若**任一步**填写了 `workflow_node_id`，则 `steps` 中出现的 `workflow_node_id` 须覆盖该次工具结果中的**全部** `nodes[].id`（每 id 至少一步）。未填任何 `workflow_node_id` 时不额外强制。

**终答规划侧向 LLM（默认关闭）**：**`final_plan_semantic_check_enabled`**（`CM_FINAL_PLAN_SEMANTIC_CHECK_ENABLED`，默认 `false`）在 **`final_plan_requirement = workflow_reflection`** 且本轮已要求终答含规划时，静态规则通过后若可自历史构造工具摘要，则再发**一次**无工具短请求，请模型判断规划与最近工具结果是否明显矛盾。侧向模型**默认只输出 JSON**：`{"consistent":true}` 或 `{"consistent":false,"violation_codes":["…"],"rationale":"…"}`。**`final_plan_semantic_check_accept_legacy_text`**（`CM_FINAL_PLAN_SEMANTIC_CHECK_ACCEPT_LEGACY_TEXT`，默认 `false`）：为 `true` 时额外接受旧式单行 `CONSISTENT` / `INCONSISTENT`（并在侧向 system 中提示该兼容路径）；默认关闭后无法解析的纯文本答复按 fail-open 视为一致。判定不一致时追加重写 user：正文含 **`crabmate_plan_semantic_feedback` v1** 的 `json` 围栏（`violation_codes`、`rationale` 可选），再接规划 JSON 重写说明（计入 `plan_rewrite_max_attempts`）。**`final_plan_semantic_check_max_non_readonly_tools`**（`CM_FINAL_PLAN_SEMANTIC_CHECK_MAX_NON_READONLY_TOOLS`，默认 `0`，合法 0–32）：摘要中额外收录的非只读工具条数上限；`0` 时仍收录内置高风险名（如 `run_command`、`workflow_execute` 等）与只读工具。**`final_plan_semantic_check_max_tokens`**（`CM_FINAL_PLAN_SEMANTIC_CHECK_MAX_TOKENS`，默认 `256`，合法 32–1024）：侧向请求的 `max_tokens`。API 失败或无法解析模型答复时**视为一致**（fail-open），避免阻断主循环。

## 规划重写（`plan_rewrite_max_attempts`）

规划不合格时追加「请重写」的上限；超过后流式前端可能收到 `code: plan_rewrite_exhausted`（可选同级 `reason_code` 子码，见 `docs/SSE协议.md`）。重写 user 仅含**短**必填说明与最短 JSON 示例；完整 schema 细则留在校验器侧，失败时以**校验反馈**错误码（及工作流「补充」段）回灌，避免整份规则塞进提示。

## SyncDefault 工具 Docker 沙盒（`sync_default_tool_sandbox_mode`）

### 模式与覆盖范围

- **`none`（默认）**：与历史一致，在 Agent 进程内 `spawn_blocking` 执行 `HandlerId::SyncDefault` 工具；**`run_command` 等**也在宿主执行。
- **`docker`**：**SyncDefault** 以及 **`run_command` / `run_executable` / `get_weather` / `web_search` / `http_fetch` / `http_request`** 在宿主完成白名单与审批（若有）后，每次调用经 **[bollard](https://docs.rs/bollard)** 走 **Docker Engine HTTP API** 创建并运行一次性容器（等价于 `docker run --rm -i`）：挂载当前工作区到容器内 **`/workspace`**（读写），只读挂载**当前正在运行的宿主 `crabmate` 可执行文件**到 **`/crabmate`**，在容器内执行 **`crabmate tool-runner-internal`**（由服务端生成临时 JSON 配置并只读挂入容器）。**Linux/macOS** 默认连接本地 Unix 套接字（与 `docker` CLI 相同）；**`DOCKER_HOST`** 在部分环境下亦可由 bollard 解析。
- **不进入沙盒**：**`workflow_execute`**、**MCP 代理工具**（`mcp__*`）仍只在宿主执行。

**bollard 编译特性（维护者）**：根目录 **`Cargo.toml`** 对 **bollard** 使用 **`default-features = false`**，仅启用 **`http`**、**`pipe`**（本地 **`unix://`**、Windows named pipe、明文 **`tcp://`** / **`http://`** 的 **`DOCKER_HOST`**，可减小依赖与二进制体积）。若 **`DOCKER_HOST` 为 `https://`** 或设置 **`DOCKER_TLS_VERIFY`**，须在 **`bollard`** 的 **`features`** 中**追加 `ssl`** 并重新编译（会链接 **rustls** 等）。

### 使用前准备

1. **Docker 守护进程可用**：本机能 `docker ps` 或等价 API 访问（与 CLI 同源套接字或 `DOCKER_HOST`）。
2. **架构一致**：宿主 **`crabmate` 二进制**与容器 **CPU 架构**须一致（例如宿主为 `linux/amd64` 则镜像也应为 `amd64`）。实现上**不会**在镜像内自带 crabmate，而是**挂载宿主二进制**；若你改为在镜像内安装 crabmate，则须自行保证版本与调用方式一致（非默认路径，需改镜像/入口，本仓库不维护该方案）。
3. **镜像职责**：镜像提供 **OS + 工具依赖**（`git`、`rg`、`cargo`、`python3`、`npm`、`bc`、`clang-format` 等——按你在工作区里**实际会调用的内置工具**安装；仓库**不提供**固定发布的「官方工具镜像」，`config/sandbox.toml` 中的 `your-registry/crabmate-tools:latest` 仅为占位。

### 镜像与最小示例

- **`sync_default_tool_sandbox_docker_image`**：`docker` 模式**必填**（`finalize` 时非空校验）。任选满足依赖的镜像名（自建或私有 registry 均可）。
- 最小思路：以 **`debian:bookworm-slim`**（或 **`ubuntu:22.04`** 等）为基础，`apt-get install` 你需要的 CLI；Rust 项目可再装 **`build-essential`**、**`pkg-config`**、**`libssl-dev`** 等。示例 Dockerfile（按需增删包）：

```dockerfile
FROM debian:bookworm-slim
RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates git ripgrep curl \
  && rm -rf /var/lib/apt/lists/*
# 若需 cargo / node / bc 等，继续 apt 或复制多阶段构建产物
```

构建并推送后，在配置中填写例如 `sync_default_tool_sandbox_docker_image = "your-registry/crabmate-tools:dev"`。

### 启用步骤（配置）

在 **`config.toml`** 的 **`[agent]`** 段（或环境变量）中设置，例如：

```toml
[agent]
sync_default_tool_sandbox_mode = "docker"
sync_default_tool_sandbox_docker_image = "your-registry/crabmate-tools:dev"
# 需要天气 / 联网搜索 / HTTP 工具出网时改为 bridge（或你环境可用的网络名）
# sync_default_tool_sandbox_docker_network = "bridge"
# sync_default_tool_sandbox_docker_timeout_secs = 600
# sync_default_tool_sandbox_docker_user = "current"   # Unix 默认等效：当前 euid:egid
```

或使用环境变量（覆盖 TOML）：`CM_SYNC_DEFAULT_TOOL_SANDBOX_MODE=docker`、`CM_SYNC_DEFAULT_TOOL_SANDBOX_DOCKER_IMAGE=...` 等。

### 网络

- **`sync_default_tool_sandbox_docker_network` 为空**：容器使用 **`network_mode: none`**，**无出网**；适合仅本地读写、`read_file`、`run_command` 白名单内离线命令等。
- **非空**（如 **`bridge`**）：容器加入该 Docker 网络，**`get_weather` / `web_search` / `http_fetch` / `http_request`** 等才可访问外网；请按环境选择，避免在不可信工作区与宽松网络组合下放大风险。

### 超时与用户

- **`sync_default_tool_sandbox_docker_timeout_secs`**：单次容器生命周期等待上限（秒，默认 600），超时后 **force remove** 容器。
- **`sync_default_tool_sandbox_docker_user`**：写入 Docker **`Config.user`**（等价 `docker run --user`）。**默认**（配置键省略或空、或 **`current` / `host`**）：在 **Unix** 上使用**当前进程有效** **`uid:gid`**（`geteuid` / `getegid`），减轻 bind mount 工作区产生 root 拥有文件的常见问题；**非 Unix** 上省略 `user`（与 `image` 相同）。**`image` 或 `default`**：不设置，沿用镜像 **`USER`**（常为 root）。其它值：原样传给 Docker（如 `1000:1000`、`myuser` 等，须与镜像内账户/权限一致）。

### 安全与运维提示

- **临时配置 JSON**：每次工具调用会在宿主 **`TMPDIR`** 写入 runner 配置（Unix 尝试 **`0600`**），其中可能含 **`web_search_api_key`** 等；仅在**可信主机**上使用，并注意磁盘与备份策略。
- **沙盒边界**：宿主仍负责 **命令白名单、HTTP 前缀、Web/CLI 审批**；Docker 隔离的是**执行环境**，不替代策略配置。
- **性能**：每次工具调用起停容器，延迟与 Docker 开销高于 `none` 模式。

环境变量：`CM_SYNC_DEFAULT_TOOL_SANDBOX_MODE`、`CM_SYNC_DEFAULT_TOOL_SANDBOX_DOCKER_IMAGE`、`CM_SYNC_DEFAULT_TOOL_SANDBOX_DOCKER_NETWORK`、`CM_SYNC_DEFAULT_TOOL_SANDBOX_DOCKER_TIMEOUT_SECS`、`CM_SYNC_DEFAULT_TOOL_SANDBOX_DOCKER_USER`。

## 系统提示词

- **默认**：嵌入的 **`config/default_config.toml`** 使用 **`system_prompt_file = "config/prompts/base_system_prompt.md"`**（**领域无关**的通用 L0；运行时读盘，**修改该 Markdown 无需重新编译**）。**`finalize`** 在 **`coding_workbench_enabled = true`**（默认）时另叠加 **`coding_workbench_increment_file`**（默认 **`config/prompts/coding_workbench_increment.md`**；编程 / Git / 开发工具）。全局关闭 L0b 或换路径：主配置 **`[agent]`** 中 **`coding_workbench_enabled`** / **`coding_workbench_increment_file`**，或环境变量 **`CM_CODING_WORKBENCH_ENABLED`** / **`CM_CODING_WORKBENCH_INCREMENT_FILE`**（读盘失败时回退嵌入默认正文）。各角色可在 **`agent_roles`** 行设 **`prepend_coding_workbench = false`**（默认 true；仍受全局开关约束）以跳过编程层——仓库默认对 companion / philosopher / literary 关闭。
- **相对路径解析顺序**：进程**当前工作目录** → 各层**覆盖配置文件所在目录**（后加载的优先，如 `.agent_demo.toml` 先于 `config.toml`）→ **`run_command_working_dir`**（已规范化的工作区根）。**绝对路径**仅尝试该路径。
- **覆盖与优先级**：若某层 TOML **只写**内联 **`system_prompt`**、**不写**该层的 `system_prompt_file`，则会**取消**继承自更早层的 `system_prompt_file`，改为使用内联。环境变量阶段：**`CM_SYSTEM_PROMPT`** 会清除已合并的 `system_prompt_file`；随后若存在 **`CM_SYSTEM_PROMPT_FILE`** 则再设为文件路径（两者同时设置时以文件为准）。
- **finalize 阶段**：若仍存在 `system_prompt_file` 则读文件；否则使用非空内联；二者皆无则报错。

仓库内默认正文含**指令优先级**（安全 → 用户当轮明确指令 → 可核对事实 → 本提示与角色 → Cursor 式规则）、**非代码问题勿强行使用开发工具**、**用户未授权则默认不擅自改代码**、工具与任务拆分等约定（例如**同一工作区路径在未被修改前不要重复 `read_file`**），并约定用户以中文为主时助手**解释性文字用简体中文、减少中英夹杂**（代码与专有名词等除外）。**沟通规范**中含**问题类型对齐**（如「哪里/对比/排序」类先给简短清单再展开）、**收窄范围时须标明**、**元对话须复述用户原话**（勿改写成自拟技术标题）、**工作区图片用 `![说明](相对路径)` 内嵌**（勿让用户拷到 `CM_WEB_STATIC_DIR`）等。若规则合并段出现**截断提示**，不得假定未见条文。完全自定义时可改 **`config/prompts/base_system_prompt.md`** 或换用自有路径；各角色 **`config/prompts/*_system_prompt.md`** 仅需写角色增量。

嵌入默认 **`config/default_config.toml`** 中 **`thinking_avoid_echo_system_prompt = true`** 且 **`thinking_avoid_echo_appendix_file = "config/prompts/thinking_avoid_echo_appendix.md"`**（可用 **`thinking_avoid_echo_appendix`** 内联或 **`CM_THINKING_AVOID_ECHO_APPENDIX*`** 覆盖）；与上文「思维链中减少复述系统提示」一致。

## 会话工作模式（session_mode：Ask / Plan / Act）

与 **`agent_role`（人格）正交**：决定本会话（或本轮）能否写盘 / 跑构建，以及首条 `system` 末尾的模式附录（`config/prompts/mode_{ask,plan,act}.md`）。

| 模式 | 工具 | 说明 |
|------|------|------|
| **ask** | 等价 `ReviewReadonly` | 只读解释 / 问答 |
| **plan** | 同 ask | 只读调研与出方案 |
| **act** | 全量 ∩ 角色 `allowed_tools` | 默认可执行 |

- **默认**：`[agent] default_session_mode = "act"`；环境变量 **`CM_DEFAULT_SESSION_MODE`**。
- **优先级**：本轮请求 JSON **`session_mode`** → 会话持久化 **`active_session_mode`** → 命名角色 **`default_session_mode`**（如 companion/philosopher/literary 默认 **`ask`**）→ 全局配置默认。
- **Web**：`POST /chat*` 可选 **`session_mode`**。底栏 **Ask / Plan / Act** 三段切换；偏好 **`prefs.session_mode`** 记忆上次选择；`GET /status` 暴露 **`default_session_mode`** 与 **`agent_role_default_session_modes`**；`GET /conversation/messages` 返回 **`active_session_mode`**。Ask/Plan 在 `run_dispatch` 挂只读约束。回合成功落盘时写入/保留 **`active_session_mode`**。
- **与意图分类**：L2 与意图门控配置键已拆除（退役 **R4**）；能力边界靠 Ask/Plan/Act；Act 下另有句关键词只读启发式。
- **REPL / TUI**：**`/mode`** 查看；**`/mode ask|plan|act`** 切换并刷新首条 system 附录（**不清空**对话）；无首条 system 时仍切换模式并提示附录将在下轮刷新。
- **角色默认**：在 **`[[agent_roles]]`** / **`agent_roles.toml`** 行可写 **`default_session_mode`**（`ask`/`plan`/`act`）。

## 多角色（agent_roles）

在全局 **`system_prompt`**（通用 L0，默认 **`config/prompts/base_system_prompt.md`**）之外，可为**命名 id** 配置不同的首条 `system` 正文。每条角色的 **`system_prompt_file`** 仅需写**增量**；**`finalize`** 会先叠加通用 L0，再按全局 **`coding_workbench_enabled`** 与角色 **`prepend_coding_workbench`**（默认 true）决定是否叠加 **L0b 编程工作台层**，再经 **`cursor_rules_*`** 与 **`skills_*`** 合并（L2 仅注入技能索引，技能正文走按轮 L5 动态注入）。

- **定义方式（二选一或混用，后加载覆盖同 id 字段）**  
  1. 主配置文件中的 **`[[agent_roles]]`** 表数组：每行含 **`id`**，以及 **`system_prompt`** 和/或 **`system_prompt_file`**（其一即可；`system_prompt` 为空字符串表示**沿用**全局合并后的 `system_prompt`）。可选 **`prepend_coding_workbench`**（默认 true）：为 false 时该角色不叠加 L0b（仍受全局 **`coding_workbench_enabled`** 约束）。  
  2. 仓库根 **`config/agent_roles.toml`**（未使用 **`--config`** 时）；若使用 **`crabmate --config path/to/foo.toml`**，则读取 **`path/to/agent_roles.toml`**（与主配置**同目录**）。文件形态为 **`[agent_roles]`** + **`default_role`** + **`[agent_roles.roles.<id>]`** 子表（见 `config/agent_roles.toml` 注释示例）。
- **默认角色**：`[agent]` 中 **`default_agent_role`**，或 `agent_roles.toml` 的 **`[agent_roles] default_role`**，或环境变量 **`CM_DEFAULT_CM_ROLE`**。须指向已定义的角色 id；未配置默认时，未显式选角则使用全局 **`system_prompt`**。
- **可选 `allowed_tools`（多角色工作台）**：在 **`[[agent_roles]]`** 行或 **`[agent_roles.roles.<id>]`** 下可写字符串数组 **`allowed_tools`**。非空时：本角色**仅允许**列表中的内置工具名；列表中含字面量 **`mcp`** 时允许所有 **`mcp__*`** MCP 代理工具，亦可写完整 **`mcp__{slug}__{remote}`** 名精确放行。省略或空数组表示**不限制**（与历史行为一致）。工具白名单按 **请求 `agent_role` → 会话持久化 `active_agent_role` → `default_agent_role_id`** 解析命名 id，与首条 `system` 所用角色对齐。
- **Web**：`POST /chat`、`POST /chat/stream` 可选 JSON 字段 **`agent_role`**（与 `conversation_id` 同类字符集，最长 64）。**新会话**（服务端尚无该 `conversation_id` 历史）：与历史相同，用于首轮 `system`。**已有会话**：若与 SQLite/内存中持久化的 **`active_agent_role`** 不同，则**仅刷新首条 `system`** 并更新持久化角色，**保留**后续对话；省略 `agent_role` 则沿用上次持久化角色。启用 **`allowed_tools`** 时，每轮按上条规则裁剪送进模型的工具列表并在执行层拒绝越权调用。
- **CLI**：全局 **`--agent-role`** 已随同进程 **`chat`/`repl` 入口移除**（D2.1）。角色请用 Web / API 请求体 **`agent_role`**，或 Client **`crabmate-tui`**；**`allowed_tools`** 仍按请求/会话中的角色 id（及配置默认角色）裁剪。
- **REPL（历史）**：同进程 **`/agent`** 斜杠入口已移除；Web composer 仍有 **`/agent`** 等控制斜杠子集。
- **热重载**：**`POST /config/reload`** 会重载角色表（与 `system_prompt` 一致）。
- **`GET /status`**：返回 **`agent_role_ids`**（升序）、**`default_agent_role_id`**，供前端展示角色下拉等。

## Cursor-like 规则注入

`cursor_rules_enabled` 为真（**默认 true**）时读取 `cursor_rules_dir` 下 `*.mdc`（可附加 `AGENTS.md`），拼到系统提示词末尾，长度受 `cursor_rules_max_chars` 限制；目录不存在或无可读规则文件时不追加、与关闭效果相同。

## 上下文窗口

请求前会按最终请求形状估算输入 Token：供应商形状的 system/messages、实际下发的 tools JSON、图片附件固定保守预算及封装开销均计入；从 `llm_context_tokens` 扣除 `max_tokens` 与安全余量后，默认在 **85%** 触发并压缩到 **70%**。历史删除以完整 `user + assistant/tool 链` 为单位，至少保留最近两个交互组；`max_message_history` 仅作高位条数兜底。`llm_context_tokens = 0` 时回退 `context_char_budget`。其中 **`tool_message_max_chars`**（`CM_TOOL_MESSAGE_MAX_CHARS`）：单条 `role: tool` 在**发往模型前**若超长则先压缩；启用 **`tool_result_envelope_v1`** 时对 `crabmate_tool.output` 采用**首尾采样**并附带 `output_truncated` 等字段（见 **`docs/开发文档.md`**）。详见 `config/tools.toml`。

Token 预算超过触发值时可强制尝试 LLM 摘要；显式设置 **`context_summary_trigger_chars > 0`** 仍可额外按字符提前触发。摘要尾部会对齐完整交互组边界。提示词默认来自 **`context_summary_system_file`** / **`context_summary_user_file`**（仓库内 **`config/prompts/context_summary_system.md`**、**`context_summary_user.md`**，可直接改 Markdown；读盘失败或空文件回退编译嵌入）。user 模板占位符：**`{max_tokens}`**（或别名 **`{max_chars}`**，同填 `context_summary_max_tokens`）、**`{transcript}`**（缺失时运行时告警并追加对话）。环境变量见上表 **`CM_CONTEXT_SUMMARY_*_FILE`**。

## `serve` 定时对话（`[[scheduled_agent_task]]`）

在**用户** `config.toml` / `.agent_demo.toml`（或 **`--config`** 指向的文件）**顶层**增加表数组项（与 **`[[agent_roles]]`** 并列），由进程内 **`tokio-cron-scheduler`** 按 **UTC** 触发，语义对齐 **`POST /chat` JSON**（走同一 **`chat` 队列**与 **`run_agent_turn`**）。

- **`id`**（`string`，必填）：任务标识；须全局唯一。
- **`schedule`**（`string`，必填）：**秒级** cron **六段**，与库内 **croner** 一致：`秒 分 时 日 月 星期`（UTC）。示例：每天 UTC `09:00` → `0 0 9 * * *`。
- **`message`**（`string`，必填）：注入的用户消息正文（与 HTTP **`message`** 相同；支持 `@` 引用须已设置 Web 工作区）。
- **`enabled`**（`bool`，默认 **`true`**）：为 **`false`** 时跳过该条。
- **`conversation_id`**（`string`，可选）：固定写入的会话 id（字符规则与 Web **`conversation_id`** 一致）。与 **`new_conversation`** 二选一组合：  
  - 固定会话：提供 **`conversation_id`**，且 **`new_conversation = false`**（默认）；  
  - 每次新建会话：设 **`new_conversation = true`**，且**不要**写 **`conversation_id`**。
- **`agent_role`**（`string`，可选）：须存在于角色表（与 Web **`agent_role`** 相同）。

**说明**：仅 **`serve`** 模式注册调度器；**多副本**部署时每个进程各自触发，需在外部协调或单实例运行。完整变更 cron 表达式后请**重启 `serve`**（见上文「配置热重载」）。

## Web 对话队列（`chat_queue_*`）

`/chat` 与 `/chat/stream` 经有界队列调度；满时 **503**、`QUEUE_FULL`。`/status` 返回队列与 **`per_active_jobs`** 等字段；**`per_active_jobs[*]`** 含 **`plan_rewrite_attempts`**（终答重写）等，见 **`docs/调试指南.md`**（HTTP 探针）与 **`GET /openapi.json`**。

- **可选 `client_llm` 对象**（仅作用于**本次入队**的对话任务，**不写**服务端配置）：可含 **`api_base`**、**`model`**、**`api_key`**（均可选；trim 后为空表示该字段不覆盖）、**`llm_context_tokens`**（可选正整数）、**`llm_thinking_mode`**（可选 **`server`** / **`on`** / **`off`**：覆盖本回合供应商 **`thinking`** 相关开关——**`on`** 对应开启智谱类深度思考并不要求 Kimi k2.5 显式关闭；**`off`** 对应关闭智谱 thinking 并对 Kimi k2.5 发送 **`thinking: disabled`**；**`server`** 或省略表示不覆盖，仍按服务端 `AgentConfig`）。若携带非空 **`api_key`**，该任务对 LLM 的 HTTP 请求按 **Bearer** 使用该密钥（即使进程配置为 **`llm_http_auth_mode = none`**）。长度上限：`api_base` 2048 字符、`model` 512、`api_key` 16384；不合法时 **400**、错误码 **`INVALID_CLIENT_LLM`**。**安全提示**：密钥会出现在发往 CrabMate 后端的 **JSON 请求体** 中，请仅在 **HTTPS** 等可信链路使用；官方 Client 在本机存放模型密钥并随请求发送（服务端不再提供模型密钥钥匙串槽），公共电脑勿用。
- **可选 `client_sse_protocol`**（`u8`）：客户端声明其实现的 SSE 控制面版本，与 workspace crate **`crabmate-sse-protocol`** 的 **`SSE_PROTOCOL_VERSION`** 对齐。官方 Web 随 **`POST /chat`** / **`POST /chat/stream`** 发送。**大于**服务端版本时 **400**（**`SSE_CLIENT_TOO_NEW`**）；**`0`** 为 **400**（**`INVALID_SSE_CLIENT_PROTOCOL`**）；**正整数且低于**服务端版本时 **400**（**`SSE_PROTOCOL_MISMATCH`**）。省略则不校验。首帧 **`sse_capabilities.supported_sse_v`** 与协商语义见 **`docs/SSE协议.md`**。

## 只读工具并行（`parallel_readonly_tools_max`）

限制同轮多只读工具进入 blocking 池的并发数： eligible 批含内建只读 **`SyncDefault`**、**`http_fetch`**（GET/HEAD）、**`get_weather`**、**`web_search`**（不含 **`http_request`**、**`run_command`**、MCP 等）。构建锁类（如 **`cargo_*`**、**`npm_*`**）整批降级为串行。
