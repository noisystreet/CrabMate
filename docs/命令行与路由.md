# 命令行与子命令

查看帮助：`crabmate --help`、`crabmate help`、`crabmate help <子命令>`（与 `--help` 等价）。根级 **after_help** 交叉引用 **`docs/命令行契约.md`**、**`docs/SSE协议.md`**。**全局选项**写在子命令**之前**：`--config`、`--workspace`、`--no-tools`、`--llm-context-tokens`、`--log`。须给出显式子命令（如 `serve`）；裸 `cargo run` 不再默认进入对话。

**官方终端**：Client 仓 **`crabmate-tui`**（HTTP/SSE 连接本仓 **`serve`**；模型密钥存 Client 本机）。本仓同进程 **`chat` / `repl` / `tui` 入口与实现已硬删**（D2.2，见 [`design/client_shell_split.md`](design/client_shell_split.md) §2.5）。

**脚本契约**（退出码、`tool-replay` 等；旧 `chat --output json` 形状仅作历史说明）：[`命令行契约.md`](命令行契约.md)。

## 手册页（troff / `man`）

- **源码树**：预生成的 **`man/crabmate.1`** 与 **`man/crabmatectl.1`**（troff），与当前 `clap` 定义一致；**Debian `.deb`** 会安装到 **`/usr/share/man/man1/`**（见根目录 `Cargo.toml` 的 `[package.metadata.deb] assets`）。
- **再生成**（**增删子命令或顶层选项**之后）：`cargo run --features gen-man --bin crabmate-gen-man`，然后提交更新后的 `man/*.1`。
- **粒度（重要）**：这两页是**单页**——只含**顶层选项**与**子命令名**（每个子命令一行说明），**不含各子命令自己的 flags**。查某个子命令的 flag 用 `crabmatectl up --help`，`-h` 永远比 man 新。因此**改子命令 flag 不需要重生成 man**（重生成也不会产生任何 diff）。
- **`cargo install crabmate`**（crates.io **稳定版 `0.7.0`**，默认 **`server`**；git tag **`v0.7.0`** 与此包一致）：默认**不会**把 man 装到 `MANPATH`；可将 `man/*.1` 拷到本机 `.../share/man/man1/` 后执行 `mandb`（视发行版而定），或优先使用 **`cargo deb`** / 发行版打包。

## 子命令一览

| 子命令 | 说明 |
|--------|------|
| `serve [PORT]` | HTTP API（永远纯 API，不托管 SPA，端口 **8080**）；**`bearer` 时可在未设 `API_KEY` 的情况下启动**，对话前须在侧栏「设置」填写**模型**密钥（`client_llm`，权威在 Client 本机）。HTTP 层：配置非空 **`web_api_bearer_token`** / **`CM_WEB_API_BEARER_TOKEN`** 时挂载 Bearer（`Authorization: Bearer` 或 `X-API-Key`）；浏览器另须在 **设置 →「Web API 共享密钥」** 保存同一串（**不是**模型 API_KEY）。嵌入默认 **`web_api_require_bearer=false`**（允许无密钥启动）；生产或对外建议 **`web_api_require_bearer=true`** 强制启动前须配密钥。**本机临时跳过鉴权**：`unset` 密钥后听 `127.0.0.1`，或清密钥后设 **`CM_ALLOW_INSECURE_NO_AUTH_FOR_NON_LOOPBACK=true`** 再听 `0.0.0.0`（见 **`docs/配置说明.md`**）。**桌面 Tauri** 为薄客户端，须**自行**启动本命令后再用壳连接（见 Client [`desktop-tauri/DEVELOPMENT.md`](https://github.com/noisystreet/crabmate-client/blob/main/desktop-tauri/DEVELOPMENT.md)）。**Ctrl+C** 触发优雅关闭（排空在途 HTTP / 队列）；关闭过程中再次 **Ctrl+C** 立即退出（退出码 130）。 |
| `ctl` | 本地多实例 `serve` 进程管理（**仅 Unix**；**不要**求 `API_KEY`）：`up` / `down` / `restart` / `run` / `ls` / `status` / `logs` / `prune`。每个实例独立 cwd、会话库与端口（默认池 **8080-8089**），状态在 **`$XDG_STATE_HOME/crabmate/instances/`**。子实例配置用 **`--serve-config`**（与全局 **`--config`** 分离）。详见下文「本地多实例（`ctl`）」。 |
| `bench` | 批量测评：`--benchmark`、`--batch` 等。 |
| `config` | 配置与 `API_KEY` 状态自检（不接受参数）。 |
| `doctor` | 本地诊断（**不需要** `API_KEY`）。 |
| `web-bearer` | **`status` / `set` / `clear`**：读写系统钥匙串中的 **Web API 共享密钥**（与 Web **`/user-data/secrets/web-api-bearer`** 同源；**不要**求 `API_KEY`）。**`set`** 推荐 **`set --stdin`**（管道）、**`set --from-env`**（读 **`CM_WEB_API_BEARER_TOKEN`**）或无参数时交互**隐藏输入**；位置参数 `TOKEN` 会进 shell 历史/`ps`，仅作兼容。**`serve`** 在 TOML / **`CM_WEB_API_BEARER_TOKEN`** 皆空时从此处加载；从「无密钥」变为「有密钥」（或反向）须**重启 `serve`** 才会挂载/拆除鉴权中间件。浏览器仍须在 **设置 → Web API 共享密钥** 保存同一串。 |
| `models` | `GET …/models`（需 `API_KEY`）。 |
| `probe` | 探测 models 端点（需 `API_KEY`）。 |
| `save-session` | 从会话文件导出 JSON/Markdown 到工作区 **`.crabmate/exports/`**（与 Web 导出同形；**不要**求 `API_KEY`）。`--format json|markdown|both`（默认 `both`），**`--projection raw|display`**（默认 **`raw`**；`display` 不可直接 **`tool-replay`**），`--session-file` 可选。兼容别名 **`export-session`**。 |
| `tool-replay` | 从会话 JSON 提取**工具调用时间线**为 fixture，或按 fixture **重放工具**（与对话相同走 `run_tool`，**不调用大模型**；**不要**求 `API_KEY`）。见下文「工具重放 fixture」。 |
| `sse-replay` | 从 **`sse-replay-events.jsonl`** 录制文件回放 AG-UI 事件并投影为 Web 块布局行（**不要**求 `API_KEY`）。**`--format`** 取 `rows`（默认，投影行列表）或 `canonical`（canonical Turn 状态）；**`--job_id N`** 仅输出指定 job（`0` = 全部）。 |
| `mcp list` | 只读列出**本进程**内与 **user-data** `mcp_servers.json` 中已启用服务器对应的已缓存会话及合并后的 OpenAI 工具名（`mcp__{slug}__…`；**不要**求 `API_KEY`）。配置真源为 **`~/.local/share/crabmate/mcp_servers.json`**（Web **设置 → MCP**）；支持 **stdio（`command`）** 与 **远程 Streamable HTTP（`url`）**。若尚无缓存，可先 **`mcp list --probe`** 按配置尝试连接（stdio 启动 `command` 子进程；远程则 HTTP 握手）。 |
| `plugin init` | 生成工作区 **`plugins/*.json`** 动态工具模板（名称需 `dyn__` 前缀）；输出文件路径默认 `plugins/<name-without-prefix>.json`。 |
| `plugin list` | 列出动态工具文件、工具名、command 与校验状态（OK/FAIL）；`--json` 输出结构化结果，`--jsonl` 按行输出便于管道处理。 |
| `plugin validate` | 校验动态工具定义（默认扫描 `plugins/*.json`，或 `--file` 指定单文件）；会检查 JSON 结构与 `command` 是否在 `allowed_commands` 白名单；`--json` 输出结构化结果，`--jsonl` 按行输出便于管道处理。 |
| `workflow compile` | 将 **`workflow_spec` v2** YAML（或含 `` ```crabmate-workflow `` 的 `.md`）编译为 **`workflow_execute`** 用的 `{"workflow":{…,"nodes":[…]}}` JSON 并打印到 stdout（**不要**求 `API_KEY`）。**用户向教程**：**`docs/工作流编写教程.md`**；示例目录 **`examples/workflows/`**。 |
| `workflow validate` | 同上编译后做作者层 JSON Schema + DAG 拓扑与工具参数校验；默认人读摘要，`--json` 输出 `author_spec_version`、`author_mode` 与层表。 |
| `workflow run` | 编译并**执行**工作区内工作流文件（等同 Agent `workflow_execute` + **`workflow_file`**；**不要**求 `API_KEY`）。例：`cargo run -- workflow run examples/workflows/ci.yaml`。 |
| `mcp serve` | 在 **stdin/stdout**（默认）或 **TCP 端口**（`--port N`）上运行 **MCP server**，将 CrabMate **内置工具**暴露给外部客户端（`tools/list` / `tools/call` → **`tools::run_tool`**；**不要**求 `API_KEY`）。工作目录与全局 **`--workspace`** / 配置 **`run_command_working_dir`** 一致。协议 JSON-RPC 走 **stdout**（stdio 模式）或 TCP 流；启动提示与日志用 **stderr**，避免污染 MCP 流。**`--no-tools`**：不向客户端列出工具（调用未知名仍走 `run_tool` 并得「未知工具」）。**`--port`**：设置 TCP 端口号（默认 `0` 表示 stdio 模式），监听 `127.0.0.1` 允许多个连接。**无传输层鉴权**：仅用于本机或 SSH 隧道可信网络集成；能力面与 `run_command` 白名单、工作区路径策略及（若启用）**`tool_call_explain_enabled`** 一致。TCP 模式可用于远程开发：通过 SSH 隧道转发端口，本地 CrabMate 以 MCP 客户端连接远程服务器。 |
| `e2e` | 真实 LLM 端到端测试：运行预设场景并生成结构化报告（需 `API_KEY`）。**`--mode real|record|replay`**（默认 `real`）、**`--output-dir DIR`**、**`--recordings-dir DIR`**。详见 [`docs/真实LLM-E2E.md`](真实LLM-E2E.md)。 |

## 日志级别

未设置 `RUST_LOG` 时：`serve` 默认 **info**；`bench` / `config` / `mcp` / `web-bearer` / `save-session`（及别名 `export-session`）/ `tool-replay` / `plugin` / `workflow` / `doctor` 等其它子命令默认 **warn**。可用 `RUST_LOG` 或 `--log <FILE>`。

## 消息管道调试日志

`RUST_LOG=crabmate=debug` 时每次调用模型前打印 **`message_pipeline session_sync`** 汇总；更细：`RUST_LOG=crabmate::message_pipeline=trace`。累计命中见 **`GET /status`**；实现见 `src/agent/message_pipeline/`。

## 兼容旧用法

**已移除**：未写子命令时的历史平铺 flag（**`--serve`**、**`--dry-run`**、**`--benchmark` / `--batch` / `--resume`** 等）**不再**映射到子命令，请显式写 **`serve` / `config` / `bench`**，否则 clap 报缺子命令。裸 argv / **`--query`** / **`--stdin`** 同样**不再**映射为 `chat` 或默认插入 `repl`。

保留的 argv 归一化只有 **`help` 子命令**：`crabmate help` → 根级 `--help`；`crabmate help <已知子命令>` → 该子命令 `--help`（与 `tests/fixtures/cli/help_normalize.json` 一致）。

## 常用选项

| 选项 | 说明 |
|------|------|
| `--config <path>` | 指定配置文件（建议写在子命令前） |
| `--host <ADDR>` | 随 `serve` |
| `--port 0` | 随 `serve`：由 OS 分配空闲端口；启动日志与 **`--desktop-ready-json`** / **`--web-ready-json`** 中的 **`port`/`url`** 以 **`TcpListener::bind` 后的 `local_addr()`** 为准 |
| `--desktop-ready-json` | 随 `serve`：监听成功后向 **stdout** 额外打印一行 JSON：`{"event":"web_ready","host":"…","port":…,"url":"http://…/","auth_enabled":…,"instance_id":…}`；**`instance_id`** 取自 **`CM_INSTANCE_ID`**（未设置时为 `null`）；**仅**在显式开启时出现；供脚本/工具解析（桌面壳**不再**依赖）。**命名已弃用**；推荐别名 **`--web-ready-json`**（行为相同） |
| `--web-ready-json` | `--desktop-ready-json` 的别名 |
| `--workspace-unset` | 随 `serve`：以**待绑定工作区**启动（初始 `workspace_override` 为 `None`），等 client 通过 `POST /workspace` 绑定；与 `--workspace` 互斥（同时给出直接报错）。仅供 **`crabmatectl`** 起的实例使用。未绑定时的工具面拒绝（`WORKSPACE_NOT_SET`）随 #1183 的后续切片落地 |
| `--yes` | 随 `serve`：跳过命令白名单（`allowed_commands` → `*`），**`run_command` 不再校验命令名**，一律放行。仅限**完全信任或已隔离**（容器/专属主机）的环境；**不**影响工作区外路径审批与参数安全检查 |
| `--workspace <path>` | 覆盖初始工作区 |
| `--no-tools` | 禁用工具 |
| `--llm-context-tokens <N>` | 覆盖 **`[agent] llm_context_tokens`** / **`CM_LLM_CONTEXT_TOKENS`**（模型上下文 token 上限；`0` 表示不覆盖）；影响会话同步裁剪近似字符预算 |
| `--log <FILE>` | 日志文件 + stderr 镜像 |

> **`config`**：不带参数，一次配置检查后退出。裸 **`--dry-run`** 已随平铺 flag 移除，`config --dry-run` 不再被接受。

> **已移除（D2.1）**：全局 **`--agent-role`**、以及仅服务于同进程 **`chat`/`repl`** 的 **`--query` / `--stdin` / `--output` / `--no-stream`** 等。对话请用 Client **`crabmate-tui`** 或 Web；角色用请求体 / Web **`agent_role`**。

## Benchmark（`bench`）

评测能力规划、各 benchmark 对接与测试策略见 **`docs/基准测试规划.md`**（与通用 CLI 说明分离）。

| 选项 | 说明 |
|------|------|
| `--benchmark <TYPE>` | `swe_bench`、`gaia`、`human_eval`、`generic` |
| `--batch <FILE>` | 输入 JSONL（`human_eval` 时每条须含 `humaneval_test`、`entry_point`，见 **`docs/基准测试规划.md`** §5） |
| `--batch-output <FILE>` | 默认 `benchmark_results.jsonl` |
| `--task-timeout <SECS>` | `0` 不限制 |
| `--max-tool-rounds <N>` | `0` **不限制**轮次（**不会**关闭工具）；关工具用全局 **`--no-tools`** |
| `--samples <N>` | 每任务采样次数（pass@k 的 `n`）；默认 `1`。多采样结果用 `humaneval_score_benchmark_results.py --k K` 聚合出 `pass@k` |
| `--resume` | 跳过已有 `instance_id`（多采样时按 `(instance_id, sample_index)` 续跑） |
| `--bench-system-prompt <FILE>` | 覆盖 system |

HumanEval 适配器会在函数桩前附加「只续写函数体、不要追问」指令，并追加 system suffix。官方数据转换与判分（Python 3，**执行模型生成代码**，须自行隔离环境）。**建议**加全局 **`--no-tools`**（`--max-tool-rounds 0` 不够）：

```bash
python3 scripts/humaneval_official_to_crabmate_jsonl.py --input HumanEval.jsonl --output tasks.jsonl
cargo run -- --no-tools bench --benchmark human_eval --batch tasks.jsonl --batch-output results.jsonl
python3 scripts/humaneval_score_benchmark_results.py --tasks tasks.jsonl --results results.jsonl
```

## 示例

```bash
cargo run -- serve
cargo run -- --config /path/to/my.toml serve
RUST_LOG=debug cargo run -- --log /tmp/crabmate.log serve
cargo run -- serve 3000
cargo run -- serve --port 3000               # 与上一行等价
cargo run -- --workspace /path/to/project serve 8080
cargo run -- serve --host 0.0.0.0            # 注意安全与鉴权
cargo run -- serve --host 127.0.0.1 --port 0 --web-ready-json   # 可选：stdout 打印 web_ready（脚本用；亦可用已弃用名 --desktop-ready-json）
cargo run -- --no-tools serve
cargo run -- serve --yes                        # 跳过命令白名单：run_command 一律放行（仅可信/已隔离环境）
cargo run -- bench --benchmark swe_bench --batch tasks.jsonl --batch-output results.jsonl --task-timeout 600
cargo run -- config
cargo run -- doctor
cargo run -- save-session
cargo run -- save-session --format json --workspace /path/to/proj
cargo run -- save-session --format json --projection display
```

**`save-session`**：默认读取 **`<workspace>/.crabmate/tui_session.json`**（`--workspace` 与全局 `--config` 写在子命令前），在 **`<workspace>/.crabmate/exports/`** 下生成带时间戳的 **`chat_export_*.json`** / **`chat_export_*.md`**（schema / Markdown 标题与 Web 共用 **`crabmate-chat-export`**）。JSON 顶层信封（**必填**）：`schema`（`crabmate.chat_session`）、`schema_version`（当前 **`2.0.0`**）、**`projection`**（**`raw`**：完整 OpenAI 形 `Message`，会话落盘 / **`save-session`** 默认；**`display`**：运维展示投影瘦消息，可用 **`--projection display`**，**不可**直接喂 **`tool-replay`**）、`version`、`messages`。**不**再兼容缺信封字段的旧 JSON。Markdown / `display` 投影的**工具段**用信封摘要或截断原文，**不保证**与 Web 工具卡逐字一致（像素级工具卡在 Client `crabmate-tool-card`）。见 `src/cm_chat_export`、`src/cm_runtime/chat_export.rs`、Client `frontend/src/session_export.rs`。每行 stdout 为写出文件的绝对路径，便于脚本捕获。

## 本地多实例（`crabmatectl`）

**仅 Unix**（Linux/macOS）。**独立二进制**，不是 `crabmate` 的子命令——它管理的是别的进程、不是一次 agent 调用，入口分开才能一眼看出用途。纯本地进程管理器：不监听端口、不碰 LLM、不要求 `API_KEY`。

与 `crabmate` 同 crate、同 `server` feature 构建，故两者版本不可能漂移。运行时需要**同目录**下的 `crabmate`（缺失时报 `serve_binary_missing`，可用 `CRABMATECTL_BIN` 指定其它路径）。

```bash
crabmatectl up proj-a --workspace ~/work/proj-a --timeout 20
crabmatectl ls                 # 人读表格；--json 供脚本消费
crabmatectl status proj-a      # 含身份校验、TCP 可达、实际加载的 config
crabmatectl restart proj-a     # 复用原 workspace / 端口 / 配置
crabmatectl logs proj-a -f     # 跟随日志
crabmatectl down proj-a        # 整组 SIGTERM → 宽限 → SIGKILL
crabmatectl down --all
crabmatectl up --all --dry-run # 按声明打印「要起哪些」，不动任何进程
crabmatectl up --all           # 按声明批量起（**只起，不回收**：回收归 supervise）
crabmatectl prune --dry-run    # 只清 stale/stopped/failed 记录，不碰健康实例
crabmatectl supervise --from-config --dry-run   # 打印收敛计划，无副作用
crabmatectl supervise --from-config             # 按 instances.toml 收敛一次
crabmatectl supervise --from-config --watch     # 常驻：声明变化即收敛（Ctrl-C 退出）
crabmatectl supervise --from-config --watch --socket  # 常驻 + 本地控制面（unix socket）
crabmatectl supervise --from-config --watch --restart on-failure  # 常驻 + 崩溃后按退避重启
crabmatectl supervise proj-a --from-config --watch --restart on-failure  # 只守护 proj-a 一个
```

**手册页**：`man crabmate` 与 `man crabmatectl` 各一页（`man/crabmate.1` / `man/crabmatectl.1`），都由 `cargo run --features gen-man --bin crabmate-gen-man` 从**当前构建的同一份 clap 定义**生成、随仓库提交，并被打进 tar 与 .deb。但注意它是**单页**：只含顶层选项与子命令名，`up` 自己的 `--all` 等 flag 不在其中——查 flag 请用 `crabmatectl up --help`。粒度与重生成时机见上文「手册页（troff / `man`）」。

**常驻怎么挂**（两条互不替代的路径）：

| 场景 | 用什么 |
|------|--------|
| 单实例常驻、有 root | `packaging/systemd/crabmate.service`（**system** 级，跑单个 `serve`） |
| 多实例 / 无 root / 容器内 / 临时机器 | `packaging/systemd-user/crabmate-supervise.service`（**user** 级，跑 `supervise --from-config --watch --restart on-failure`，`WantedBy=default.target`） |

user unit 的装法与前置条件写在文件头部注释里，要点两条：`systemctl --user enable --now` 即可，未登录也要常驻再加 `loginctl enable-linger "$USER"`；**`instances.toml`（及被引用的 `profiles.toml`）必须 `0600`**，否则 ctl 按设计拒绝收敛。它刻意**不在** `packaging/systemd/` 下：那个目录被 `Cargo.toml` 的 `systemd-units` 扫成 **system** 级单元，user unit 混进去会被装到 `/etc/systemd/system/`，而它的 `%h` 与 `default.target` 语义只在 user 实例下成立。

**目录布局**（状态目录按 `0700`、状态文件与日志 `0600`）：

| 路径 | 内容 |
|------|------|
| `$XDG_STATE_HOME/crabmate/instances/<name>.json` | 状态记录（缓存，容忍未知/缺失字段） |
| `$XDG_STATE_HOME/crabmate/instances/<name>/` | 该实例的**子进程 cwd**（会话库、上传目录都在其中） |
| `$XDG_STATE_HOME/crabmate/instances/<name>.log` | 子 serve 的 stdout/stderr |
| `$XDG_STATE_HOME/crabmate/instances/.lock` | 状态目录级 `flock`（临界区仅覆盖「选端口 + 预写 starting」） |

**`up --all` 与 `supervise --from-config` 的分工**（两者共用同一份计划，所以「什么算需要起」只有一个定义）：

| | 起缺的 | 停多的 / 停 `enabled = false` 的 | 常驻 |
|---|---|---|---|
| `up --all` | ✅ | ❌ **不回收** | ❌ 跑完就退出 |
| `supervise --from-config` | ✅ | ✅ | 加 `--watch` |
| `supervise <name> --from-config` | ✅（仅该实例） | ❌ **不回收别的** | 加 `--watch` |

想「把声明的都拉起来，但停由我说了算」用 `up --all`；要「声明就是唯一事实」用 `supervise`。`up --all` 拒绝单实例参数（`--serve-config` / `--port` / `--yes`）——它们在声明或 profile 里，静默忽略只会让人以为生效。

**`supervise <name>` 只认声明**：名字必须出现在 `instances.toml` 里，否则报 `not_declared`（退出码 2）。这不是限制，是因为**状态记录只存 `env_keys`、不存 env 值**（刻意的安全边界）——从记录重建启动规格会在重启后静默丢掉手工 `up -e FOO=bar` 的变量，一个「配置悄悄变了」的守护进程比没有更糟。临时实例请写进声明（`enabled = false` 保存着，用时再起）。

**对外 JSON 契约**：`ls --json` / `status --json` 与状态文件 `<name>.json` 的字段集由 `crabmate-client` 直接消费，现由 `fixtures/ctl_contract.json` 双向钉住 —— 增、删、改字段都必须显式改一次 golden。详见 [命令行契约.md](命令行契约.md) → `crabmatectl` 输出与状态文件。

**关键语义**（实现见 `src/cm_ctl/`）：

1. **每实例独立 cwd**：`serve` 的会话库与 `.serve.lock` 按 **cwd** 相对解析，同 cwd 起第二个实例会直接启动失败。这是 `ctl` 存在的首要理由。
2. **环境不继承**：子进程 `env_clear()` 后只注入白名单（`PATH`、`HOME`、`XDG_*`、代理与 `SSL_CERT_*`）。**`API_KEY` / `CM_*` / `*_TOKEN` / `*_SECRET` 一律不透传**，声明这些变量会直接报 `forbidden_env`。`env_keys` 记录实际注入的变量**名**（无值），便于核对。
3. **端口池**：默认 `8080-8089`，取第一个空闲；全占用报 `port_pool_exhausted`（**不随机挑**）。探测与 `bind` 之间的 TOCTOU 由「顺延重试一次」兜底。
4. **就绪判定是 TCP connect**，不是 `GET /health`——后者会跑外部 CLI 探测并可能触发 LLM 端点探测，既慢又受外部依赖影响。`/health` 只用于 `status` 展示。
5. **发信号前必须验身份**：`boot_id` + `pid_start_ticks`（`/proc/<pid>/stat` 第 22 字段）+ `cmdline` token 级校验。PID 复用会指向无关进程，校验不过一律**拒绝**并报 `identity_mismatch`，宁可少杀不可误杀。
6. **`down` 先落 `desired_state = stopped`**：即使随后杀进程失败，`supervise --from-config` 也不会立刻把实例拉起来。
7. **`--config` 与 `--serve-config` 是两回事**：前者是 `ctl` 自己的配置（当前仅用于预检），后者交给子 serve。二者绝不互相继承。`up` / `run` 的 workspace 取自全局 `--workspace`。
8. **workspace 预检**：给了 `--serve-config` 时，用**子实例配置**里的 `workspace_allowed_roots` 预检 workspace —— 越界直接报 `workspace_out_of_roots` 且**绝不自动加白**。**未给时不预检、只打 WARN**：子实例按它自己的 cwd（实例目录）解析配置，ctl 无法可靠推断它会加载哪个文件，猜出来的结论只会误导。`--serve-config` 的相对路径按 **ctl 的 cwd** 绝对化后再交给子实例（子进程 cwd 不同，原样传会解析错位）。
9. **端口占用在 spawn 前就拦**：显式 `--port` 会先检查 `127.0.0.1:PORT` 是否已被监听，占用则报 `port_in_use`（退出码 2），**不进入** readiness 等待。理由不是洁癖：readiness 只问「这个地址能不能连上」，端口被别的实例占着时连到的就是**它**，于是自己的实例被判成 `ready`、`base_url` 指向别人的进程 —— 客户端连过去全落到同一个 serve，两个 lane 共用一份会话库。auto 分配不需要这一查（端口池已跳过占用），它到 `spawn` 之间的 TOCTOU 窗口由 `port_race` 顺延兜住；显式端口若是在检查之后被抢，**不会**擅自换号，只在 readiness 超时后报错。
10. **readiness 超时即失败并回收**：超时后对子实例**进程组**发 `SIGTERM` → 宽限期 → `SIGKILL`，记录落 `failed` + 可读 `last_error`（含 pid 与日志路径）。**不停在 `starting`**：`starting` 不在巡检的失败集合里（`restart::is_failure` 只认 `stopped` / `failed` / `stale`），停在那儿等于让实例既不重试也不回收，`--restart on-failure` 也救不了它。

### 声明式收敛（`supervise --from-config`）

读 **`$XDG_CONFIG_HOME/crabmate/instances.toml`**，把实例收敛到声明：缺的起、`enabled = false` 的停、声明里已删且**由 `crabmatectl` 拉起**的回收。

```toml
[instances.proj-a]
workspace = "~/work/proj-a"          # 必填；支持 ~，绝对化后交给子 serve
profile   = "readonly-audit"         # 可选：引用 profiles.toml 的预设（与 config 互斥）
config    = "/etc/crabmate/a.toml"   # 可选：交给子 serve 的 --config；不能与 profile 同时给
port      = 8080                     # 可选：省略则由端口池分配
enabled   = true                     # 可选，默认 true；false = 保留声明但不运行

[instances.proj-a.env]
GIT_SSH_COMMAND = "ssh -i ~/.ssh/id_proj_a"
```

四条边界，各有测试或实测锚点：

1. **文件权限必须是 `0600`（或更严）**，否则拒绝加载（`instances_file_insecure`）。它等同**进程启动清单**：同机其他用户若能写它，就能借 ctl 起一个指向任意目录的 serve。
2. **未知键一律报错**（`instances_file_invalid`），不静默忽略——`enabledd` 这类拼写错误否则只会表现成「实例莫名不起」。
3. **只回收自己拉起的实例**：状态记录里的 `managed_by` 区分 `cli` / `supervise`。人工 `up` 的实例即使不在声明里也**不动**（删声明 ≠ 杀掉用户手工起的进程）。
4. **不越过用户的 `down`**：`desired_state = stopped` 的实例即使声明 `enabled = true` 也跳过（输出为 `跳过`），需 `restart` 或改声明后重新收敛。

#### Profile：预设菜单（`profiles.toml`）

实例只写 `profile = "<名字>"`，具体能力由**声明方**在 `$XDG_CONFIG_HOME/crabmate/profiles.toml` 预先定义。这样做的原因有两条：跨端（Web / 移动端不知道服务端文件系统，拼不出 `--config` 路径），以及「允许按任意路径加载配置」等于让能力集合无界。

```toml
[profiles.readonly-audit]
config           = "~/.config/crabmate/audit.toml"  # → 子 serve 的 --config
allowed_commands = ["grep", "cat", "ls"]            # → CM_ALLOWED_COMMANDS（整体替换）
permission_level = "read"                            # → CM_PERMISSION_LEVEL
no_tools         = false                             # → 子进程 --no-tools
llm_model        = "deepseek-chat"                   # → CM_LLM_MODEL
llm_api_base     = "https://api.deepseek.com/v1"     # → CM_LLM_API_BASE

[profiles.readonly-audit.env]
GIT_SSH_COMMAND = "ssh -i ~/.ssh/id_audit"
```

合并顺序（后者覆盖前者）：**ctl 默认**（`env_clear` + `PATH` / `HOME` / `XDG_*` 白名单）→ **profile 派生键** → **`profile.env`** → **`instance.env`**。

硬边界：

1. **`profiles.toml` 也必须 `0600`（或更严）**，否则 `profiles_file_insecure`。它决定了子进程能跑哪些命令、拿什么权限等级，威胁与 `instances.toml` 同级。
2. **`workspace` 与 `yes` 永久禁止出现在 profile 里**：workspace 只能由实例提供（并被子实例的 `workspace_allowed_roots` 兜住）；白名单全放行必须是实例级显式决定 —— 含 `allowed_commands = ["*"]` 也会被拒（等价 `--yes`）。
3. **`CM_*` 只放行 4 个键的白名单**（`CM_ALLOWED_COMMANDS` / `CM_PERMISSION_LEVEL` / `CM_LLM_MODEL` / `CM_LLM_API_BASE`）。按前缀放行等于允许注入 `CM_SERVE_DISABLE_INSTANCE_LOCK` 之类，直接打掉实例隔离。
4. **`permission_level` 必须是 `chat` / `read` / `workspace` / `approved` / `unrestricted`**（注意不是 `readonly`）。
5. **改 profile 不热改运行中实例**：收敛计划会给出「重启」并说明 profile 从 X 变为 Y；`status` 同时显示 `profile`（声明）与 `profile_in_use`（实际），二者不一致时会提示要 `restart`。

`--dry-run` 只打印计划、不写任何状态，与 `--watch` 互斥。

**`--watch`** 常驻生效：轮询声明文件（默认 1s，`--interval` 可调；不用 inotify——容器 overlayfs 上不可靠）。指纹是**内容 + 权限位**，所以 `chmod 600` 修好一个 0644 的文件后即使内容一字未改也会重新加载。声明一旦不可用（权限过宽 / 属主不符 / 语法错 / 不存在）就**暂停收敛并告警**，既不退出、也绝不按坏声明起进程；修好后指纹变化，自动恢复。

#### 本地控制面（`supervise --socket`）

`--watch` 解决了「声明变了要收敛」，但没回答「谁来写这份声明」。让客户端（TUI）直接写 `instances.toml` 会与 `--watch` 构成同一文件的两个写入者，还要把 TOML 编辑能力复制进客户端；让客户端执行 `crabmatectl` 又等于让它 spawn 进程。`supervise --socket` 补上这条**本地**写入通道：

```bash
crabmatectl supervise --from-config --watch --socket              # 默认 $XDG_RUNTIME_DIR/crabmate/ctl.sock
crabmatectl supervise --from-config --watch --socket /run/u/c.sock
```

- **协议**：unix socket 上**行分隔 JSON**，一问一答；`op` 取 `add` / `remove` / `list`。
- **ctl 是声明文件与进程的唯一写入者**：socket 线程只把请求投进主循环，由主循环写盘并立刻收敛，所以不存在「socket 与 `--watch` 交错改文件」。
- **鉴权只靠文件权限**：目录 `0700`、socket `0600`，仅同用户可连；**不监听 TCP**，网络不可达。这正是它与「让 `serve` 暴露 `POST /instances`」在攻击面上的主要差别。
- **参数面收窄**：`add` 只接受 `name` / `workspace` / `profile` / `port` / `enabled`。**`config` 被拒绝**——否则 socket 又成了「按任意路径加载配置」的入口，与 profile 的目的恰好相反。（注意 serde 的 `deny_unknown_fields` 对 internally tagged enum **不生效**，所以字段白名单是手写的。）
- **幂等**：重复 `add` 返回既有实例且不改动它（覆盖会悄悄丢掉手工写的 `env`）；`remove` 对不存在的实例也成功返回。
- **陈旧 socket**：同路径已有服务时报 `socket_in_use`；上次崩溃留下的死 socket 会被清理后重建。
- **`workspace` 只查存在性**：是否越界（子实例 `workspace_allowed_roots`）由收敛阶段的 `preflight` 判定，实例落 `failed` + `last_error`。ctl 不加载子实例配置，写入时无法可靠推断。

```json
{"op":"add","name":"proj-a","workspace":"/home/u/work/proj-a"}
{"ok":true,"name":"proj-a","created":true}
```

```json
{"op":"list"}
{"ok":true,"instances":[{"name":"proj-a","state":"starting","observed":"starting","base_url":null,"port":null,"pid":null,"last_error":null,"workspace":"/home/u/work/proj-a","profile":null,"enabled":true,"declared":true,"managed_by":null}]}
```

```json
{"op":"list","include_unmanaged":true}
```

错误响应的 `code` 稳定可机读（`bad_request` / `bad_workspace` / `socket_in_use` / `supervisor_gone` 等），`error` 只面向人。

`list` 的两个易错点：

- **`observed` 与 `state` 并列，不能只看 `state`**：`state` 是落盘态（四态），`observed` 是读取时派生的观测态（`ready` / `starting` / `stale` / `stopped` / `failed` / `held`）。只有 `observed` 会说「记录是 `ready`，但连不上」（`stale`）——客户端据此决定要不要连；只看 `state` 会把一个死实例当活的，连过去打到空端口。
- **缺省只列声明中**的实例：人工 `up` 起的不在其中，那是 `ctl ls` 的视野。`include_unmanaged: true` 才把它们并进来，每项以 `declared`（布尔）与 `managed_by`（`cli` / `supervise`）区分来源。

#### 退避重启（`supervise --restart on-failure`）

`--watch` 只在**声明变化**时收敛：一条 lane 自己崩掉后，ctl 会一直停在最后一次观测结果上，直到有人改文件、发 socket 请求或重启 ctl。`--restart on-failure` 补上这条观测回路，**默认关闭**（`never` 与加这个开关之前逐字一致）：

```bash
crabmatectl supervise --from-config --watch --restart on-failure
crabmatectl supervise --from-config --watch --socket --restart on-failure \
    --health-interval 30 --backoff-initial 5 --backoff-max 300
```

- **触发条件**：声明里 `enabled = true`、期望态 `running`、且观测到 `stopped` / `failed` / `stale`。**`starting` 不算失败**——那是启动中的中间态，`up` 自己的就绪等待才是它的裁判；否则「启动慢」会被判成「崩溃」。
- **判据复用收敛计划**：巡检跑一遍**只读**的 `plan`，只执行其中的 `Start`；`Running` 用来清零退避，`Stop` / `Skipped` 一律不执行。回收语义仍只属于「声明变化」，否则每 30 秒一次的周期性动作会偷偷变成「顺手杀进程」。
- **退避曲线**：第 n 次尝试之后等待 `min(初始 × 2^(n-1), 封顶)`，默认 5s → 10s → … 封顶 300s；**次数不设上限**（会静默放弃的守护进程比会刷屏的更糟），坏实例的 `last_error` 在 `status` 里可见。
- **进度写盘**：`restart_attempts` / `next_restart_at` 落在状态文件里，所以 ctl 重启后仍在退避窗口内——崩溃实例不会因为守护进程重启就白得一次即时重试。观测到 `ready` 即清零（它记的是**连续**次数）。
- **失败同样记账**：重启失败也计数并推迟下一次，否则「永远起不来的实例」每轮巡检都被重试一次，退避形同不存在。
- **不刷日志**：只有真正尝试才打一行；被退避挡下的巡检静默，看 `status` 的 `next_restart_at`。
- **显式 `down` 优先**：`desired_state = stopped` 的实例不会被拉起；`down` 同时清零退避字段，下次 `up` 不被上一轮崩溃的等待时间挡住。
- **只在常驻模式可用**：`--restart on-failure` 不带 `--watch` / `--socket` 报 `restart_requires_resident`（一次性收敛没有下一轮巡检）。
- **巡检间隔独立于声明轮询**：`--health-interval`（默认 30s）与 `--interval`（默认 1s，只 stat + 读文件）分开，避免每秒发一次 TCP 探测。

一个实现上的坑值得记下来：重启流程内部会先 `ops::down`，而 `down` 会写下 `desired_state = stopped` 作为「用户显式停止」的标记。若不在记账时把它恢复成 `running`，**一次失败的重启就会把实例永久钉成「已被用户 down」，退避重试再也走不到**——这个 bug 是被 `failed_attempt_books_backoff_and_blocks_next_sweep` 用例在实现阶段抓到的。

单个实例失败不影响其余实例；一次性模式下退出码非零（`supervise_partial_failure`）。

**状态**：落盘只有 `starting` / `ready` / `failed` / `stopped`；`stale`（记录说在跑但连不上或身份不符）与 `held`（进程还在但已标记停止）是**读取时派生**的观测态，由 `ls` / `status` 输出，不写文件。所以 `remove` 摘掉声明、进程被回收后，**记录不会消失**（转成 `stopped`，要清就 `prune`）——客户端判断「lane 是否还在」应以 `list`（只看声明）为准，不要等状态文件消失。

**`--json` 契约**（`ls --json` 数组元素）：`name`、`state`、`desired_state`、`base_url`、`port`、`pid`、`pgid`、`started_at`、`uptime_secs`、`last_error`、`config_in_use`、`workspace`、`log`、`env_keys`、`profile`、`profile_in_use`、`restart_attempts`、`next_restart_at`。新增字段只增不删。

**已知限制**：`serve` 收到 `SIGTERM` 后实测约 **30 秒**才退出，因此默认宽限 10 秒的 `down` 通常会走到 `SIGKILL`（输出会明确提示，可用 `--timeout` 放宽）。`prune` 只删状态记录，不删实例目录与日志。

## `tool-replay`（工具时间线 fixture）

用于复现某次对话中的**工具调用顺序与参数**，或做**回归对比**（与录制时的 `tool` 消息输出是否一致）。

- **`export`**：从 **`ChatSessionFile`**（与 `save-session` / Web 导出同形）扫描 `assistant.tool_calls` 及紧随其后的 `role=tool` 消息，写出 **`tool_replay_YYYYMMDD_HHMMSS.json`** 到 **`.crabmate/exports/`**（或 `--output`）。fixture 顶层含 `version`、`source: "crabmate-tool-replay"`、可选 `note`、**`steps`**（`name`、`arguments`、`tool_call_id`、可选 **`recorded_output`**）。
- **`run`**：按 `steps` 顺序对当前工作区调用 **`tools::run_tool`**（**真实执行**：`run_command` / `http_fetch` 等仍受配置与白名单约束；**无**终端审批交互，非白名单 `run_command` 会直接失败）。`--compare-recorded` 时对含 `recorded_output` 的步骤做**字符串全等**比较，有不一致则进程退出码 **6**。

示例：

```bash
crabmate save-session --format json --workspace /path/to/proj   # 先得到 chat_export_*.json
crabmate tool-replay export --session-file /path/to/chat_export_20260101_120000.json --note "bug repro"
crabmate tool-replay run --fixture /path/to/proj/.crabmate/exports/tool_replay_20260101_120500.json
crabmate tool-replay run --fixture ./fixture.json --compare-recorded   # CI 回归
```

**安全**：重放与正常 Agent 回合相同，仅在**可信工作区**使用；勿对不可信会话 fixture 在敏感目录执行。

## 一键打包（tar.gz + 可选 .deb）

默认 **server-only**（**不**附带 frontend）：

```bash
make package           # tar.gz + 可选 .deb → dist/
make package-tar       # 仅 tar.gz
make package-deb       # 仅 .deb（Linux + cargo-deb）
# 等价：./scripts/package-release.sh --skip-frontend
```

产物在仓库根目录 **`dist/`**：**`tar.gz`** 始终生成（除非 **`--skip-tar`**）；**`.deb`** 仅在 **Linux** 且已安装 **`cargo-deb`** 时复制自 **`target/debian/`**（可用 **`--skip-deb`** 跳过）。**`./scripts/package-release.sh --help`** 查看全部选项。

## 打包 Debian `.deb`

```bash
cargo install cargo-deb
make package-deb
# 或：cargo build --release && cargo deb
sudo dpkg -i dist/crabmate_*.deb   # 或 target/debian/crabmate_*.deb
```

本仓 `.deb` / **`make package*`** 为 **server-only**（不内嵌 UI）。运行时**永远纯 API**，不托管 SPA；浏览器 UI 由 Client 仓自行托管并经 **CORS**（**`CM_WEB_CORS_ALLOWED_ORIGINS`**）接入。

安装后：`export API_KEY=… && crabmate serve`（纯 API）。包内包含 **`/usr/share/man/man1/crabmate.1`**，可用 **`man crabmate`** 查看（若 **`MANPATH`** 已含 `/usr/share/man`）。

### systemd（`.deb` / tar）

- **`.deb`**：安装 **`/usr/lib/systemd/system/crabmate.service`**、**`/etc/crabmate/config.toml`**（锚定相对路径）、**`/etc/crabmate/config/prompts/`**、**`crabmate.env.example`**；`postinst` 会创建系统用户 **`crabmate`** 与 **`/var/lib/crabmate`**。**默认不** `enable` / `start`。
- **默认监听**：**`127.0.0.1:8080`**；**`ExecStart`** 含 **`--config /etc/crabmate/config.toml`**（解析 **`config/prompts/*.md`**）。永远纯 API（不挂 SPA）；**`/`** 为 404，API（如 **`/health`**）仍可用。
- **环境文件**：仅 **`KEY=value`**（**禁止** `export`）；可设 **`API_KEY`**、**`PATH`**（系统用户默认 PATH 较窄，需 cargo 时自行追加）。
- 启用前建议：

```bash
sudo cp /etc/crabmate/crabmate.env.example /etc/crabmate/crabmate.env
sudo chmod 600 /etc/crabmate/crabmate.env   # 填入密钥等占位项
sudo systemctl daemon-reload
sudo systemctl enable --now crabmate.service
sudo systemctl status crabmate.service
```

- **tar.gz**：附带 **`systemd/`** 与 **`etc/crabmate/`**（含 `config.toml`、prompts、env 示例）。可将 **`etc/crabmate`** 拷到系统 **`/etc/crabmate`**，单元装到 **`/usr/lib/systemd/system/`**（按需改 `ExecStart` 路径）。更完整的反代与加固示例见 **[docs/个人VPS部署指南.md](个人VPS部署指南.md)**。

从源码树直接预览：`man -l man/crabmate.1`（路径相对仓库根）。
