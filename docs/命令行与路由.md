# 命令行与子命令

查看帮助：`crabmate --help`、`crabmate help`、`crabmate help <子命令>`（与 `--help` 等价）。根级 **after_help** 交叉引用 **`docs/命令行契约.md`**、**`docs/SSE协议.md`**。**全局选项**写在子命令**之前**：`--config`、`--workspace`、`--no-tools`、`--llm-context-tokens`、`--log`。须给出显式子命令（如 `serve`）；裸 `cargo run` 不再默认进入对话。

**官方终端**：Client 仓 **`crabmate-tui`**（HTTP/SSE 连接本仓 **`serve`**；模型密钥存 Client 本机）。本仓同进程 **`chat` / `repl` / `tui` 入口与实现已硬删**（D2.2，见 [`design/client_shell_split.md`](design/client_shell_split.md) §2.5）。

**脚本契约**（退出码、`tool-replay` 等；旧 `chat --output json` 形状仅作历史说明）：[`命令行契约.md`](命令行契约.md)。

## 手册页（troff / `man`）

- **源码树**：预生成的 **`man/crabmate.1`**（troff），与当前 `clap` 定义一致；**Debian `.deb`** 会安装到 **`/usr/share/man/man1/crabmate.1`**（见根目录 `Cargo.toml` 的 `[package.metadata.deb] assets`）。
- **再生成**（增删子命令或全局选项后）：`cargo run --features gen-man --bin crabmate-gen-man`，然后提交更新后的 `man/crabmate.1`。
- **`cargo install crabmate`**（crates.io **稳定版 `0.5.0`**，默认 **`server`**；git tag **`v0.5.0`** 与此包一致）：默认**不会**把 man 装到 `MANPATH`；可将 `man/crabmate.1` 拷到本机 `.../share/man/man1/` 后执行 `mandb`（视发行版而定），或优先使用 **`cargo deb`** / 发行版打包。

## 子命令一览

| 子命令 | 说明 |
|--------|------|
| `serve [PORT]` | HTTP API（默认纯 API，端口 **8080**）；同机托管 SPA 用 **`--with-web`** + **`CM_WEB_STATIC_DIR`**；**`bearer` 时可在未设 `API_KEY` 的情况下启动**，对话前须在侧栏「设置」填写**模型**密钥（`client_llm`，权威在 Client 本机）。HTTP 层：配置非空 **`web_api_bearer_token`** / **`CM_WEB_API_BEARER_TOKEN`** 时挂载 Bearer（`Authorization: Bearer` 或 `X-API-Key`）；浏览器另须在 **设置 →「Web API 共享密钥」** 保存同一串（**不是**模型 API_KEY）。嵌入默认 **`web_api_require_bearer=false`**（允许无密钥启动）；生产或对外建议 **`web_api_require_bearer=true`** 强制启动前须配密钥。**本机临时跳过鉴权**：`unset` 密钥后听 `127.0.0.1`，或清密钥后设 **`CM_ALLOW_INSECURE_NO_AUTH_FOR_NON_LOOPBACK=true`** 再听 `0.0.0.0`（见 **`docs/配置说明.md`**）。**桌面 Tauri** 为薄客户端，须**自行**启动本命令后再用壳连接（见 Client [`desktop-tauri/DEVELOPMENT.md`](https://github.com/noisystreet/crabmate-client/blob/main/desktop-tauri/DEVELOPMENT.md)）。**Ctrl+C** 触发优雅关闭（排空在途 HTTP / 队列）；关闭过程中再次 **Ctrl+C** 立即退出（退出码 130）。 |
| `bench` | 批量测评：`--benchmark`、`--batch` 等。 |
| `config` | 配置与 `API_KEY` 状态自检；`--dry-run` 可选。 |
| `doctor` | 本地诊断（**不需要** `API_KEY`）。 |
| `web-bearer` | **`status` / `set` / `clear`**：读写系统钥匙串中的 **Web API 共享密钥**（与 Web **`/user-data/secrets/web-api-bearer`** 同源；**不要**求 `API_KEY`）。**`set`** 推荐 **`set --stdin`**（管道）、**`set --from-env`**（读 **`CM_WEB_API_BEARER_TOKEN`**）或无参数时交互**隐藏输入**；位置参数 `TOKEN` 会进 shell 历史/`ps`，仅作兼容。**`serve`** 在 TOML / **`CM_WEB_API_BEARER_TOKEN`** 皆空时从此处加载；从「无密钥」变为「有密钥」（或反向）须**重启 `serve`** 才会挂载/拆除鉴权中间件。浏览器仍须在 **设置 → Web API 共享密钥** 保存同一串。 |
| `models` | `GET …/models`（需 `API_KEY`）。 |
| `probe` | 探测 models 端点（需 `API_KEY`）。 |
| `save-session` | 从会话文件导出 JSON/Markdown 到工作区 **`.crabmate/exports/`**（与 Web 导出同形；**不要**求 `API_KEY`）。`--format json|markdown|both`（默认 `both`），**`--projection raw|display`**（默认 **`raw`**；`display` 不可直接 **`tool-replay`**），`--session-file` 可选。兼容别名 **`export-session`**。 |
| `tool-replay` | 从会话 JSON 提取**工具调用时间线**为 fixture，或按 fixture **重放工具**（与对话相同走 `run_tool`，**不调用大模型**；**不要**求 `API_KEY`）。见下文「工具重放 fixture」。 |
| `mcp list` | 只读列出**本进程**内与 **user-data** `mcp_servers.json` 中已启用服务器对应的已缓存会话及合并后的 OpenAI 工具名（`mcp__{slug}__…`；**不要**求 `API_KEY`）。配置真源为 **`~/.local/share/crabmate/mcp_servers.json`**（Web **设置 → MCP**）；支持 **stdio（`command`）** 与 **远程 Streamable HTTP（`url`）**。TOML `mcp_command` / `CM_MCP_COMMAND` 仅在 user-data 为空且未置 **`toml_legacy_imported`** 时**一次性**导入。若尚无缓存，可先 **`mcp list --probe`** 按配置尝试连接（stdio 启动 `command` 子进程；远程则 HTTP 握手）。 |
| `plugin init` | 生成工作区 **`plugins/*.json`** 动态工具模板（名称需 `dyn__` 前缀）；输出文件路径默认 `plugins/<name-without-prefix>.json`。 |
| `plugin list` | 列出动态工具文件、工具名、command 与校验状态（OK/FAIL）；`--json` 输出结构化结果，`--jsonl` 按行输出便于管道处理。 |
| `plugin validate` | 校验动态工具定义（默认扫描 `plugins/*.json`，或 `--file` 指定单文件）；会检查 JSON 结构与 `command` 是否在 `allowed_commands` 白名单；`--json` 输出结构化结果，`--jsonl` 按行输出便于管道处理。 |
| `workflow compile` | 将 **`workflow_spec` v2** YAML（或含 `` ```crabmate-workflow `` 的 `.md`）编译为 **`workflow_execute`** 用的 `{"workflow":{…,"nodes":[…]}}` JSON 并打印到 stdout（**不要**求 `API_KEY`）。**用户向教程**：**`docs/工作流编写教程.md`**；示例目录 **`examples/workflows/`**。 |
| `workflow validate` | 同上编译后做作者层 JSON Schema + DAG 拓扑与工具参数校验；默认人读摘要，`--json` 输出 `author_spec_version`、`author_mode` 与层表。 |
| `workflow run` | 编译并**执行**工作区内工作流文件（等同 Agent `workflow_execute` + **`workflow_file`**；**不要**求 `API_KEY`）。例：`cargo run -- workflow run examples/workflows/ci.yaml`。 |
| `mcp serve` | 在 **stdin/stdout**（默认）或 **TCP 端口**（`--port N`）上运行 **MCP server**，将 CrabMate **内置工具**暴露给外部客户端（`tools/list` / `tools/call` → **`tools::run_tool`**；**不要**求 `API_KEY`）。工作目录与全局 **`--workspace`** / 配置 **`run_command_working_dir`** 一致。协议 JSON-RPC 走 **stdout**（stdio 模式）或 TCP 流；启动提示与日志用 **stderr**，避免污染 MCP 流。**`--no-tools`**：不向客户端列出工具（调用未知名仍走 `run_tool` 并得「未知工具」）。**`--port`**：设置 TCP 端口号（默认 `0` 表示 stdio 模式），监听 `127.0.0.1` 允许多个连接。**无传输层鉴权**：仅用于本机或 SSH 隧道可信网络集成；能力面与 `run_command` 白名单、工作区路径策略及（若启用）**`tool_call_explain_enabled`** 一致。TCP 模式可用于远程开发：通过 SSH 隧道转发端口，本地 CrabMate 以 MCP 客户端连接远程服务器。 |
| `e2e` | 真实 LLM 端到端测试：运行预设场景并生成结构化报告（需 `API_KEY`）。**`--mode real|record|replay`**（默认 `real`）、**`--output-dir DIR`**、**`--recordings-dir DIR`**。详见 [`docs/真实LLM-E2E.md`](真实LLM-E2E.md)。 |

## 日志级别

未设置 `RUST_LOG` 时：`serve` 默认 **info**；`bench` / `config` / `mcp` / `web-bearer` / `save-session`（及别名 `export-session`）/ `tool-replay` / `plugin` / `workflow` / `doctor` 等其它子命令默认 **warn**。可用 `RUST_LOG` 或 `--log <FILE>`。

## 消息管道调试日志

`RUST_LOG=crabmate=debug` 时每次调用模型前打印 **`message_pipeline session_sync`** 汇总；更细：`RUST_LOG=crabmate::message_pipeline=trace`。累计命中见 **`GET /status`**；实现见 `src/agent/message_pipeline/`。

## 兼容旧用法

未写子命令时仍可用 **`--serve`**、**`--benchmark`**、**`--dry-run`** 等映射到对应子命令。**不再**把裸 argv / `--query` / `--stdin` 映射为 `chat` 或默认插入 `repl`（须显式子命令；与 `tests/fixtures/cli/legacy_normalize.json` 一致）。若 argv **任意位置**已含已知子命令名，则不做额外插入。

## 常用选项（兼容写法）

| 选项 | 说明 |
|------|------|
| `--config <path>` | 指定配置文件（建议写在子命令前） |
| `--serve [port]` | 等价于 `serve` |
| `--host <ADDR>` | 随 `serve` |
| `--port 0` | 随 `serve`：由 OS 分配空闲端口；启动日志与 **`--desktop-ready-json`** / **`--web-ready-json`** 中的 **`port`/`url`** 以 **`TcpListener::bind` 后的 `local_addr()`** 为准 |
| `--desktop-ready-json` | 随 `serve`：监听成功后向 **stdout** 额外打印一行 JSON：`{"event":"web_ready","host":"…","port":…,"url":"http://…/","auth_enabled":…}`；**仅**在显式开启时出现；供脚本/工具解析（桌面壳**不再**依赖）。**命名已弃用**；推荐别名 **`--web-ready-json`**（行为相同） |
| `--web-ready-json` | `--desktop-ready-json` 的别名 |
| `--workspace <path>` | 覆盖初始工作区 |
| `--no-tools` | 禁用工具 |
| `--llm-context-tokens <N>` | 覆盖 **`[agent] llm_context_tokens`** / **`CM_LLM_CONTEXT_TOKENS`**（模型上下文 token 上限；`0` 表示不覆盖）；影响会话同步裁剪近似字符预算 |
| `--with-web` / `--web` | 显式挂载业务 UI 静态资源（须配合 `CM_WEB_STATIC_DIR` 或可探测 dist） |
| `--dry-run` | 映射为 `config` |
| `--log <FILE>` | 日志文件 + stderr 镜像 |

> **已移除（D2.1）**：全局 **`--agent-role`**、以及仅服务于同进程 **`chat`/`repl`** 的 **`--query` / `--stdin` / `--output` / `--no-stream`** 等。对话请用 Client **`crabmate-tui`** 或 Web；角色用请求体 / Web **`agent_role`**。

## Benchmark（`bench`）

评测能力规划、各 benchmark 对接与测试策略见 **`docs/基准测试规划.md`**（与通用 CLI 说明分离）。

| 选项 | 说明 |
|------|------|
| `--benchmark <TYPE>` | `swe_bench`、`gaia`、`human_eval`、`generic` |
| `--batch <FILE>` | 输入 JSONL（`human_eval` 时每条须含 `humaneval_test`、`entry_point`，见 **`docs/基准测试规划.md`** §5） |
| `--batch-output <FILE>` | 默认 `benchmark_results.jsonl` |
| `--task-timeout <SECS>` | `0` 不限制 |
| `--max-tool-rounds <N>` | `0` **不限制**轮次（**不会**关闭工具）；关工具用全局 **`--no-tools`** |
| `--samples <N>` | 每任务采样次数（pass@k 的 `n`）；默认 `1`。多采样结果用 `humaneval_score_benchmark_results.py --k K` 聚合出 `pass@k` |
| `--resume` | 跳过已有 `instance_id`（多采样时按 `(instance_id, sample_index)` 续跑） |
| `--bench-system-prompt <FILE>` | 覆盖 system |

HumanEval 适配器会在函数桩前附加「只续写函数体、不要追问」指令，并追加 system suffix。官方数据转换与判分（Python 3，**执行模型生成代码**，须自行隔离环境）。**建议**加全局 **`--no-tools`**（`--max-tool-rounds 0` 不够）：

```bash
python3 scripts/humaneval_official_to_crabmate_jsonl.py --input HumanEval.jsonl --output tasks.jsonl
cargo run -- --no-tools bench --benchmark human_eval --batch tasks.jsonl --batch-output results.jsonl
python3 scripts/humaneval_score_benchmark_results.py --tasks tasks.jsonl --results results.jsonl
```

## 示例

```bash
cargo run -- serve
cargo run -- --config /path/to/my.toml serve
RUST_LOG=debug cargo run -- --log /tmp/crabmate.log serve
cargo run -- serve 3000
cargo run -- serve --port 3000               # 与上一行等价
cargo run -- --workspace /path/to/project serve 8080
cargo run -- serve --host 0.0.0.0            # 注意安全与鉴权
cargo run -- serve --host 127.0.0.1 --port 0 --web-ready-json   # 可选：stdout 打印 web_ready（脚本用；亦可用已弃用名 --desktop-ready-json）
cargo run -- --no-tools serve
cargo run -- bench --benchmark swe_bench --batch tasks.jsonl --batch-output results.jsonl --task-timeout 600
cargo run -- config
cargo run -- doctor
cargo run -- save-session
cargo run -- save-session --format json --workspace /path/to/proj
cargo run -- save-session --format json --projection display
```

**`save-session`**：默认读取 **`<workspace>/.crabmate/tui_session.json`**（`--workspace` 与全局 `--config` 写在子命令前），在 **`<workspace>/.crabmate/exports/`** 下生成带时间戳的 **`chat_export_*.json`** / **`chat_export_*.md`**（schema / Markdown 标题与 Web 共用 **`crabmate-chat-export`**）。JSON 顶层信封（**必填**）：`schema`（`crabmate.chat_session`）、`schema_version`（当前 **`2.0.0`**）、**`projection`**（**`raw`**：完整 OpenAI 形 `Message`，会话落盘 / **`save-session`** 默认；**`display`**：运维展示投影瘦消息，可用 **`--projection display`**，**不可**直接喂 **`tool-replay`**）、`version`、`messages`。**不**再兼容缺信封字段的旧 JSON。Markdown / `display` 投影的**工具段**用信封摘要或截断原文，**不保证**与 Web 工具卡逐字一致（像素级工具卡在 Client `crabmate-tool-card`）。见 `crates/crabmate-chat-export`、`runtime/chat_export.rs`、Client `frontend/src/session_export.rs`。每行 stdout 为写出文件的绝对路径，便于脚本捕获。

## `tool-replay`（工具时间线 fixture）

用于复现某次对话中的**工具调用顺序与参数**，或做**回归对比**（与录制时的 `tool` 消息输出是否一致）。

- **`export`**：从 **`ChatSessionFile`**（与 `save-session` / Web 导出同形）扫描 `assistant.tool_calls` 及紧随其后的 `role=tool` 消息，写出 **`tool_replay_YYYYMMDD_HHMMSS.json`** 到 **`.crabmate/exports/`**（或 `--output`）。fixture 顶层含 `version`、`source: "crabmate-tool-replay"`、可选 `note`、**`steps`**（`name`、`arguments`、`tool_call_id`、可选 **`recorded_output`**）。
- **`run`**：按 `steps` 顺序对当前工作区调用 **`tools::run_tool`**（**真实执行**：`run_command` / `http_fetch` 等仍受配置与白名单约束；**无**终端审批交互，非白名单 `run_command` 会直接失败）。`--compare-recorded` 时对含 `recorded_output` 的步骤做**字符串全等**比较，有不一致则进程退出码 **6**。

示例：

```bash
crabmate save-session --format json --workspace /path/to/proj   # 先得到 chat_export_*.json
crabmate tool-replay export --session-file /path/to/chat_export_20260101_120000.json --note "bug repro"
crabmate tool-replay run --fixture /path/to/proj/.crabmate/exports/tool_replay_20260101_120500.json
crabmate tool-replay run --fixture ./fixture.json --compare-recorded   # CI 回归
```

**安全**：重放与正常 Agent 回合相同，仅在**可信工作区**使用；勿对不可信会话 fixture 在敏感目录执行。

## 同进程对话入口（已移除）

**D2.2**：本仓 **`crabmate chat` / `repl` / `tui`** 的 clap 入口（D2.1）与 **`runtime/tui` / 同进程对话 REPL/`chat` 实现**均已硬删。官方终端为 Client **`crabmate-tui`**（HTTP/SSE → **`serve`**）；Web / Desktop 仍走 **`POST /chat`** / **`/chat/stream`**。

仍可用的本仓运维能力：

- **`save-session`**（别名 **`export-session`**）：从磁盘会话文件导出到 **`.crabmate/exports/`**（与 Web 同形；默认仍可读历史路径 **`.crabmate/tui_session.json`**）。
- **`tool-replay`**：从会话 JSON 提取/重放工具时间线（**不**调用大模型）。
- **`bench`**：批量测评。
- Web 侧会话持久、人工审批（SSE + **`POST /chat/approval`**）、导出：见下文 HTTP 路由与 Client UI。

进程退出码常量仍见 **`src/runtime/cli_exit.rs`** / [`命令行契约.md`](命令行契约.md)（现主要被 **`tool-replay`** 等使用）。

配置热重载对 **`serve`**：仍用 **`POST /config/reload`**（见 **`docs/配置说明.md`**）。

## 前端构建与 Web

业务 UI 源码在官方 [crabmate-client](https://github.com/noisystreet/crabmate-client)（路径 A；本机命令假定同级克隆）：


## 主要 HTTP 路由（`serve`）

### HTTP 鉴权矩阵

与 **`src/web/server.rs`** 路由分层一致。启动时若 **`web_api_bearer_token` / `CM_WEB_API_BEARER_TOKEN` 非空**，则对下表「受保护」路径挂 Bearer 中间件（`Authorization: Bearer` **或** `X-API-Key`）；密钥为空则**不**挂层，受保护路径对能访问监听地址的客户端开放（仅可信环境）。

| 类别 | 路径 | Bearer 层 | 说明 |
|------|------|-----------|------|
| 受保护 API | `/chat*`、`/conversation/*`、`/workspace*`、`/skills`、`/tasks`、`/github/*`、`/config/*`、`/user-data/*`、`/upload`、`GET /uploads/{filename}`、`/uploads/delete` | **是**（仅当启动时 token 非空） | 与配置说明「Web API 鉴权层」一致 |
| 系统公开 | `GET /health`、`GET /status` | **否** | **即使配置了 Bearer，也不经该层**；非 loopback 部署应假设能打到端口即可读 status（用防火墙 / 仅绑 `127.0.0.1` / 反代鉴权隔离） |
| 契约 / 壳 | `GET /openapi.json`、`GET /web-ui` | **否** | |

## 一键打包（tar.gz + 可选 .deb）

默认 **server-only**（**不**附带 frontend）：

```bash
make package           # tar.gz + 可选 .deb → dist/
make package-tar       # 仅 tar.gz
make package-deb       # 仅 .deb（Linux + cargo-deb）
# 等价：./scripts/package-release.sh --skip-frontend
```

产物在仓库根目录 **`dist/`**：**`tar.gz`** 始终生成（除非 **`--skip-tar`**）；**`.deb`** 仅在 **Linux** 且已安装 **`cargo-deb`** 时复制自 **`target/debian/`**（可用 **`--skip-deb`** 跳过）。**`./scripts/package-release.sh --help`** 查看全部选项。

## 打包 Debian `.deb`

```bash
cargo install cargo-deb
make package-deb
# 或：cargo build --release && cargo deb
sudo dpkg -i dist/crabmate_*.deb   # 或 target/debian/crabmate_*.deb
```

本仓 `.deb` / **`make package*`** **默认不内嵌**业务 UI。运行时**默认纯 API**；托管 SPA 用 **`--with-web`** + **`CM_WEB_STATIC_DIR`** 指向 Client `frontend/dist`。若确需随 tar 附带 UI，可用脚本 **`./scripts/package-release.sh --frontend-dist …/frontend/dist`**（Makefile 目标不走该路径）。

安装后：`export API_KEY=… && crabmate serve`（纯 API）；或 **`crabmate serve --with-web`** 并设 **`CM_WEB_STATIC_DIR`**。包内包含 **`/usr/share/man/man1/crabmate.1`**，可用 **`man crabmate`** 查看（若 **`MANPATH`** 已含 `/usr/share/man`）。

### systemd（`.deb` / tar）

- **`.deb`**：安装 **`/usr/lib/systemd/system/crabmate.service`**、**`/etc/crabmate/config.toml`**（锚定相对路径）、**`/etc/crabmate/config/prompts/`**、**`crabmate.env.example`**；`postinst` 会创建系统用户 **`crabmate`** 与 **`/var/lib/crabmate`**。**默认不** `enable` / `start`。
- **默认监听**：**`127.0.0.1:8080`**；**`ExecStart`** 含 **`--config /etc/crabmate/config.toml`**（解析 **`config/prompts/*.md`**）。**默认纯 API**（不挂 SPA）；同机托管 UI 时在单元或 wrapper 中加 **`--with-web`** 并设 **`CM_WEB_STATIC_DIR`**。未挂 UI 时 **`/`** 为 404，API（如 **`/health`**）仍可用。
- **环境文件**：仅 **`KEY=value`**（**禁止** `export`）；可设 **`API_KEY`**、**`PATH`**（系统用户默认 PATH 较窄，需 cargo 时自行追加）。
- 启用前建议：

```bash
sudo cp /etc/crabmate/crabmate.env.example /etc/crabmate/crabmate.env
sudo chmod 600 /etc/crabmate/crabmate.env   # 填入密钥等占位项
sudo systemctl daemon-reload
sudo systemctl enable --now crabmate.service
sudo systemctl status crabmate.service
```

- **tar.gz**：附带 **`systemd/`** 与 **`etc/crabmate/`**（含 `config.toml`、prompts、env 示例）。可将 **`etc/crabmate`** 拷到系统 **`/etc/crabmate`**，单元装到 **`/usr/lib/systemd/system/`**（按需改 `ExecStart` 路径）。更完整的反代与加固示例见 **[docs/个人VPS部署指南.md](个人VPS部署指南.md)**。

从源码树直接预览：`man -l man/crabmate.1`（路径相对仓库根）。
