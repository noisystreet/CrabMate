## 进程退出码（历史：`chat`；现行：`tool-replay` 等）

| 码 | 含义 | 典型场景 |
|----|------|----------|
| 0 | 成功 | 回合完成且未触发「全拒」分支 |
| 1 | 一般错误 | I/O、配置、未归类失败 |
| 2 | 用法 / 输入错误 | 参数不合法、JSON/JSONL 解析失败 |
| 3 | 模型 / 解析错误 | 网关错误体、响应无法解析、部分规划无效前缀（启发式归类见 `classify_model_error_message`） |
| 4 | 本回合内全部 `run_command` 均被审批拒绝（**historical**） | 同进程 `chat` 管道下未输入 `y`/`a`、或交互全选拒绝。**D2.2 后生产不再发出码 4**（无同进程 CLI 工具审批）；常量仍保留供契约测试占位 |
| 5 | 配额 / 限流 | HTTP 429、402、部分 503 等（启发式） |
| 6 | 工具重放与录制不一致 | `tool-replay run --compare-recorded` 下至少一步输出与 `recorded_output` 字符串不等 |

实现常量：`EXIT_GENERAL`、`EXIT_USAGE`、`EXIT_MODEL_ERROR`、`EXIT_TOOLS_ALL_RUN_COMMAND_DENIED`（**historical**，D2.2 后生产不再发出）、`EXIT_QUOTA_OR_RATE_LIMIT`、`EXIT_TOOL_REPLAY_MISMATCH`（`src/runtime/cli_exit.rs` / `crates/crabmate-runtime`）。契约测试：`tests/cli_contract.rs`（仍断言码 4 占位值）。

## SSE / 流式错误码（Web `POST /chat/stream`）

控制面 JSON 中 **`error` + 非空 `code`** 表示流级失败（与模型正文中的 `{"error":"…"}` 区分）。常见 **`code`** 见 **[`docs/SSE协议.md`](SSE协议.md)** 中「流错误 `code` 枚举」表，例如：

| `code` | 含义（摘要） |
|--------|----------------|
| `INTERNAL_ERROR` | 队列或编排其它失败（**`error`** 为通用用户文案；**`reason_code`** 为截断内部摘要） |
| `STEP_RETRY_EXHAUSTED` / `REPLAN_EXHAUSTED` / `TIME_LIMIT_EXHAUSTED` / `TOKEN_LIMIT_EXHAUSTED` | 编排预算类失败（同上） |
| `CONVERSATION_CONFLICT` | 会话版本冲突 |
| `plan_rewrite_exhausted` | 终答规划重写次数用尽（可选 `reason_code`，见 `docs/SSE协议.md`） |
| `SSE_ENCODE` | 控制面 JSON 序列化失败（兜底） |

**`INTERNAL_ERROR`** 等码在 **SSE 流**与 **`POST /chat` JSON** 中可由同一套 `RunAgentTurnError` 映射产生；`chat` 子进程仍由 `classify_model_error_message` 等对**错误字符串**归类。

**HTTP JSON（非 SSE `data:`）**：失败时 **`ApiError`** 含 **`code`**、**`message`**（用户可读）；可选 **`reason_code`**（常见于 **`INTERNAL_ERROR`** 的截断内部摘要）；可选 **`request_id`**（与响应头 **`x-request-id`** 同值；**4xx/5xx** 的 `application/json` **`ApiError`** 体由中间件补齐，若 handler 已填写则不覆盖）；可选 **`details[]`**（字段级子码，旧客户端可忽略）。**SSE** `SseErrorBody` / AG-UI `RUN_ERROR` 亦可带同值 **`request_id`** / **`requestId`**（见 **`docs/SSE协议.md`**）；官方 Web 会在错误文案中附带 **`code`** 与 **`request_id`**。握手阶段其它码以 **`web/chat_handlers`** 与 OpenAPI 为准。

### HTTP `ApiError.code` 表（非 SSE）

排障**优先看响应头 `x-request-id`**。下表为常见稳定码（非穷尽；新增码时同步 OpenAPI / 本表）。**可重试**指客户端自动退避重试是否合理（改密钥后再试不算自动可重试）。

| `code` | 典型 HTTP | 可重试 | 场景摘要 |
|--------|-----------|--------|----------|
| `UNAUTHORIZED` | 401 | 否 | Bearer / X-API-Key 失败 |
| `QUEUE_FULL` | 503 | **是**（退避） | 对话队列满 |
| `LLM_API_KEY_REQUIRED` | 400 | 否 | 缺模型 API 密钥 |
| `WORKSPACE_NOT_SET` | 400 | 否 | 未设工作区 |
| `SSE_PROTOCOL_MISMATCH` / `SSE_CLIENT_TOO_NEW` / `INVALID_SSE_CLIENT_PROTOCOL` | 400 | 否 | SSE 协议握手 |
| `STREAM_JOB_GONE` | 410 | 否 | 流任务已结束（`stream_resume` 与 `POST /chat/stream/{job_id}/cancel`） |
| `JOB_NOT_FOUND` | 404 | 否 | 后台任务 id 不存在 / 从未创建（`GET /tools/jobs/{id}`、`GET .../output`、`POST .../cancel`） |
| `JOB_EXPIRED` | 410 | 否 | 后台任务已过 TTL+宽限被清理 |
| `JOB_OWNERSHIP_MISMATCH` | 403 | 否 | 请求头 `X-Workspace-Root` 与任务归属工作区不符 |
| `UNKNOWN_JOB` | 404 | 否 | 异步 `job_id` 未知 |
| `CONVERSATION_NOT_FOUND` / `INVALID_CONVERSATION_ID` | 404 / 400 | 否 | 会话 |
| `CONVERSATION_CONFLICT` / `CONVERSATION_REVISION_UNKNOWN` | 409 / 400 | 否 | 会话乐观锁 |
| `APPROVAL_*` / `INVALID_APPROVAL_*` | 4xx | 否 | 工具审批 |
| `CONFIG_RELOAD_FAILED` / `SESSION_STORE_SWITCH_FAILED` | 400 | 否 | 配置 / 会话库切换 |
| `CLONE_NO_POOL` / `CLONE_BUSY` / `CLONE_TIMEOUT` / `CLONE_CANCELLED` / `CLONE_AUTH_REQUIRED` | 4xx / 429 | 视码（`BUSY` 可短退避） | 项目池 Clone（亦见 SSE） |
| `SKILL_INVOKE_FAILED` | 400 | 否 | 强制 skill 失败 |
| `UPLOAD_*` / `MULTIPART_ERROR` | 4xx | 否 | 上传 |
| `EMPTY_MESSAGE` / `INVALID_*` | 400 | 否 | 请求校验 |
| `INTERNAL_ERROR` | 500 | 视情况 | 编排失败；可有截断 `reason_code` |
| `STEP_RETRY_EXHAUSTED` / `REPLAN_EXHAUSTED` / `TIME_LIMIT_EXHAUSTED` / `TOKEN_LIMIT_EXHAUSTED` / `LLM_RATE_LIMIT` | 4xx / 5xx | 视码（限流可退避） | 编排预算 / LLM |

常量摘录见 **`crates/crabmate-api-contract/src/error_codes.rs`**。流式 **`data:`** 行内错误码完整表见 **[`docs/SSE协议.md`](SSE协议.md)**。

### 后台工具任务端点（`run_command` 的 `async:true`）

发起 `async:true` 后，`tool_result` 带 `tool_job_id` / `tool_job_poll_url` / `tool_job_status`（软字段，见 `docs/SSE协议.md`），任务状态与终态输出经以下端点获取：

| 端点 | 说明 |
|------|------|
| `GET /tools/jobs/{tool_job_id}` | 轮询：`200` 返回 `tool_job_id` / `status`（`queued`\|`running`\|`succeeded`\|`failed`\|`cancelled`\|`timed_out`）/ `exit_code` / `stdout` / `stderr` / `summary` / `error_code` / `failure_category` / `workspace_changed` / `result_version`。错误：`403 JOB_OWNERSHIP_MISMATCH`（`X-Workspace-Root` 不符）、`404 JOB_NOT_FOUND`、`410 JOB_EXPIRED` |
| `GET /tools/jobs/{tool_job_id}/output?cursor=N` | **实时输出增量轮询**（`tail -f` 语义；`N` 省略/非法 → 从最早可用起）：`200` 返回 `tool_job_id` / `status` / `cursor`（下次请求携带）/ `items`（`[{seq, stream(stdout\|stderr), text}]`，升序、跨响应不重不漏）/ `truncated`（环形缓冲已丢早段，本次从最早可用重放）/ `eof`（终态且已全部返回，可停止）。单次响应至多 500 条；`401/403/404/410` 同轮询 |
| `POST /tools/jobs/{tool_job_id}/cancel` | 取消：`queued` 直接转移、`running` 置取消标记（进程组 SIGTERM→SIGKILL）、已是 `cancelled` 幂等 **200**；其它终态 **409** `{ "status": "<当前状态>" }` 不覆盖；`404` / `410` 同轮询 |

鉴权与受保护路由一致（Bearer / X-API-Key）。**归属校验**：随机 `tool_job_id`（32 hex，不可枚举）为能力凭证（主防护）；可选请求头 **`X-Workspace-Root`** 与创建时工作区比对，不符 `403`。状态机与字段契约见 `docs/design/background_tool_jobs_contract.md`；实时输出流（游标/截断/`eof` 语义、环形缓冲上限）见 `docs/design/background_tool_jobs_output_streaming_contract.md`。

## `chat --output json` 每行结果（历史形状；入口已移除）

> **已移除**：`crabmate chat --output json` 不再可用。下列字段仅描述旧版 stdout 一行 JSON，便于迁移脚本。

### 顶层字段

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | 固定 **`crabmate_chat_cli_result`** |
| `v` | number | 模式版本，当前 **`1`** |
| `reply` | string | 本轮最后一条 `assistant` 的 `content`（无则空串） |
| `model` | string | 当前配置中的模型 id |
| `batch_line` | number? | 仅 **`--message-file`** 批跑时出现，为 JSONL **1-based** 行号 |

### 示例

单轮：

```json
{"type":"crabmate_chat_cli_result","v":1,"reply":"你好。","model":"deepseek-chat"}
```

批跑某行：

```json
{"type":"crabmate_chat_cli_result","v":1,"reply":"…","model":"deepseek-chat","batch_line":3}
```

### 演进

增加字段时应保持 **`v`** 递增或保持后向兼容；破坏性变更须在本文档与 **`crabmate --help`** 的 cross-link 中说明。
