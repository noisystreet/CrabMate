# 发布流程（版本号 · CHANGELOG · 依赖许可）

> 本文件是 `AGENTS.md` §4.10「发布与依赖」的**细则**。
> 触发场景：改 `Cargo.toml` 版本、打 tag、发 Release、动 `deny.toml` / 依赖。
> 与 `AGENTS.md` 冲突时以 `AGENTS.md` 为准，并顺手把本文件改对。
>
> 以下正文沿用原 `AGENTS.md` 的英文原文，未做改写，以免语义漂移。

## 1. 版本号 / Release & versioning

**Single source of version truth: `Cargo.toml` → `[package] version`.** There is no second **source** — but there are **derived files**,
  so a bump is not a one-line edit:

- **Bump with `make set-version VERSION=X.Y.Z[-pre]`** (= `scripts/set-version.sh`), never by hand. One command rewrites `[package] version`,
  re-resolves `Cargo.lock`, regenerates `docs/openapi.json` (`CRABMATE_BLESS=1`) and both `man/*.1` pages (`crabmate-gen-man`),
  then prints the suggested `## [X.Y.Z]` heading + link-reference line for `CHANGELOG.md` (the prose stays hand-written).
  It **writes files only** — no commit, no tag, no push. Re-running it with the current version is the supported way to
  re-sync the derived files.
- **`scripts/check-version-sync.sh`** guards the result (pre-commit hook `check-version-sync` + a step in `ci.yml`):
  it asserts `docs/openapi.json` → `info.version`, both `man/*.1` version strings and the `Cargo.lock` entry equal
  `[package] version`, and says `derived file X says A, Cargo.toml says B` — unlike `openapi_docs_snapshot_matches_spec`,
  which only runs in the `client-contract` job and reports `drifted (fields: ["info"])`, and unlike the man pages,
  which previously had **no** signal at all (#1269).

- **Tag format**: `vX.Y.Z`, optionally `vX.Y.Z-rc.N`. `.github/workflows/release.yml` rejects anything not matching
  `^v[0-9]+\.[0-9]+\.[0-9]+([.-].*)?$`, and **fails the run** when the tag's core `X.Y.Z` does not match `Cargo.toml`.
  A prerelease tag (`v0.1.0-rc.1`) is allowed while `Cargo.toml` stays at `0.1.0`.
- **Cut the CHANGELOG before tagging**: the workflow extracts the `## [X.Y.Z]` section from `CHANGELOG.md` as the GitHub
  Release body; a missing section yields a stub body plus a warning. So “move `[Unreleased]` into `## [X.Y.Z]`” is part
  of the release, not an afterthought.
- **Pushing the tag is the release**: it builds the `tar.gz` / `.deb` artifacts and creates or updates the GitHub Release
  (re-running the same tag updates the existing one; `workflow_dispatch` accepts an existing tag for a manual rebuild).
  Local equivalent for verification: `make package` → `dist/`.
- **Local packaging must stay warning-free** (#1363): `make package` / `make package-deb` should print **no**
  `warning:` lines. A warning there is manifest drift, not packaging noise — `cargo::redundant_homepage` (a
  `homepage` that only repeats `repository`), `cargo::unused_dependencies` (a declared-but-unreferenced dep;
  #1363 removed `urlencoding` this way) — or a `警告:` line from `scripts/package-release.sh` itself (e.g. it
  could not find a `.deb` under `target/debian/`). `cargo-deb` 3.6.3 and `dpkg-deb` added none of their own.
- `client-contract-v*` tags belong to the **Client repo** (`crabmate-client`) contract pin and are outside this repo's
  release flow — do not reuse this repo's `v*.*.*` tags for it.
- A change that breaks config keys, SSE/HTTP contracts or the public CLI is a **breaking change**: mark it in the commit
  subject (`!` or `BREAKING CHANGE:` footer) **and** call it out in the CHANGELOG entry. See `AGENTS.md` §4.7
  「Architecture & documentation sync」 for the docs that must move with it.

## 2. CHANGELOG

`CHANGELOG.md` follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and is **English-primary**
  (matching `README.md`). Entries accumulate under `## [Unreleased]`, grouped as `Added` / `Changed` / `Deprecated` /
  `Removed` / `Fixed` / `Security`; the release step moves them into a version section (see 第 1 节).

- **Must be recorded**: user-visible behavior (CLI flags, routes, config keys, `CM_*` env vars, tool add/remove/rename,
  SSE/HTTP contract changes), behavior fixes, dependency changes with user impact, and every breaking change.
- **Need not be recorded**: internal refactors with no behavior change, comments, tests, formatting, typo fixes in docs,
  and `agent_space/` drafts.
- Write the **why and the user-visible consequence**, not a restatement of the diff. Long entries are acceptable here
  (existing entries run to a full paragraph); keep secrets, keys and internal hostnames out.
- Going forward from a deleted/deprecated capability, say so explicitly (`Removed`) rather than silently dropping the
  line — the D2.2 `repl` / `chat` / `tui` removal is the reference case.

## 3. 依赖与许可证 / Dependencies & licenses

Triggers: edits to the root `Cargo.toml` / `Cargo.lock` (new crate, major bump, new feature); shell dependencies live
  in the Client repo (`../crabmate-client/desktop-tauri/src-tauri/Cargo.toml`).

- Check the new crate's **license** against how the project is distributed; watch **copyleft** (GPL) and **network
  clauses** (AGPL). `deny.toml` backs `cargo deny check licenses bans sources`
  (CI: `.github/workflows/dependency-security.yml`) — a new identifier not in the allowlist means updating `deny.toml`
  **with a stated reason**.
- `cargo audit` covers known vulnerabilities; it and `cargo deny` advisories are intentionally split (see `docs/开发文档.md`).
- Keep lockfiles (`Cargo.lock`, `package-lock.json`) consistent with the manifests so reproducible builds hold.
- Local path / git dependencies: explain the source and update strategy in the PR or `docs/开发文档.md`.
- This is not legal advice; material compliance decisions need a human.
