## Web 身份与账号体系（不在 CrabMate 进程内实现）

**共识**：**不在 CrabMate 内做按用户账号体系**（注册登录、JWT 会话、按 `user_id` 隔离会话存储等）。进程内保持 **`web_api_bearer_token`** / **`CM_WEB_API_BEARER_TOKEN`** 的**共享密钥**模型：`Authorization: Bearer …` 或 `X-API-Key …` 与配置值做常量时间比对，通过即视为「已授权调用方」，**不区分自然人**。实现见 **`src/web/chat_handlers/auth.rs`**。

**推荐部署形态**：在 CrabMate **前面**放置已具备账号体系的 **API 网关、反向代理或 BFF**（OAuth2/OIDC、Keycloak、Authentik、云厂商 API 网关等），由网关完成登录、配额、审计；再向 CrabMate 注入凭证：

1. **模式 A（常见）**：网关校验终端用户后，为下游请求附上与本进程配置的 **`web_api_bearer_token` 相同的 Bearer**（或由 BFF 持有该机密并代发）。CrabMate 仍只见「单一服务级密钥」；**租户 / 用户隔离**在网关与上游业务系统中完成。适合「每租户独立部署 CrabMate」或「BFF 统一代填机密」。
2. **模式 B**：网关终止 TLS 与用户会话后，内网到 CrabMate 使用**固定共享密钥**，并由网关写入 **`X-User-Id` 等头**表达身份。**注意**：CrabMate **当前不消费**此类信任头做授权；若自行扩展，必须保证**仅可信内网**且请求**无法绕过网关**伪造头，否则等同后门。

**与上游 LLM 密钥**：环境变量 **`API_KEY`**（或 Web **`client_llm.api_key`**）仅用于调用 **`chat/completions`** 等上游，与「谁在用 CrabMate HTTP API」是两条线；网关侧可按租户转发不同上游密钥属于网关/BFF 职责。

**可选演进（仍非「进程内账号」）**：若将来在仓库内做**极小**改动，可考虑「多枚服务级 API Key → 租户 id 映射」等，仍与完整账号体系不同；若需每用户会话落库隔离，应优先在 **BFF + 独立存储** 或 **多实例** 上解决，而非在 Agent 核心内复制 IdP。

**相关文档**：**`docs/design/web_api_integration.md`**（桥接、多租户与网关分工）、**`docs/配置说明.md`**（Web API 鉴权与热重载边界）。

## 观众角色（编排层侧向点评）

**共识**：在**不替代**确定性验收（**`acceptance` / `step_verifier`** 等）的前提下，可选增加**无工具**侧向 LLM 调用，对规划—执行—反思链路的片段做**结构化分析与评价**，以提升可观测性、可选驱动有界重写，并与现有 **`final_plan_semantic_check_*`** 明确分工。

**设计草案（锚点、输入脱敏、输出 schema、分阶段落地、与 `plan_rewrite` 关系）**：**`docs/design/audience_critic_role.md`**。

**实现跟踪**：落地任务见 **`docs/待办清单.md`** → **`agent/`** 章「观众角色（侧向点评）」。

## Web / 桌面内置 IDE 模式

**共识**：内置「对话 / 编辑器」是 **Agent 工作流的可视编辑面**（轻编辑、变更审阅、与 SSE 写盘对齐），**不是**第二套 VS Code。完整 IDE / 多语言 LSP 体验优先外置编辑器或官方扩展。

**完善规划（基线、Phase 0–5、与扩展分工）**：**`docs/design/ide_mode_roadmap.md`**。并行路线：**`docs/design/vscode_extension.md`**。

## 能力差距与演进优先级（改进建议摘要）

对照主流开源 Agent（CrewAI、AutoGen、Mastra、LangChain Agents 等），以下差异不进入 `docs/待办清单.md`，按优先级排序供社区参考；权威细节见各条所指文档。

### P0 — 安全性（部署与网关）

| 改进项 | 状态 |
|--------|------|
| Web API 共享密钥与网关分工 | **已文档化**（见上文「Web 身份与账号体系」；`doctor` 含 serve 部署检查；写工具审计默认开启） |
| 工作区路径 TOCTOU（`openat2` + `RESOLVE_IN_ROOT` 贯通读/写/删） | **已落地**（残余风险见 `src/workspace/path.rs`） |

### P1 — 架构（多 Agent 与自主 Agent）

| 改进项 | 难度 |
|--------|------|
| 多 Agent 协作框架（Agent 实例抽象 + 共享消息总线/队列，参考 CrewAI Role-based Agent + Task） | 高 |
| 主动型自主 Agent 模式（目标 → 自主循环至完成，可结合 `workflow_execute` DAG） | 高 |
| MCP Server 暴露（stdio 已落地 `crabmate mcp serve`；剩余 streamable HTTP 出口与传输鉴权） | 低–中 |

### P2 — 体验与可观测性

| 改进项 | 难度 |
|--------|------|
| Benchmark 评测落地（在 `crabmate bench` 上跑 SWE-bench / GAIA / HumanEval，见 **`docs/基准测试规划.md`**） | 中 |
| 可视化 Workflow 编辑（DAG 节点编辑器，复用 `workflow_execute` schema） | 高 |
| 多级自我修复 / 重规划（逐工具重试 → 逐步回退 → 整规划重写，基于 `plan_rewrite`） | 中 |
| Token / 费用估算（token 侧部分落地；剩余上游 `usage` 元数据透出与费用估算） | 低 |

### P3 — 生态与扩展性（中长期）

| 改进项 | 难度 |
|--------|------|
| 外部向量库支持（Qdrant / pgvector adapter，解耦 `long_term_memory_store` 为 trait；多租户键与网关身份同向，见上文） | 中 |
| 外部可观测平台集成（OpenTelemetry trace export，与 Chrome Trace 共用 span 模型） | 低 |
| 云端扩缩容（Redis/SQS 替代进程内 mpsc；会话共享需统一存储层） | 高 |

### 推进节奏

- **近期**：Web 鉴权与部署边界（确认生产启用 `web_api_require_bearer=true` 与非空密钥，身份与配额在网关完成）+ Benchmark 基线（`crabmate bench --benchmark swe_bench`，结果记入 **`docs/BENCHMARK_RESULTS.md`**）。
- **中期**：MCP streamable HTTP 出口（对齐 Web bearer 策略）+ 多 Agent 协作框架设计（先做单进程内逻辑角色分离，再演进为独立实例）。
- **远期**：可视化编排 UI + 云端扩缩容（前端工程与分布式改造，按用户量增长驱动）。

### 能力对照（现状）

| 能力维度 | 主流方案代表 | CrabMate 现状 |
|----------|------------|--------------|
| 多 Agent 协作 | CrewAI、AutoGen | 仅单 Agent（`logical_dual_agent` 为逻辑角色分离，非独立协作） |
| 可视化编排 | Mastra、Flowise、LangFlow | 无 UI 编排器 |
| Benchmark 评测 | SWE-bench、GAIA、HumanEval | 框架就绪，待落地 |
| 外部向量库 | Qdrant、pgvector、Pinecone | 仅 fastembed 本地 |
| MCP 双向 | MCP 生态 | client 侧 + server stdio（`mcp serve`）已通；streamable HTTP 出口待实现 |
| Token / 费用估算 | LangChain Usage Tracking | token 预算 / 上下文芯片已落地；费用估算未实现 |
| 主动型自主 Agent | AutoGPT、BabyAGI | 响应式，工具按需调用 |
| 多级自我修复 | AutoGPT 内置重试、LangChain Plan-and-Execute | 基础规划重写（`plan_rewrite`），待增强 |
| 云端扩缩容 | Mastra、CrewAI 云部署 | 单进程，分布式待实现 |
| 外部可观测平台 | LangSmith、OpenTelemetry | 仅 Chrome Trace |
| API 鉴权（按用户账号） | — | 进程外（网关 / BFF）；见上文 |
