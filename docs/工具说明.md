# CrabMate 内置工具参考

**演进参考**（工具调用层能力规划、与单工具条目实现进度脱钩）：**[`docs/design/tool_calling_evolution.md`](design/tool_calling_evolution.md)**（对标开源 Agent 的并行编排、沙箱、观测、MCP、人机协同等维度；工单仍以 **`docs/待办清单.md`** 为准）。

本文档列出各内置工具的能力说明，以及常见 Function Calling JSON 参数示例与发布检查排障指引。Web 工作区、流式与会话导出等行为说明仍在根目录 [`README.md`](../README.md)「功能概览」中；日常使用与入门亦见该文件。

**可选「解释卡」**（配置 `tool_call_explain_enabled`）：启用后，凡**非只读**内置工具（与 `tool_registry::is_readonly_tool(&AgentConfig, name)` 一致，含 `run_command`、`terminal_session`、`cargo_test`、`cargo_run`、`pytest_run`、写文件、`http_request`、**`gh_api`**、git 写操作、`workflow_execute` 等；**`[tool_registry] write_effect_tools`** 可覆写只读判定）调用时，须在 JSON **顶层**增加字符串字段 **`crabmate_explain_why`**，用一句自然语言说明本步目的；服务端校验长度后**执行前会剥离**该键，避免与 `additionalProperties: false` 冲突。只读工具与 MCP 代理工具不要求；MCP 调用仍会剥离该键再转发。与命令/HTTP **审批**互补（审批管授权，解释卡管可理解性）。

**长输出进模型上下文**（`tool_result_envelope_v1` 默认开启）：写入历史的 `role: tool` 为 **`crabmate_tool`** JSON 信封（`summary`、`output` 等）。可选 **`structured_payload`**：**`schema`** 含 **`run_command_exit_v1`**（**`run_command`**：`invocation`、`exit_code`、`stdout_nonempty` 等）、**`subprocess_exit_v1`**（**`cargo_*`**：首行 `{title} (exit=N):` 解析出的 **`title`**、`exit_code`、`ok`）、**`http_tool_response_v1`**（**`http_fetch`** / **`http_request`** 成功响应：解析 **`method:`** / **`请求 URL:`** / **`状态:`**；白名单/失败文案路径通常无此块）。另含 **`tool_call_id`**、**`execution_mode`**（`serial` / `parallel_readonly_batch`）、**`parallel_batch_id`**（同批并行只读工具共享）；失败时含 **`error_code`**、**`failure_category`**（与 **`tool_result::ToolFailureCategory`** 蛇形字符串同源，由 `error_code` 推导，见 **`docs/SSE协议.md`**）、**`retryable`**（与 `error_code` 配套的**启发式**，非保证）。**并行只读批**内各工具使用与串行 **`dispatch_tool`** 对齐的**墙上时钟**（`tool_registry::parallel_tool_wall_timeout_secs`，如 **`http_fetch`** 取 **`http_fetch_timeout_secs` 与 `command_timeout_secs` 的较大者**，**`get_weather` / `web_search`** 用各自超时，其余多为 **`command_timeout_secs`**）；超时时输出含「超时」文案，**`tool_result.error_code`** 为 **`timeout`**。每次请求模型前若超过 **`tool_message_max_chars`**，服务端对 **`output`** 做**首尾采样**并设置 **`output_truncated`**、**`output_original_chars`**、**`output_kept_head_chars`**、**`output_kept_tail_chars`**，避免单次 grep/构建日志撑满上下文；完整原文仍可通过 SSE/导出等在会话中查看（视 UI 设置）。SSE **`tool_result`** 事件含相同关联字段，与信封对齐；**`tool_result.structured_preview`** 可为 **`crabmate_tool_output`** 首行副本、**`structured_payload`**，或二者合并为 **`tool_output_header`** + **`structured_payload`**。执行前 SSE **`tool_call`** 另含 **`arguments_preview`**（与 `execute_tools` 日志同源的单行截断）；配置 **`sse_tool_call_include_arguments`**（**`CM_SSE_TOOL_CALL_INCLUDE_ARGUMENTS`**）为真时再下发启发式脱敏后的 **`arguments`**（更长上限，仍非全文保证）。详见 **`docs/开发文档.md`**、**`docs/SSE协议.md`** 与 **`docs/配置说明.md`**。**工具失败透明重试**（配置 **`[tool_registry] tool_retry_*`**，默认关闭）：开启后，只读且免交互审批的工具（**`http_fetch`** 需 URL 已匹配 `http_fetch_allowed_prefixes`、**`read_dir`** 需非外部路径；**`codebase_semantic_search`** 等参数可写副作用的工具硬排除）对瞬时类错误（默认 **`timeout`** / **`http_timeout`** / **`rate_limited`** / **`http_network_error`**）在分发层**透明重试**，退避 **`min(backoff*2^(n-1), 5000)`**，失败中间态**不进入模型上下文**，仅最终结果写回；重试期间用户取消立即停止。详见 **`docs/配置说明.md`**。

**`run_command` + Web diff 预览**：当 **`标准输出：`** 段为 **git unified diff**（首条非空行以 **`diff --git`** 或 **`diff --cc`** 开头），或命令行为 **`git … status`**（跳过 **`-C` / `--git-dir`** 等全局参数后子命令为 **`status`**）且 stdout 呈常见 **`git status`** 形态（如 **`On branch` / `##` / `位于分支`**、**`nothing to commit`**、**`Changes not staged`**、**`?? `** 等短状态行）时，SSE **`tool_result.structured_preview`** 会附加与写文件工具同形的 **`workspace_write_diff`** 预览头，Web 工具卡复用「变更预览（unified diff）」区块（单段 stdout 体积仍受预览上限约束）。

**工具输出头 `ok`（状态判定契约）**：写盘类工具（**`create_file`** / **`modify_file`** / **`copy_file`** / **`delete_files`** / **`append_file`** / **`search_replace`** / **`apply_patch`** 等）在 **`crabmate_tool_output`** 首行显式写入 **`ok`**，解析工具状态时**优先**采用该值；仅旧输出缺少 **`ok`** 时才回退到正文关键词启发式。失败且无 diff 文件时仍会写头（**`files`** 为空数组），因此「报错但文件实际已写入」这类误判不再发生。详见 **`docs/SSE协议.md`**。

**外部 CLI 未找到**：依赖本机可执行文件的工具在子进程 **`ENOENT`（未找到）** 时，除「请确认 PATH」外，还会在输出末尾附带**简短安装/验证示例**（常见为 `apt`/`brew`/`pip` 或官方文档链接）；覆盖范围包括 **`run_command`**（白名单内命令名）、**`gh_api`** 的 `gh`、`format_*`（如 `rustfmt`/`clang-format`/`npx`/`gofmt`/`shfmt`/`xmllint`）、**`python_snippet_run`**（`python3`/`uv`）、**`git`** 前置探测及 **`cargo audit`/`cargo deny`** 启动失败等；未内置映射的程序仍仅保留通用说明。

**会话工作区变更集**（默认开启，`session_workspace_changelist_*`）：对 **`create_file` / `modify_file` / `copy_file` / `move_file` / `delete_files` / `append_file` / `search_replace` / `apply_patch` / `structured`（`action=patch`）**（实际写入成功）按会话作用域累积**相对路径**与相对「本会话首次触碰」的 **unified diff**；在**每次**向模型发请求前注入一条 **`user`**（**`name=crabmate_workspace_changelist`**），便于后续轮次优先引用真实改动路径。Web 保存会话前会**剥离**该条（与长期记忆注入同理）。**`workflow_execute` DAG 内**工具不在此表（独立 `ToolContext`）。

**终答 `agent_reply_plan` v1**（在工作流反思等路径下由服务端校验）：`steps[].id` 须唯一且符合稳定字符规则（见 **`docs/开发文档.md`**）；可选 **`workflow_node_id`** 用于与最近一次 **`workflow_execute`** 工具结果里的 **`nodes[].id`** 对齐（子集校验），便于规划与 DAG 节点一一对应。可选 **`steps[].executor_kind`**（`review_readonly` / `patch_write` / `test_runner`）以步级收窄可见工具并拒绝越权调用（越权时工具结果含本步允许名摘要）；**`[tool_registry]`** 可用 **`sub_agent_*`** 键扩展默认补丁/测试名单或只读步拒绝表，详见 **`docs/配置说明.md`**。

**步级验收 `acceptance`**（由 **`step_verifier.rs`** 校验）：对**本分步**内、自该步分步 `user` 起至下一条 `user` 前**最后一条** `role: tool` 做断言（多工具时通常对**本步最后一条**工具输出验收，或拆步）。可选 **`steps[].acceptance`** 对象支持以下确定性规则：
- **`expect_exit_code`**：期望的退出码（如 `cargo test` → 0）
- **`expect_stdout_contains`**：stdout 期望包含的字符串
- **`expect_stderr_contains`**：stderr 期望包含的字符串
- **`expect_file_exists`**：期望存在的文件路径（相对于工作区）
- **`expect_json_path_equals`**：JSON path 验证（对象须含 `path` 与 `value` 字段）。**Legacy**：`$.field.nested`、`$[0].field`、`$.items[0][1]`（单段内可多组 `[下标]`）；空白 `path` 表示整段输出 JSON。**RFC 6901 JSON Pointer**：以 `/` 开头（如 `/data/items/0/name`），键名含 `/`、`~` 时用 `~1`、`~0`。失败时区分非法 JSON、路径语法错误与路径不存在（见验收失败文案前缀 `invalid_json:` / `invalid_path_syntax:` / `path_not_found:`）。
- **`expect_http_status`**：HTTP 状态码（对 `http_request`/`http_fetch` 类工具生效）

验收失败时触发**补丁规划轮**，可通过 **`max_step_retries`** 控制本步重试次数，通过 **`transitions`** 定义 `on_verify_fail` 等条件跳转。失败文案常见机器可读前缀包括 **`exit_code_mismatch:`**、**`stdout_missing:`** / **`stderr_missing:`**、**`combined_output_missing:`**（分层子目标合并输出场景）、**`file_not_found:`**、**`json_path_mismatch:`**、**`http_status_mismatch:`** 等，补丁 **user** 中会随 `step_verifier` 结果一并回灌。

**可选 Docker 沙盒**（`sync_default_tool_sandbox_mode = docker`）：**SyncDefault** 与 **`run_command` / `run_executable` / `get_weather` / `web_search` / `http_fetch` / `http_request`** 在宿主完成审批/白名单后，在 **一次性 Docker 容器**内执行（经 **bollard** 调 Engine API）；**`workflow_execute`** 与 **MCP** 仍只在宿主。须本机 **Docker 守护进程可访问**，并设置非空的 **`sync_default_tool_sandbox_docker_image`**：镜像需含你实际会用到的 CLI（`git`、`rg`、`cargo` 等），且与**宿主 `crabmate` 二进制同 CPU 架构**（二进制由服务端只读挂入容器，仓库不附带固定镜像）。默认容器 **无网络**（`docker_network` 为空）；需天气/搜索/HTTP 出网时配置 **`sync_default_tool_sandbox_docker_network`**（如 `bridge`）。**启用步骤、示例 Dockerfile、环境变量与安全提示**见 [`docs/配置说明.md`](配置说明.md)「SyncDefault 工具 Docker 沙盒」。

## 内置工具（模型可调用）

**`run_command` 与 `terminal_session` 选型（减少误选）**：非交互、一次性命令（构建、查询、脚本跑完即退出）优先 **`run_command`**；仅当程序依赖 **TTY**（全屏交互、原始终端控制、需在**同一伪终端**内多轮输入输出）时使用 **`terminal_session`**（仅 Linux；**`sync_default_tool_sandbox_mode = docker`** 下不可用）。勿用 **`terminal_session`** 代替普通批处理命令。

**`run_command` 超时与取消**：墙上时钟默认 **`command_timeout_secs`**（可用 **`CM_COMMAND_TIMEOUT_SECS`** 覆盖），单次可用参数 **`timeout_secs`**（1～600，越界钳制）覆盖。到期、用户取消或 SSE 关闭时，对子进程**进程组**发送 SIGTERM，短等待后 SIGKILL（Unix）；工具正文带已截断的部分 stdout/stderr，信封 **`error_code`** 为 **`timeout`** / **`cancelled`**（`timeout` 启发式 `retryable`）。宿主路径执行中会按块下发已有 SSE **`tool_output_chunk`**（`tool_call_id`、单调 **`seq`**、`stream`=`stdout`/`stderr`；**不**进模型上下文，总量仍受 **`command_max_output_len`** 约束）。进度块按**管道读到的先后**排队（非 PTY 精确交错）；Client 若忽略 `stream` 会把两路拼成一段。SSE 通道满时会留下增量下一轮再发，不跳号。workflow 节点目前仅 **`run_command`** 在工具内 reap（**不下发** chunk）；其它节点超时仍可能留下 `spawn_blocking` 子进程。Docker 沙盒内进程不在本刀保证范围。实现见 **`docs/design/long_running_tool_execution_todo.md`**。

**复合 shell（glob / `$VAR` / `~` / `&&` / `|` 等）**：`command` + `args` 会拼成**完整脚本**。当 **`allowed_commands` 含 `bash` 或 `sh`**（嵌入默认二者都有）时，glob/`$VAR`/`~` 经 **`bash -c` / `sh -c`** 执行。独立 argv 中的 **`&&` / `||` / `|` / `;`** 也会包装，但 **Web 即使 bash 已在白名单也会再审该脚本**（避免 `ls && rm` 绕过单命令白名单）。无审批通道且 bash 已在白名单时仍自动包装。**不在白名单的命令**以及**白名单无 bash/sh 但仍需展开**时，Web 审批对象为该整行脚本（通过后本次把 `bash` 加入允许列表）。无展开的简单 argv（如 `git status`）仍直接 `execve`。生产若要禁止任意脚本，从白名单去掉 **`bash`/`sh`**。**`terminal_session`** 首轮 **`exec`** 同理。**反引号与 `$()` 命令替换不触发包装，也不会被执行**：需要包装时它们会被转义为字面量（如提交信息 ``fix `id` `` 原样保留）；确需命令替换时请用显式 **`script`** 或 **`bash -c`**。

**`run_command` 先换工作区子目录**：可用 **`command` 为 `cd`**、**`args` 为 `["相对子目录","&&",后续命令名,…]`** 的形式（`相对子目录` 须已存在；路径穿越形 `..`/`../` 与工作区外绝对路径默认经 **`allow_external_path_with_approval`** 人工审批后放行，设 `false` 则仍拒绝；**git** `A..B` 不算穿越）。实现会换目录后执行后续参数（先剥 `cd`，不把 `cd` 当独立可执行）。后续 argv 若需 glob/`$VAR` 且白名单含 **`bash`/`sh`**，再经 **`bash -c`**。**新写法**：可直接用可选字段 **`cwd`** 指定工作区相对子目录（等价 `cd` 前缀）；绝对路径或含 `..` 的 `cwd` 在解析阶段即报错；目录不存在直接报错；若 `cwd` 经符号链接落到工作区外，由 **`allow_external_path_with_approval`** 决定（开启时可人工审批放行，关闭则拒绝）。

**`run_command` 显式 `script`**：可选字段 **`script`** 用一行 shell 脚本代替 `command` + `args`，二者**互斥**（同时提供非空 `command`/`args` 会直接报错）。`script` 需白名单内存在 **`bash`** 或 **`sh`**，否则报错；脚本正文不逐 argv 审计，但**未获信任时须经 shell 审批**（审批展示完整脚本），无审批通道时按白名单决定是否放行。旧的 `command`/`args`、`cd` 前缀、`bash -c` 写法保持完全兼容。

**`run_command` 归一化回显（`rewrites`）**：当参数触发解析期归一化（如 `./` 合并、内嵌命令拆分、`cd` 前缀剥离）时，内部会记录改写项。设置环境变量 **`CM_RUN_COMMAND_ECHO_REWRITES=1`**（等同 `true`/`yes`/`on`）后，这些改写会以 **`[rewrite] …`** 追加在工具输出**末尾**；默认关闭时输出与旧版逐字一致。

- **内置多种工具，由模型按需调用**：
  - `get_weather`：获取指定城市/地区当前天气（[Open-Meteo](https://open-meteo.com/) API，无需 Key）。
  - `web_search`：**联网网页搜索**。默认 **`web_search_provider = worbrow`**（经 [worbrow](https://crates.io/crates/worbrow) **≥0.2.0** 驱动本机 **Firefox / Chrome/Edge** headless；引擎链 **bing→duckduckgo**；**无需 API Key**；亦接受别名 `browser`；结果可含广告/词典等质量标记）。可选 **`brave`**（[Brave Search API](https://brave.com/search/api/)）或 **`tavily`**（[Tavily](https://tavily.com/)），此时须配置 `web_search_api_key` / `CM_WEB_SEARCH_API_KEY`。无可用浏览器且未配置 API 路径时工具返回说明性错误。仓库内**精确**字符串/正则匹配优先用 `search_in_files`；**混合全文+语义**检索用 `codebase_semantic_search`（SQLite **FTS5** + 向量，默认 `retrieve_mode: hybrid`；须先 `rebuild_index`，见下文与 **`docs/配置说明.md`**）。
  - `http_fetch`：对给定 URL 发起 **GET**（默认）或 **HEAD**。GET 返回状态、Content-Type、**重定向链**与正文（有超时与体长上限）；**HEAD** 不下载 body，仅状态码、Content-Type、Content-Length 与重定向链。正文解码：`Content-Type` 的 **`charset`**、HTML **`<meta charset>`** / **http-equiv=Content-Type**、`<?xml encoding=…?>`，否则 **`chardetng`** 嗅探；`application/json` 等优先按 UTF-8；`image/*` 等二进制类型仍按 UTF-8 有损预览。可选 **`text_format: html_text`**：用 **`scraper`（html5ever）** 将 **HTML 文档**转为纯文本（跳过 `script`/`style`/`noscript`，优先 `main` / `article` / `[role=main]`，否则 `body`）；非 HTML 或 JSON/二进制仍输出解码原文，并在「正文解码」说明中注明。请求向 curl 对齐：自动发送 **`Accept: */*`** 与 **`Accept-Encoding`**（gzip/brotli/deflate，响应体自动解压）；**`User-Agent`** 默认 **`crabmate/<版本>`**，可经 **`http_fetch_user_agent`** / **`CM_HTTP_FETCH_USER_AGENT`** 覆盖（如浏览器/curl UA 以应对反爬站点）。环境代理遵循 **`ALL_PROXY` / `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`**（HTTP(S) 代理正常；**reqwest 0.13 不支持 SOCKS**，遇 `socks5://` 代理会失败并提示 unset 或改用同端口 `http://` 代理）。**URL 闸门**：`http_fetch_allowed_prefixes` 含 **`"*"`** 时任意 **http/https** 直接执行（嵌入默认；**仍拒绝** `file:` 等方案）。否则须匹配**同源 + 路径前缀边界**。不匹配时，**仅 Web**（`/chat/stream` 携带 `approval_session_id`）可经 SSE 人工审批 **拒绝 / 本次允许 / 永久允许**（GET/HEAD 共用同一归一化白名单键；运维 CLI 无同进程终端审批）。**`"*"` 会让模型拉取环回/内网/云元数据 URL**（SSRF）；多租户或把 `serve` 暴露到不可信网络时请改回具体前缀，或 **显式** `http_fetch_allowed_prefixes = []` / 空 `CM_HTTP_FETCH_ALLOWED_PREFIXES` 覆盖嵌入默认（空=全部走审批）。`http_request` 共用同一列表。**失败错误码**：`http_fetch` / `http_request` 失败正文首行带显式标记 `错误[码]：`（服务端据此精确归类）——连接/DNS 失败为 **`http_network_error`**、请求超时为 **`http_timeout`**（信封 `retryable=true`）、读取响应体失败为 **`http_body_read_error`**；`get_weather` 网络/API 失败为 **`weather_api_error`**、`web_search` 为 **`web_search_api_error`**，二者超时均为 **`timeout`**。
  - `http_request`：对给定 URL 发起 **POST / PUT / PATCH / DELETE**（可选 `json_body`）。与 `http_fetch` 共用 `http_fetch_allowed_prefixes`（**`"*"`** 放行全部 http/https；否则同源 + 路径前缀边界）。匹配则直接执行，**未匹配**时 **仅 Web**（`/chat/stream` + `approval_session_id`）可与 `http_fetch` 一样经 SSE 走 **拒绝 / 本次允许 / 永久允许**（永久键为 `http_request:<METHOD>:<URL>`，与 `http_fetch:` 键区分；两者实际落进集合时都带**等级作用域前缀**，如 `l3|http_fetch:https://…`——命中要求等级**严格相等**，会话降到 `workspace` 后旧批示不再放行，见 `docs/配置说明.md` 的「权限等级」）。**`workflow_execute` 节点**内仍仅前缀匹配（同步路径无审批）。返回状态、Content-Type、重定向链与正文（解码与可选 **`text_format: html_text`** 与 `http_fetch` 相同；默认建议先 dry-run，不在 body 中放真实密钥）。
  - **GitHub CLI 封装**（须本机 **`gh`** 且 **`allowed_commands` 含 `gh`**）：**PR**：**`gh_pr`**（按 **`action`** 分发：`checks`（可选 **`structured: true`** 附失败摘要）/ `create`（**写远端**；省略 **`body`** 时默认 **`auto_body`** 从模板 + git log 生成）/ `merge` / `review` / `comment` / `edit`（**写远端**）/ `body_draft`（只读正文草稿））；**Issue**：**`gh_issue_create`**（写远端）；**Actions**：**`gh_run`**（`action=failure_summary` 失败 job + 日志尾部，排障首选 / `action=rerun` 写远端）；**Release**：**`gh_release_create`**（写远端；可选 **`auto_notes`**）；**`gh_api`**。**退出码 0** 且 **stdout 整段为合法 JSON** 时，输出末尾附加**缩进 JSON**。`gh_pr` / `gh_run` 整体按非只读工具处理（含 `checks` / `body_draft` / `failure_summary` 这几个只读动作）。只读列表/查看/搜索类（`gh pr list` / `gh pr view` / `gh pr diff` / `gh issue list` / `gh issue view` / `gh run list` / `gh run view` / `gh release list` / `gh release view` / `gh search`）已按薄封装收敛改为通用 `run_command` 直接拼 `gh` 子命令。**失败语义**（全部 `Typed` runner，显式 `error_code`）：参数校验 → `invalid_args`；`allowed_commands` 不含 `gh` → `command_not_allowed`；本机无 `gh` → `command_not_found`；**`gh` 非零退出** → `gh_{子命令}_failed`（`pr` / `run` / `issue` / `release` / `api`）；超时或取消 → `timeout`。唯一例外是 **`gh pr checks`**：它对「有检查失败」返回 1、「仍有 pending」返回 8，这两种退出码仍按成功处理（stdout 仍是合法 JSON，失败摘要照常附加）。

执行。独立 argv 中的 **`&&` / `|` / `;`** 也会包装，但 **Web 即使 bash 已在白名单也会再审完整脚本**（避免 `ls && rm` 绕过单命令白名单）。`?` / `[` 默认不当 glob（`rg -e foo?`、`git log --pretty=format:[%h]`），仅路径形如 `file?.c` 才展开。`cd dir && git status` 先剥 `cd` 前缀。审批卡片展示完整脚本。无展开的调用仍 `execve` 白名单程序。亦可显式 **`command` 为 `bash` 或 `sh`、`args` 为 `["-c","整段脚本"]`**。若误将 **`command` 设为 `./`**、相对可执行路径放在 **`args` 首元素**（如 `{"command":"./","args":["hello/build/hello"]}` 或带程序参数 `{"command":"./","args":["build/hello","-g","Hi"]}`），服务端会**自动合并**为 **`./hello/build/hello`** / **`./build/hello`** 并把其余 `args` 留给该程序（首参须为相对路径、不以 `-` 开头，且**不得**含路径穿越形 `..`/绝对路径；**git** `A..B` 不算穿越）。已设置工作区时，若 **`command`** 为相对路径且形如 **`./…`** 或 **`foo/bar`**（**不得**含路径分量 `..`），并解析为工作区内**已存在**的可执行文件（含 Unix 可执行位）或常见脚本后缀（如 `.sh`、`.py`、`.js` 等），则**跳过**「命令不在白名单」时的 Web SSE 人工审批（与「本次允许」等效，**不**写入永久允许列表）；裸命令名（如 `gcc`）仍一律按白名单与既有审批逻辑处理。其余：执行白名单内的只读/查询类 Linux 命令（`ls`、`pwd`、`whoami`、`date`、`cat`、`file`、`head`、`tail`、`wc`、`cmake`、`ctest`、`mkdir`、`ninja`、`gcc`、`g++`、`clang`、`clang++`、`c++filt`、`autoreconf`、`autoconf`、`automake`、`aclocal`、`make`，以及 **GNU Binutils 常用只读分析**：`objdump`、`nm`、`readelf`、`strings`、`size`；开发环境默认另含 `ar` 等），带超时与输出截断。**参数路径安全**：工作区内绝对路径会归一成相对路径；**`cmake` 的 `..`** 为合法特例。argv 含工作区外绝对路径或 `..` 时，嵌入默认 **`allow_external_path_with_approval = false`** 则仍无条件拒绝。无审批通道（workflow/MCP/运维 CLI 等）、**Docker** 沙盒模式仍拒绝。本机制**不**审计 `bash`/`sh -c` 脚本字符串内部路径。**GitHub CLI**：默认白名单含 **`gh`**（需本机安装并完成 `gh auth login`   - **写盘前校验（`write_precheck`）**：`create_file` / `modify_file`（`mode=full/overwrite`）/ `append_file` / `search_replace` 写盘前对**将写入的内容**按扩展名做语法冒烟：`.py`（Python `compile`，覆盖 `IndentationError` 缩进错误与 `return outside function` 等）、`.json`（`serde_json`）、`.toml`（`toml`）。失败默认**拒写**，返回 `校验失败（CODE）：path:行: 信息`（`CODE` 为 `PY_SYNTAX_ERROR` / `JSON_SYNTAX_ERROR` / `TOML_SYNTAX_ERROR`；工具信封 `error_code` 为 **`write_precheck_failed`**、`failure_category=invalid_input`），便于模型按行号自纠错后重试。`skip_precheck=true` 可显式绕过（渐进式编辑/中间态）；校验器缺失（如无 `python3`）或超时则自动跳过、不阻塞写盘。`modify_file` 的 `replace_lines` / `insert_after_line` 为局部流式编辑，暂不校验。
  - `read_dir` / `glob_files` / `list_tree`：列单层目录；按 glob（如 `**/*.rs`）递归匹配文件路径；递归列树（`max_depth` / `max_entries` 有上限，路径不出工作区）。**`read_dir`** 与 **`list_tree`** 成功时正文首行均为 **`crabmate_tool_output` v1**（`tool` 分别为 **`read_dir`** / **`list_tree`**），与 Web SSE **`tool_result.structured_preview`** 同源。

  - `markdown_check_links`：扫描 Markdown（默认 `README.md` 与 `docs/`），校验**相对路径**链接与 `#fragment` 锚点；支持 `output_format=text|json|sarif`。`http(s)://` 外链默认不联网，可选 `allowed_external_prefixes` 对匹配 URL 做 HEAD 探测（同 URL 去重缓存）。

  - `structured`：结构化数据处理，按 **`action`** 分派（`validate` / `query` / `diff` / `patch`）——校验、按路径取值、键路径级结构化 diff，以及对 **JSON / YAML / TOML** 做定点 `set`/`remove`（`action=patch` 默认 dry-run，显式 `dry_run=false` 即写盘；子动作用 **`mutation`** 选 `set`/`remove`）。CSV/TSV 仍用于校验/查询/diff，不支持结构化写回。**该工具整体按写处理**（合并的既定代价）：`action=validate` / `query` / `diff` 不再享有并行只读批、只读重试与 `Ask`·`Plan` 只读门控，`ReviewReadonly` 步也调不到它。

  - **后台任务查询**（同一会话内取回以 `async: true` 启动的长任务结果（`run_command` / `cargo_test` / `pytest_run`）；直接读进程内注册表，不走白名单审批）：`background_job`（**按 `action` 分发**，三个动作均只读，`status` / `output` 必须传 `tool_job_id`；与本 `action` 无关的字段会被忽略，但 `limit` 无论 action 都受 1–100 约束（超出即参数校验失败）；`status` 按 `tool_job_id` 查询状态与输出——任务未结束时返回当前状态，结束时返回退出码与 stdout/stderr；`list` 按工作区列出后台任务，最新创建在前，可传 `limit`，默认 20 / 上限 100；`output` 增量拉取输出，`tail -f` 语义；传 `tool_job_id` 与可选 `cursor`（上次返回的 `next_cursor`），返回 stdout/stderr 增量，并在文本末尾给出游标与 `eof` 标记；省略 `cursor` 从最早可用起；单次至多 500 条，未 `eof` 时请携带游标继续拉取）、`background_job_cancel`（**写副作用，故保持独立工具名**；取消后台任务：`queued` 直接转 `cancelled`，`running` 置取消标记，已是 `cancelled` 幂等成功，其它终态不可取消）。**错误码**（2026-10-28 起两者均为 Typed runner）：`invalid_args`（缺 / 空 `tool_job_id`、未知或缺失 `action`、参数形状不符）；执行上下文未注入注册表时同样返回 `invalid_args`（提示改在主对话回合调用）。此前「`参数错误：`tool_job_id` 不能为空…」既不以「错误」开头、也不含「失败 / 超时」，会被 `parse_legacy_output` 判成**成功**——模型漏传 id 却被告知查询成功，现已修正。
  - **日程与提醒**（写 `.crabmate/reminders.json` / `.crabmate/events.json`；合并前是九个独立工具）：`reminder`（**按 `action` 分发**：`list` 列出（默认不含已完成，可选 `include_done` / `future_days`）、`add`（`title` 必填，可选 `due_at`）、`update`（按 `id` 改 `title` / `due_at` / `done`）、`delete`（按 `id`）、`complete`（按 `id`））、`event`（`list`（可选 `year` / `month` / `future_days` 过滤）、`add`（`title` 与 `start_at` 必填）、`update`（按 `id`）、`delete`（按 `id`））。`update` / `delete` / `complete` 必须传 `id`；除 `list` 外均写盘，故整工具计入写副作用（不进并行只读批 / 只读 TTL 缓存 / 同轮去重缓存）。**错误码**（2026-10-28 起两者均为 Typed runner，失败路径显式返回）：`invalid_args`（参数 JSON / 必填字段缺失 / 未知或缺失 `action`）、`reminder_not_found` / `event_not_found`（`id` 不存在，归 `invalid_input`——模型可先 `action=list` 自查）、`schedule_io_failed`（建 `.crabmate` 目录 / 读 / 写失败，归 `external`）、`schedule_parse_failed`（既有 JSON 文件内容损坏）、`schedule_serialize_failed`（序列化失败，归 `internal`）。此前「`add` 缺 `title`」「缺 `id`」「`id` 未命中」三类正文不含「错误 / 失败」关键词，会被 `parse_legacy_output` 判成**成功**，现均已修正为显式失败。
  - **代码度量与分析**（只读）：`code_stats`（代码行数统计，优先 tokei/cloc，回退内置统计器）、`dependency_graph`（依赖关系图，支持 Cargo/Go/npm，输出 Mermaid/DOT/tree）、`coverage_report`（覆盖率报告解析，支持 LCOV/.info、Tarpaulin JSON、Cobertura XML）。

## 权限等级对各工具的影响

五档（`chat` / `read` / `workspace` / `approved` / `unrestricted`）经一组「能力投影」同时决定**工具是否可见**与**注册了能不能调**。设计见 [design/permission_levels.md](design/permission_levels.md)，配置键与生效顺序见 [配置说明.md](配置说明.md)「权限等级（`permission_level`：L0–L4）」。默认档是 `approved`，即引入等级之前的行为。

| 档 | 工具可见性 | 外部工具（`mcp__*` / 动态） | 路径范围 | 命令 | 出站网络 | 越界时 |
|---|---|---|---|---|---|---|
| `chat` | **不下发工具定义** | 拒 | 不可达 | 全禁 | 全禁 | 直接拒 |
| `read` | 只读工具正列表 | 拒 | 会话工作区根 | 全禁 | 按前缀白名单 | 直接拒 |
| `workspace` | 全量 | **拒** | 会话工作区根 | 白名单 | 按前缀白名单 | **直接拒，不弹审批** |
| `approved` | 全量 | 允许 | 会话工作区根 | 白名单 | 按前缀白名单 | 人工审批（AllowOnce / AllowAlways） |
| `unrestricted` | 全量 | 允许 | 任意 | 不受白名单约束 | 任意 | 不审批，只审计 |

- `run_command` / `terminal_session` / `python_snippet_run` / `run_executable` 由**命令轴**统一决定：`chat` / `read` 一律硬拒（即便模型凭历史发出调用）、`workspace` 白名单外直接拒、`approved` 白名单外弹审批、`unrestricted` 不查白名单。
- `read_file` / `write` / `read_dir` 等文件类工具经同一路径载体判定：`unrestricted` 接受绝对路径与 `..`；`chat`–`approved` 仍在会话工作区根内（`approved` 的越界走 `WorkspaceExternalPath` 审批）。
- `http_fetch` / `http_request` 由**网络轴**决定：`chat` 全禁；`read` 起按 `http_fetch_allowed_prefixes` 前缀，未命中时 `workspace` 直接拒、`approved` 弹审批、`unrestricted` 放行。
- `mcp__*` 与 `plugins/*.json` 动态工具：`chat` / `read` / `workspace` **一律拒**（工作区「硬边界」承诺）；`approved` / `unrestricted` 允许。
- **不可逆操作确认不受等级豁免**：`delete_files` / `delete_dir` 等 `permission_confirm_tools` 在 `unrestricted` 下**仍**要求 `confirm`；`run_command` 的危险 argv（`git reset --hard`、`git push --force`）也仍单独判定。
- `AllowAlways` 的持久批准键带等级前缀（形如 `l3|git`）：命中要求**等级严格相等**，把会话降档后旧批准立即失效。`http_fetch` / `http_request` 的永久键同样带前缀（如 `l3|http_fetch:https://…`）。
- 工具时间线条目（`TOOL_CALL_START.permissionLevel`）与审批弹窗（`command_approval` 的 `permissionLevel`）带上本回合等级，**只用于展示**，不参与放行判断。
- **现状边界**（未落地，见设计 §6.4 与 §12 的 S7）：`workspace_allowed_roots` 的多根放行（`PathScope::AllowedRoots`）尚未接线，因此 `workspace` / `approved` 的路径范围仍只有会话工作区根；沙盒模式下也暂不收窄网络轴，`clamped_by` 不会报 `sandbox`。


## Rust 开发工具示例

以下示例展示了常用 Rust 开发工具的结构化参数（Function Calling 参数 JSON）：

- `cargo_run`（运行二进制）：
  ```json
  {"bin":"crabmate","args":["--help"]}
  ```
- 运行单个测试用 `cargo_test` + `test_filter`（原 `rust_test_one` 已删除 —— 它只是这一写法的语法糖，且还会被误判为只读工具）：
  ```json
  {"test_filter":"tools::tests::test_build_tools_names","nocapture":true}
  ```
- **本地 CI / 发版前组合检查（已改用 `run_command`）**：原 `ci_pipeline_local` / `release_ready_check` / `quality_workspace` 三个聚合工具已按 [tool_thin_wrapper_candidates.md](design/tool_thin_wrapper_candidates.md) §8.5 整族移除，改用 `run_command`（`bash -c` 串联；`cargo` / `npm` / `python3` / `git` 均已在白名单）：
  ```json
  {"command":"bash","args":["-c","cargo fmt --all --check && cargo clippy --all-targets --all-features -- -D warnings && cargo test"]}
  ```
  ```json
  {"command":"bash","args":["-c","cargo audit && cargo deny check advisories licenses bans sources && git status --porcelain"]}
  ```
  注意：原聚合器的 `fail_fast` / `summary_only` / 分节汇总，以及「无 `Cargo.toml` 时自动跳过」等保护**不再存在**，需自行用 `&&` 串联并阅读完整输出。
- `rust_analyzer`（本机需 **`rust-analyzer` 在 PATH**；**line/character 为 0-based**，与 LSP 一致）——原本的 8 个 `rust_analyzer_*` 工具已合并为 **一个工具 + `action`**：
  ```json
  {"action":"goto_definition","path":"src/cm_tools/mod.rs","line":1195,"character":4,"wait_after_open_ms":500}
  ```
  ```json
  {"action":"find_references","path":"src/cm_tools/mod.rs","line":1195,"character":4,"include_declaration":true}
  ```
  ```json
  {"action":"document_symbol","path":"src/lib.rs","max_symbols":200}
  ```
  ```json
  {"action":"workspace_symbol","path":"src/lib.rs","query":"run_agent_turn","max_results":32}
  ```
  **`action` 取值与必填字段**：`goto_definition` / `find_references` / `hover` / `goto_implementation` / `goto_type_definition` / `document_highlight` 需 `path` + `line`（分别对应 `textDocument/definition`、`/references`、`/hover`、`/implementation`、`/typeDefinition`、`/documentHighlight`）；`document_symbol` 需 `path`（`max_symbols` 默认 500、上限 5000）；`workspace_symbol` 需 `path` + `query`（`max_results` 默认 64、上限 500）。缺/未知 `action` 会返回包含完整可选值清单的错误；`path` 缺失与 `line` 缺失的报错文案与合并前逐字一致。
  **失败与错误码**（2026-10-28 迁 `Typed`）：成功正文与合并前逐字一致；失败一律带 `error_code`，不再靠正文关键词猜——
  `invalid_args`（缺 / 未知 `action`、参数 JSON 非法、缺 `path` / `line` / `query`、绝对路径与 `..`、路径越界或指向非文件、文件 >512KiB）、
  `rust_analyzer_file_not_found`（目标文件不存在，`canonicalize` 失败）、
  `rust_analyzer_read_failed`（读取源文件失败）、
  `rust_analyzer_spawn_failed`（`rust-analyzer` 起不来：未安装 / 无权限 / `server_path` 错）、
  `rust_analyzer_lsp_failed`（LSP 读写或协议错误，以及 rust-analyzer 在响应里返回 `error`，如 `method not found`）、
  `rust_analyzer_workspace_resolve_failed`（工作区根自身不可解析，归 `Workspace`）、
  `timeout`（LSP 读取超时 25s）、`rust_analyzer_internal`（子进程管道装配缺失，内部缺陷）。
  **此前「路径无法解析: …」与「`rust_analyzer hover` : LSP error: …」两处都会被判成成功**，模型会把「文件不存在」或「LSP 拒绝请求」读成「该位置没有信息」，所以这轮是迁 `Typed` 而不只是改文案。
- `rust_backtrace_analyze`：已于 2026-10-27 **整工具删除**——纯计算分析器，模型可直接阅读 panic 文本，或用 `run_command`（`c++filt` 在默认白名单）与 `code_nav` 定位可疑帧，无需专用工具。
- `frontend_lint` / `frontend_build` / `frontend_test`（前端 lint / build / test）：已按 §8.5.4 **A 档**移除，改用 `run_command`（如 `npm run lint` / `npm run build` / `npm run test`）。
- `workflow_execute`（DAG 工作流执行：并行/串行、审批、SLA、失败补偿）：
  - **按工作区文件执行**：参数顶层 **`workflow_file`**（相对工作区路径，如 **`examples/workflows/ci.yaml`**；支持 `.yaml`/`.yml` 与含 `` ```crabmate-workflow `` 的 Markdown）。服务端编译作者层 `steps`（含 `when` / `for_each` / `repeat`）后执行；可选 **`workflow`** 对象覆盖 `fail_fast` 等（不覆盖 `nodes`/`steps`）。CLI 等价命令：**`crabmate workflow run <path>`**（不要求 `API_KEY`）。示例文件见仓库 **`examples/workflows/ci.yaml`**。
  - **作者层 YAML 契约**：工作区/Markdown 围栏文件须根级 **`version: 2`**（整数）。**steps 模式**（`steps[]` 编译为 `nodes`）与 **nodes 模式**（直接 `workflow.nodes` 或 `workflow.workflow_template`）互斥；加载时做 JSON Schema 校验（`fixtures/workflows/schema/workflow_author_v2_*.schema.json`）。内联 `workflow_execute` 仅含 `workflow.nodes` 且无 `version` 时仍兼容（不经作者层 schema）；含 `steps` 或显式 `version` 时须满足 v2。**编写教程与示例**：**`docs/工作流编写教程.md`**、仓库 **`examples/workflows/`**（可复制到工作区 `.crabmate/workflows/`）。
  - **内置模板（减少手写 `nodes`）**：在 **`workflow`** 对象中设 **`workflow_template`**（**`rust_ci_light`** | **`code_review`** | **`refactor_precheck`**）可展开为预设 DAG，与手写 **`nodes`** 二选一。**`rust_ci_light`**：`run_command`（`cargo fmt --check`）→ `cargo_check` → `cargo_clippy` → `cargo_test`。**`code_review`**：`git`（`action=diff` + `name_only` 取变更文件）→ `git`（`action=diff` 正文）→ `search_in_files`（默认 Rust 风险模式）→ `cargo_clippy`（`fail_fast: false`）。**`refactor_precheck`**：须另设非空 **`refactor_symbol`**（或 **`symbol`**）：`code_nav`（`action=call_graph_sketch`）→ `code_nav`（`action=find_references`）。可选 **`review_search_pattern`** 覆盖 `code_review` 的检索正则。其余 **`workflow`** 键（如 **`fail_fast`**）在展开后合并；若含 **`nodes`** 数组则整体替换模板节点。
  - **架构扩展（设计稿）**：状态机式配置、条件分支、有界循环等与当前 DAG 的关系及推荐演进阶段见 **`docs/工作流编排架构.md`**（**不**改变本节已约定的 JSON 语义，仅供维护者对齐路线图）。**Markdown 作者层**（`` ```crabmate-workflow `` 确定性编译 vs 大模型解析、混合策略）见 **`docs/工作流Markdown作者层设计.md`**。
  - **节点 `max_retries`**（0～5，默认 0）：对 **`timeout`**、**`workflow_tool_join_error`**、**`workflow_semaphore_closed`** 等**可重试**失败自动退避重跑（1s/2s/4s… 上限 8s）；**业务失败**（如测试失败、命令非零退出）**不重试**，避免重复写盘或重复副作用。
  - **静态校验**：每个节点的 **`tool_name`** 须为当前进程内置工具名；**`tool_args`** 须至少包含该工具 JSON Schema 中声明的 **`required`** 键（嵌套对象/数组内对象会递归检查；类型与 `additionalProperties` 等仍以运行时 `runner` 为准）。
  - **节点工具角色（可选）**：节点对象可设 **`node_tool_role`**（**`review_readonly` / `patch_write` / `test_runner`**），与 **`executor_kind`** 共用 **`cm_agent::step_executor_policy`** 的枚举定义（亦可写 **`executor_kind`** 作为别名）；解析后回显于结果 **`nodes[].executor_kind`**（便于与 **`agent_reply_plan`** 对齐），当前**不**在 DAG 执行层按角色强制节点级 **`tool_name`** 允许表。
  - **结果 JSON**（`workflow_execute_result` / `workflow_validate_result`）含 **`workflow_run_id`**（与日志 `workflow_run_id=` 对齐）、**`trace`**（`dag_start` / **`node_run_start`/`node_run_end`**（整节点墙钟）/ `node_attempt_*` / `node_retry_backoff` / **`compensation_phase_*`**（启用补偿时）/ `dag_end` 等；带 **`node_id`**、**`tool_name`**、**`phase`**）、**`completion_order`**（成功节点完成顺序，供补偿逆序对照）；**`nodes[].attempt`** 为最终计入结果的尝试次数；若节点声明了 **`node_tool_role`**（或 **`executor_kind`**），**`nodes[].executor_kind`** 为对应蛇形字符串（便于与 **`agent_reply_plan`** 对齐）。可选：设置 **`CM_WORKFLOW_CHROME_TRACE_DIR`** 后，每次 DAG 执行结束写入 Chrome trace JSON，且 **`workflow_execute_result`** 含 **`chrome_trace_path`**；若同时设置 **`CM_REQUEST_CHROME_TRACE_DIR`**，工作流事件并入回合 **`turn-*.json`**，**`chrome_trace_path` 为 null**，详见 **`docs/配置说明.md`**。
  ```json
  {"workflow":{
    "max_parallelism":2,
    "fail_fast":true,
    "compensate_on_failure":true,
    "nodes":[
      {"id":"clean","tool_name":"run_command","tool_args":{"command":"cargo","args":["clean","--dry-run"]},"deps":[],"compensate_with":[]},
      {"id":"clippy","tool_name":"cargo_clippy","tool_args":{"all_targets":true},"deps":["clean"],"compensate_with":["clean"]},

    ]
  }}
  ```

## 常见失败处理指引

下面是用 `run_command` 运行 `cargo audit` / `cargo deny check` 时最常见的失败场景与处理建议。

- `cargo deny check` 失败（许可证/策略不满足）
  - 先单独执行并看完整输出：
    ```bash
    cargo deny check advisories licenses bans sources
    ```
  - 常见原因：
    - 新依赖命中了 `bans`（被禁止包或重复版本过多）
    - 许可证不在允许列表（`licenses`）
    - 来源不符合策略（`sources`）
  - 建议处理：
    - 优先升级或替换触发规则的依赖
    - 在项目 `deny.toml` 中按团队策略补充白名单/例外（需代码评审）
    - 对临时例外设置说明与到期计划，避免长期“豁免”

- `cargo audit` 失败（存在已知漏洞）
  - 先单独执行并看完整输出：
    ```bash
    cargo audit
    ```
  - 常见原因：
    - 依赖树中存在 RustSec 漏洞公告
    - 锁文件过旧，仍引用已修复前版本
  - 建议处理：
    - 优先执行 `cargo update`（或定向 `cargo update -p <crate>`）后复测
    - 若上游尚未修复，评估降级功能、替代库或临时隔离风险
    - 确认修复后重新运行 `cargo audit` 与测试

- 工作区不干净（`require_clean_worktree=true`）
  - 现象：工作区不干净检查（等价 `git status --porcelain` 输出非空）不通过。
  - 先确认改动：
    ```bash
    git status
    git diff
    ```
  - 建议处理：
    - 需要保留改动：先提交（或拆分提交）再执行发布检查
    - 暂不发布这些改动：可 stash 后再跑检查
    - 仅想本地快速自检：将 `require_clean_worktree` 设为 `false`

- 工具未安装导致失败
  - `cargo-deny` 未安装：
    ```bash
    cargo install cargo-deny
    ```
  - `cargo-audit` 未安装：
    ```bash
    cargo install cargo-audit
    ```

### 发布前建议顺序

建议按“先快后严”的顺序执行，能更高效定位问题：

1. 本地快速自检（快速版）  
   目标：先确认主流程基本可用，快速发现明显问题。
2. 修复后运行严格检查（严格版）  
   目标：补齐安全与策略校验，确保发版质量门禁。
3. 确认工作区干净并复跑关键测试  
   目标：避免把临时改动带入发布物。
4. 打 tag / 进入发布流程  
   目标：在可追溯状态下产出正式版本。

  ```json
  {"path":"src/main.rs","start_line":1,"max_lines":200}
  ```
  **检索命中后精读**：可用 **`anchor_line`**（1-based 命中行）+ **`context_lines`**（每侧上下文行数，默认 120），在锚点附近对称取窗口，仍受 **`max_lines`** 封顶；**勿与 `start_line`/`end_line` 同传**。示例：`{"path":"src/lib.rs","anchor_line":842,"context_lines":40,"max_lines":500}`。
  **`path` 须指向常规文件（含扩展名）；若误填目录则失败（稳定码 `read_file_not_file`），正文提示改用 `read_dir`。若路径在工作区内不存在或中间目录缺失（常见于误猜 `foo.rs` / `src/lib.rs`），失败信息末尾会追加布局提示（建议 `read_dir` / `glob_files` 等）。**  
  非 UTF-8 或需去 BOM 时可设 **`encoding`**，例如 `{"path":"legacy.txt","encoding":"gb18030"}`、`{"path":"utf8bom.txt","encoding":"utf-8-sig"}`、`{"path":"unknown.bin","encoding":"auto"}`。默认 **`utf-8` 严格**：非法 UTF-8 字节会返回明确错误，而**不会**用替换字符静默乱码。响应中会提示「下一段可将 start_line 设为 N」。需要精确总行数时可设 `"count_total_lines": true`（大文件会多扫一遍）；**文件大于 32 MiB 时**为免整文件多次扫描拖垮回合，将返回稳定错误码 **`read_file_count_total_too_large`**（请省略该开关或分段读取）。也可用 `start_line` + `end_line` 精确区间（仍受 `max_lines` 上限截断）；若两者同时给出且 **end_line 小于 start_line**（起止写反），会**自动交换**后再读，聊天摘要中的 `[a-b]` 也会按升序显示。**成功**时正文**第一行**为单行 JSON **`{"kind":"crabmate_tool_output","tool":"read_file","version":1,…}`**（`path`、**`revision`**、`start_line`、`line_count_returned`、`has_more` 等），其后为历史人类可读块。其中 **`revision`** 是文件**内容**的 SHA-256 快照票据（`sha256:<hex>`），可原样传给 `modify_file` 的 **`base_revision`** 做写前校验；`role: tool` 信封的 **`error_code`** 在失败时另有稳定子码（如 `read_file_workspace_*`、`read_file_invalid_range`、`read_file_count_total_too_large`）。**Web SSE**：`tool_result` 控制面在同帧 **`output`**（完整正文）之外，可选带 **`structured_preview`**（与首行 JSON **同源**的副本，便于前端/集成方解析元数据而不扫长文本）。
- `modify_file`（**局部内容改动首选 `search_replace`**（文本锚定、无需行号）；按行区间替换用 `mode=replace_lines`：行号区间 + `content`，流式改写不落整文件到内存；起止行写反会自动交换；**`dry_run` 默认 `true`**（只返回 diff、不写盘），显式 `dry_run=false` 才写入）：
  ```json
  {"path":"src/huge.rs","mode":"replace_lines","start_line":120,"end_line":135,"content":"// 新片段\n","dry_run":false}
  ```
  示例里的 `"dry_run":false` 表示真正写盘；**省略 `dry_run` 只返回 unified diff 预览**（下同）。
  未显式给 `mode` 但传了 `start_line` / `end_line` 时会自动按 `replace_lines` 执行；传了 `after_line` 时会自动按 `insert_after_line`。插入示例：
  ```json
  {"path":"src/huge.rs","mode":"insert_after_line","after_line":120,"content":"// 插入片段\n","dry_run":false}
  ```
  **`after_line=0`** 表示插入文件开头。**`mode=full`（默认）或 `mode=overwrite`：整文件覆盖**（二者等价，`overwrite` 仅强调「整盘替换」语义）：`content` 即为磁盘上的**全部**新正文；若不完整将**永久截断**原文件。若命中高危启发式（显著缩短、大量删行、清空非空文件等），须 **`confirm_full_overwrite=true`** 才执行写入；拒绝写盘时也会返回 unified diff 预览。局部改动请优先 `search_replace`（文本锚定、无需行号），或按行用 `replace_lines`、`insert_after_line`。
  **防行号偏移守卫（跨轮/并行编辑必读）**：多次编辑同一文件时，前一次编辑会使后续行号整体偏移，按过期行号盲写可能误删/重复代码。两种防护：
  - **内容守卫（`guard` 子对象）**：写盘前用「调用方声称的当前内容」核对行坐标；不一致即**拒写**（未写盘，文件保持原样），并提示该内容实际所在行号（纠偏提示）。子键分工：`replace_lines` 用 `guard.content`（校验 `[start_line..=end_line]` 当前内容与此**逐行精确一致**，最严格）或 `guard.first_line` + `guard.last_line`（只校验区间**首行**与**末行**，删除长区间时不必整段复述；二者**互斥**）；`insert_after_line` 用 `guard.anchor_line`（校验锚点行当前内容一致）。守卫与 `mode=full` / `mode=overwrite` 互斥（混用直接报错）：
    ```json
    {"path":"src/huge.rs","mode":"replace_lines","start_line":120,"end_line":135,"content":"// 新片段\n","guard":{"content":"// 原片段第一行\n// 原片段第二行\n…"}}
    {"path":"src/huge.rs","mode":"replace_lines","start_line":120,"end_line":135,"content":"","guard":{"first_line":"// 片段起始行","last_line":"// 片段结束行"}}
    {"path":"src/huge.rs","mode":"insert_after_line","after_line":120,"content":"// 插入片段\n","guard":{"anchor_line":"// 锚点行"}}
    ```
    `guard.content` 与 `guard.first_line`/`guard.last_line` 之间互斥；`guard.first_line`/`guard.last_line` 仅用于 `replace_lines`（含 `edits` 内的 replace 项），`insert_after_line` 请用 `guard.anchor_line`。
    > **兼容旧写法**：平铺参数 `expect_content` / `expect_first_line` / `expect_last_line` / `expect_line_content` 依次等价于 `guard.content` / `guard.first_line` / `guard.last_line` / `guard.anchor_line`；服务端在 schema 校验前自动上抬到 `guard`，旧调用与历史会话回放仍可用（工具 schema 与 description 只暴露 `guard`）。
  - **批量 `edits`（同一文件多处改动首选）**：一次调用携带多条局部编辑，全部行号基于**调用时的磁盘快照**，服务端**自底向上**应用、互不偏移；最多 **16** 条，区间重叠即拒绝：
    ```json
    {"path":"src/huge.rs","edits":[
      {"start_line":10,"end_line":12,"content":"// 替换片段"},
      {"after_line":30,"content":"// 插入片段"},
      {"after_line":0,"content":"// 文件头插入"}
    ]}
    ```
    每条编辑同样支持 `guard` 子对象（replace 项：`guard.content` 或 `guard.first_line`+`guard.last_line`，二选一；insert 项：`guard.anchor_line`），以及 `dry_run`（默认 `true`，预览整批 diff 不写盘）。`edits` 与顶层 `mode` / `content` / `start_line` / `end_line` / `after_line` / `guard` 互斥。
  - **revision 校验（默认自动生效）**：`read_file` 成功输出头里的 **`revision`** 是文件内容快照票据（`sha256:<hex>`）。同一轮内服务端会按**规范化路径**自动绑定最近一次成功读取的 revision；`modify_file` 的**行号类模式**（`replace_lines` / `insert_after_line` / `edits`）在写盘前默认拿它比对当前内容 hash，**无需显式传参**。文件已变更即返回 **`错误[stale_revision]`** 并**拒写**（未写盘，文件保持原样），从而避免同一条消息内多个工具调用都基于旧快照、按已漂移的行号误改。**若本轮从未对目标文件调用 `read_file`、且调用方也未传 `base_revision`，则没有可比对的基线——行号类模式同样拒写，返回 `错误[missing_revision_baseline]`**（不再凭记忆的行号落盘；先 `read_file` 取得快照，或改用按文本锚定的 `search_replace`，或确认风险后传 `allow_stale_revision=true`）。**预览（未传 `dry_run` 或 `dry_run=true`）不写盘，因此跳过上述「本轮自动绑定」的基线校验；只有 `dry_run=false` 真正写盘时才要求基线。显式 `base_revision` 不受预览影响，仍然始终校验。**`mode=full/overwrite` 不依赖行号，不做自动绑定。
    ```json
    {"path":"src/huge.rs","mode":"replace_lines","start_line":120,"end_line":135,"content":"// 新片段\n","dry_run":false}
    ```
    - 也可显式传 **`base_revision`**（适用于所有 `mode` 与 `edits`）：显式值**优先**于自动绑定，且**始终校验**。
    - 确认要基于当前内容跳过轮次自动校验时，可传 **`allow_stale_revision=true`**（显式 `base_revision` 仍会校验）。
    - **原子写盘**：`full` / `overwrite` 与 `edits` 均先写同目录临时文件、`fsync` 后再 **rename 原子替换**（`replace_lines` / `insert_after_line` 本就如此）；revision 校验紧贴 rename 前一刻，并发读者不会看到被截断的半成品文件。多硬链接（`nlink > 1`）文件为保留其它硬链接会退化为写回原 inode（该路径非原子）。
- `read_dir`（列出目录内容）：
  ```json
  {"path":"src","max_entries":50,"include_hidden":false}
  ```
  **成功**时正文首行亦为 **`crabmate_tool_output` v1**（`tool":"read_dir"`：`path`、`entries_shown`、`entries_walked`），其后为人类可读列表；SSE **`tool_result.structured_preview`** 与之同源。**失败**时 `error_code` 按原因区分：路径存在但不是目录 → `read_dir_path_not_dir`（`invalid_input`）；起始目录不存在 / 读取失败 → `read_dir_io_failed`（`external`，正文 `错误：无法解析目录路径：…`）；路径落到工作区根之外 → `read_dir_workspace_resolve_failed`（`workspace`）；触碰 `/proc` 等敏感路径 → `read_dir_sensitive_path`（`policy_denied`）；参数校验 → `invalid_args`。
- `list_tree`（递归列树，相对工作区）：
  ```json
  {"path":"src","max_depth":4,"max_entries":500,"include_hidden":false}
  ```
  **成功**时首行 **`crabmate_tool_output` v1**（`tool":"list_tree"`：`path`、`max_depth`、`lines_count`、`truncated` 等），其后为 `dir:` / `file:` 行列表。
  **`glob_files` / `list_tree` 失败**时 `error_code` 按原因区分：起始目录不存在 / 读取失败 → `*_io_failed`（`external`，正文 `错误：无法解析起始目录：…`）；路径存在但不是目录 → `*_path_not_dir`（`invalid_input`）；路径落到工作区根之外 → `*_workspace_resolve_failed`、工作区根自身不可解析 → `*_workspace_root_resolve_failed`（均 `workspace`）；参数校验（缺 `pattern`、绝对路径、含 `..`）→ `invalid_args`。
- `markdown_check_links`（维护 `README.md` / `docs/`：相对链接与 `#fragment` 是否有效；外链仅在对 `allowed_external_prefixes` 命中时才发 HTTP）：
  ```json
  {"roots":["README.md","docs"],"max_files":300,"check_fragments":true,"output_format":"text","allowed_external_prefixes":["https://example.com/docs/"],"external_timeout_secs":10}
  ```
  省略 `roots` 时默认扫描 `README.md` 与 `docs` 目录。
- `structured`（按 **`action`** 分派；下列示例均为最小可用入参）：
  - `action=validate`（解析 `package.json` / `Cargo.toml` / `.yml` 等是否合法，可选顶层摘要）：
  ```json
  {"action":"validate","path":"frontend/Cargo.toml","format":"auto","summarize":true}
  ```
  - `action=query`（取嵌套字段，省上下文）：
  ```json
  {"action":"query","path":"Cargo.toml","query":"/package/name","format":"toml"}
  ```
  点号路径示例：`{"action":"query","path":"frontend/Cargo.toml","query":"dependencies.leptos"}`。
  - `action=diff`（两份 OpenAPI/配置的结构差异，非行级 diff）：
  ```json
  {"action":"diff","path_a":"specs/openapi.v1.json","path_b":"specs/openapi.v2.json","max_diff_lines":200}
  ```
  **CSV/TSV**：`format` 可用 `csv`/`tsv` 或依赖扩展名；`has_header`（默认 `true`）为 `false` 时表解析为「数组的数组」，便于无表头导出。查询示例：`{"action":"query","path":"data/sample.csv","query":"/0/name"}`。
  - `action=patch`（按 key 路径改 JSON/YAML/TOML）：
  ```json
  {"action":"patch","path":"config/app.toml","query":"/llm/model","value":"glm-5","dry_run":false}
  ```
  `mutation` 默认 `set`（`remove` 删除该路径），`create_missing` 默认 `true`。**不传 `dry_run` 一律只预览**（与 `modify_file` / `append_file` / `search_replace` 同一旋钮），预览返回 **unified diff**（`--- a/<path>` / `+++ b/<path>`，超出字符预算截断），不再只回报字节数。
  不属于本 `action` 的字段（如 `diff` 的 `path_a`）会被忽略；`format=csv|tsv` 对 `action=patch` 直接报错（不支持结构化写回）。
  **写盘**：同目录临时文件 → 继承属主/权限/扩展属性 → `fsync` → **rename 原子替换**（多硬链接退化为写回原 inode），与 `modify_file` 共用提交通道，并发读者不会看到半成品文件。
  **注意：写盘是整份重新序列化**——JSON 输出 pretty（2 空格缩进），TOML/YAML 由序列化器重新生成，**注释与原始排版不会保留**，因此预览里的 diff 常表现为整文件重排。在意注释的配置文件请优先 `modify_file`（按行/文本锚定）或 `search_replace`；`action=patch` 适合 `.json`（无注释）或「值优先」的配置。
  **CAS（可选）**：传 `base_revision`（`read_file` 输出头里的 `revision`）即做写前校验，内容已变则返回 **`错误[stale_revision]`** 并拒写（未写盘）。不传则不做 CAS——键路径编辑不受行号漂移影响，故不像行号类编辑那样强制要求基线。
- `apply_patch`（在工作区应用 **unified diff**，纯 Rust `diffy` 实现，不依赖系统 `patch` CLI）：例如 `{"patch":"--- a/src/x.rs\n+++ b/src/x.rs\n@@ -1,3 +1,3 @@\n ...","strip":1}`。`strip` 与 `git apply -p` 同义（`--- a/x` 用 1、`--- x` 用 0），并支持 `/dev/null` hunk（新建 / 删除文件）。
  **多文件补丁整体试算、全部能应用才写**——任一文件对不上就一个字节都不落盘（旧实现边算边写，会「部分应用」，现已消除）；`dry_run: true` 只返回 diff 预览（默认 `false`，因为本工具的语义就是「应用」）。
  写盘走与 `modify_file` 相同的**原子替换**通道（tmp → 继承元数据 → fsync → rename），并对**单文件**补丁支持 `base_revision` 写前校验；多文件补丁传 `base_revision` 会直接报错（一个 revision 表达不了多个文件的基线）。成功/失败正文都带 `crabmate_tool_output` 头，错误码 **`apply_patch_failed`**；路径仍受工作区根约束（禁止绝对路径、`..` 穿越与 symlink 逃逸）。
- `table_text`（表格行操作，与 `structured`（`action=query`）的整表 JSON 路径不同）：例如预览 `{"action":"preview","path":"data/foo.tsv","preview_rows":15}`；按列筛选 `{"action":"filter_rows","path":"data/foo.csv","column":2,"contains":"ERR","max_output_rows":100}`。
- `diagnostic_summary`（脱敏排障：工具链、`target/`、关键 env 是否设置，**不输出任何 env 取值**）：

  ```json
  {"include_toolchain":true,"include_workspace_paths":true,"include_env":true,"extra_env_vars":["CI"]}
  ```

- `apply_patch`（**统一 unified diff**，先 dry-run 再应用；强调 **小步、可回滚、带上下文**）：
  - **格式**：与 `git diff` 相同：`---` / `+++` 文件头、`@@ -旧起始,行数 +新起始,行数 @@`，变更行 `-`/`+`，**上下文行必须以单个空格开头**。
  - **带上下文**：每个 hunk 在修改行上下保留 **至少 2～3 行** 未改动内容，减少错位；避免零上下文单行 hunk。
  - **小步**：一次补丁尽量只做一个逻辑改动（单函数/单配置块），大改动拆多次调用，便于 dry-run 失败定位。
  - **可回滚**：`patch -R`、或 `git checkout -- <file>`、或反向 diff；小步更易安全撤销。
  - **路径与 strip（二选一）**：
    - **推荐**：`--- src/example.rs` / `+++ src/example.rs`（相对工作区根，**无** `a/`），**`strip` 用默认 `0`**。
    - **Git 导出**：`--- a/src/example.rs` / `+++ b/src/example.rs` 时须设 **`"strip": 1`**，否则 patch 会找错路径。
  - 路径须在工作区内，禁止 `..`。
  ```text
  --- src/example.rs
  +++ src/example.rs
  @@ -4,6 +4,7 @@ fn demo() {
       let a = 1;
       let b = 2;
  -    let c = a + b;
  +    let c = a + b + 1;
       println!("{}", c);
       // trailing context
  ```
  ```json
  {"patch":"--- src/example.rs\n+++ src/example.rs\n@@ -4,6 +4,7 @@ fn demo() {\n ...\n"}
  ```

  ```json
  {"action":"find_symbol","symbol":"run_agent_turn","kind":"fn","path":"src","context_lines":2,"max_results":10}
  ```
  ```json
  {"action":"find_references","symbol":"run_tool","path":"src/cm_tools/tools","max_results":50,"case_sensitive":false,"exclude_definitions":true}
  ```
  ```json
  {"action":"call_graph_sketch","symbols":["run_tool_dispatch","RunAgentTurnParams"],"path":"src","max_edges":600}
  ```
  ```json
  {"action":"file_outline","path":"src/cm_tools/mod.rs","include_use":false,"max_items":200}
  ```
  **必填**：`find_symbol` / `find_references` / `call_graph_sketch` 需 `symbol`（`call_graph_sketch` 也可用 `symbols`），`file_outline` 需 `path`；与 `action` 无关的字段被忽略（未知键仍报错），但 schema 的取值区间（如 `max_results` 的 1–300）对每次调用都校验。`call_graph_sketch` 是**启发式**影响面草图（`use` + 非定义行词边界命中，按目录聚合；**非**真调用图）。需要 LSP 级精度请用 `rust_analyzer`。
